## Release Overview

K0 V1.0.0 is the first production-ready release of the K0 microkernel, providing:

- **ACID envelope processing** with SQLite WAL mode (zero data loss)
- **Ed25519 signatures** for envelope authentication (PyNaCl library, 64-byte signatures)
- **Async worker architecture** for embeddings (4 backends) and FTS indexing
- **Policy enforcement** with PEM (GREEN/AMBER/RED bands)
- **Full observability** (Prometheus, OpenTelemetry, Grafana)
- **Production performance**: P95 3.32ms (97% better than 100ms target), 10k+ events/s replay
- **Complete documentation**: Integration spec, quickstart, deployment guide

**Known Issues:**

- K0 kernel metrics bug: `policy_stamp_attached_total` counter defined without labels (line 403 command.py)
  - Does not affect envelope processing
  - Envelope commits succeed before this error
  - Workaround: Ignore ValueError in logs related to this metric

## CHANGELOG.md (Release Notes)

```markdown
# Changelog

All notable changes to K0 will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [1.0.0] - 2025-01-10

### Added

**Core Features:**
- SQLite WAL-based storage with ACID guarantees
- MinimalGate validation with envelope signature verification (Ed25519)
- Four production ports: Command (/k0/command.submit), Query (/k0/query.recall), SSE (/k0/sse.subscribe), Observability (/k0/obs.emit)
- Idempotency with HMAC-SHA256 idem_key derivation (60-second bucket)
- Policy Enforcement Module (PEM) with GREEN/AMBER/RED bands
- Outbox pattern for async worker coordination
- **Signature Algorithm:** Ed25519 (64-byte signatures, base64url encoding - PyNaCl library)

**Async Workers:**
- EmbeddingWorker with 4 backends:
  - sentence-transformers (all-mpnet-base-v2, 768 dims, default)
  - OpenAI (text-embedding-3-small, 1536 dims)
  - Ollama (local deployment at localhost:11434)
  - Fake (deterministic hash, testing only)
- FtsIndexingWorker with NLTK NLP pipeline:
  - Tokenization, stemming (Porter), stop word removal
  - n-gram indexing (unigram, bigram, trigram)
  - SQLite FTS5 full-text search

**Observability:**
- Prometheus metrics endpoint (/metrics)
- OpenTelemetry OTLP tracing
- Grafana dashboards (kernel overview, command latency, query latency, SSE health, replay throughput)
- Structured logging with PII redaction
- Performance SLOs: submit→receipt P95≤150ms, query P95≤250ms, SSE P95≤250ms

**CLI (k0ctl):**
- `k0ctl serve` - Start K0 kernel server
- `k0ctl migrate` - Run database migrations
- `k0ctl provision` - Provision tenant/space/device
- `k0ctl schema` - Manage schema registry (register, promote, block)
- `k0ctl replay` - Replay WAL events
- `k0ctl dlq` - Manage dead-letter queue (requeue, purge)
- `k0ctl config` - Reload configuration (SIGHUP)

**Documentation:**
- K0 V1 Integration Specification (700+ lines): Envelope format, API reference, test vectors
- Developer Quickstart Guide (800+ lines): Installation, first envelope, worker monitoring
- Production Deployment Guide (1800+ lines): Docker/K8s, security, monitoring, operations

**Deployment:**
- Docker Compose configuration with telemetry stack
- Kubernetes manifests (Deployment, Service, Ingress, ConfigMap, Secret, PVC)
- NGINX reverse proxy with TLS termination
- Hot reload support for config changes

**Security:**
- Ed25519 envelope signatures (PyNaCl library, 64-byte signatures)
- TLS/mTLS support
- Geohash privacy masking
- Capability-based access control (PEM)
- Secret management via Kubernetes Secrets / HashiCorp Vault

## Migration Guide

Since this is the first release, no migration is needed.

For future upgrades:
1. Back up database: `sqlite3 k0_kernel.db ".backup backup.db"`
2. Stop services: `docker compose down`
3. Extract new release: `tar -xzf k0-v1.1.0.tar.gz`
4. Run migrations: `docker compose run --rm k0-kernel k0ctl migrate`
5. Restart services: `docker compose up -d`
6. Verify health: `curl http://localhost:8080/healthz`
```
