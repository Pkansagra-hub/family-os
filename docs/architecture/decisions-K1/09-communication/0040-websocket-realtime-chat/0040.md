# ADR-0040: WebSocket for Real-Time Chat

**Status:** ✅ Approved
**Date:** 2025-10-11
**Authors:** K1 Architecture Team
**Category:** Communication & Integration
**Related ADRs:** ADR-0011 (FlatBuffers Serialization), ADR-0015 (WebSocket Binary Protocol), ADR-0037 (JWT Authentication), ADR-0046 (SSE → WebSocket Bridge)

---

## Hybrid Architecture Context

**WebSocket provides full-duplex real-time communication for chat interfaces via RFC 6455 protocol, enabling <200ms TTFT streaming responses, bidirectional message flow (client ↔ server), FlatBuffers binary serialization (2× smaller than JSON), JWT authentication (ADR-0037), and auto-reconnect with message buffering for mobile reliability.**

### Critical Insight: Why WebSocket Beats HTTP Polling and SSE

Without WebSocket, real-time chat relies on **HTTP polling** (client asks "new messages?" every 500ms, creating 120 requests/min with 1-5s latency and 99% wasted requests) or **SSE** (server-sent events for server → client only, requiring separate HTTP POST connection for client → server, can't send mid-stream actions like pause/interrupt). WebSocket achieves **<200ms TTFT** (time to first token via streaming), **bidirectional communication** (client ↔ server on single connection), **2× bandwidth efficiency** (FlatBuffers binary vs JSON text), **JWT authentication** (stateless token in handshake), and **auto-reconnect** (exponential backoff + message buffer for mobile reliability).

### WebSocket Components

| Component | HTTP Polling | SSE (Server-Sent Events) | WebSocket (RFC 6455) | Benefit |
|-----------|--------------|-------------------------|---------------------|---------|
| **Connection Type** | Request/response (new TCP each poll) | Unidirectional (server → client) | Full-duplex bidirectional | Single connection, both directions |
| **Latency (TTFT)** | 1-5s (polling interval) | 200-500ms (HTTP overhead) | <200ms (streaming) | 5-25× faster first token |
| **Bandwidth Efficiency** | 99% wasted requests ("no new messages") | JSON text (2× larger than binary) | FlatBuffers binary (50% smaller) | 2× bandwidth reduction |
| **Mobile Battery** | High (constant HTTP requests) | Medium (long-lived HTTP connection) | Low (efficient binary protocol) | 50% better battery life |
| **Streaming** | No (wait for complete response) | Yes (server → client only) | Yes (bidirectional) | Real-time token-by-token |
| **Mid-Stream Actions** | No (new HTTP POST required) | No (can't send from client) | Yes (send pause/interrupt anytime) | Interactive chat (barge-in, clarification) |
| **Authentication** | Per-request (JWT in header) | Initial HTTP handshake | JWT in handshake (persistent) | 1× auth check vs 120×/min |

### Decision Matrix: 6 Alternatives for Real-Time Chat

| Alternative | Latency (TTFT) | Bidirectional | Binary Support | Mobile Battery | Ecosystem | Score | Decision |
|-------------|----------------|---------------|----------------|----------------|-----------|-------|----------|
| **HTTP Polling (500ms)** | 1-5s | No (separate POST) | JSON only | Poor (120 req/min) | Universal | **3/10** | ❌ REJECTED |
| **HTTP Long Polling** | 500ms-2s | No (separate POST) | JSON only | Medium (holds connection) | Universal | **5/10** | ❌ REJECTED |
| **SSE (Server-Sent Events)** | 200-500ms | No (server → client only) | JSON only | Medium | Good | **7/10** | ❌ REJECTED |
| **WebSocket (RFC 6455)** | <200ms | Yes (full-duplex) | FlatBuffers binary | Good | Excellent | **10/10** | ✅ SELECTED |
| **gRPC Bidirectional Stream** | <100ms | Yes (full-duplex) | Protobuf binary | Good | Limited (no browser) | **8/10** | ❌ REJECTED |
| **WebRTC Data Channel** | <50ms | Yes (P2P possible) | Binary | Good | Complex (NAT traversal) | **6/10** | ❌ REJECTED |

### Key Decision Factors

1. **<200ms TTFT via Streaming:** WebSocket enables token-by-token streaming (AgentMessageChunk), user sees response appear as typed (5-25× faster than polling)
2. **Full-Duplex Bidirectional:** Client ↔ server on single connection, enables mid-stream actions (pause, interrupt, clarification request) without separate HTTP POST
3. **2× Bandwidth Efficiency:** FlatBuffers binary serialization (ADR-0011) 50% smaller than JSON, reduces mobile data costs and improves slow network performance
4. **JWT Authentication (ADR-0037):** Stateless token in handshake (query param or Sec-WebSocket-Protocol header), 1× auth check vs 120× per minute with HTTP polling
5. **Auto-Reconnect + Message Buffer:** Exponential backoff (1s, 2s, 4s, 8s, 16s max), server buffers last 100 messages (5-minute window), client requests missed events on reconnect

### Why Alternatives Were Rejected

- **HTTP Polling 500ms (3/10):** 1-5s latency kills UX (user waits), 99% wasted requests ("no new messages" = 120 empty responses/min), poor mobile battery (constant TCP connections), no streaming (wait for complete response)
- **HTTP Long Polling (5/10):** Still requires separate POST for client → server messages, holds connection open (server resource waste), 500ms-2s latency (slower than WebSocket), no binary support (JSON text only)
- **SSE Server-Sent Events (7/10):** Unidirectional (server → client only), client must use separate HTTP POST for messages (2 connections = 2× complexity), can't send mid-stream actions (pause/interrupt), JSON text only (no binary efficiency)
- **gRPC Bidirectional Stream (8/10):** Not supported in browsers (requires gRPC-Web proxy, adds latency), limited ecosystem (no browser native API), Protobuf requires codegen (FlatBuffers zero-copy faster)
- **WebRTC Data Channel (6/10):** P2P complexity (STUN/TURN/ICE for NAT traversal), designed for video/audio (overkill for chat), poor mobile support (battery drain), no standard authentication mechanism

### Research Foundation: Real-Time Communication Protocols

- **RFC 6455 (WebSocket Protocol 2011):** Full-duplex communication over single TCP connection, low-latency low-overhead, used by Slack, Discord, Figma, Google Docs, WhatsApp Web
- **W3C WebSocket API (2012):** Browser native API (`new WebSocket("wss://...")`), events (onopen, onmessage, onclose, onerror), 99.9% browser coverage
- **FlatBuffers (Google 2014):** Zero-copy binary serialization (ADR-0011), 50% smaller than JSON, <1ms serialization (used by Android, Unity, Facebook)
- **RFC 7692 (WebSocket Compression Extension 2015):** Permessage-deflate compression (reduces bandwidth by 60-80% for text)
- **JWT Authentication (RFC 7519 2015):** Stateless token in WebSocket handshake (query param or Sec-WebSocket-Protocol header), used by Socket.io, Pusher, Ably
- **Exponential Backoff (Google SRE Book 2016):** Auto-reconnect strategy (1s, 2s, 4s, 8s, 16s max) prevents thundering herd on network outage

## Context

### Problem Statement

**K1 requires a real-time bidirectional communication protocol for chat interfaces that supports low-latency streaming, message acknowledgments, reconnection handling, and binary efficiency for high-throughput agent responses.**

**Current Challenge:** Without WebSocket protocol:

**Problem 1: HTTP Polling is Inefficient**
- Traditional HTTP polling: Client asks "new messages?" every N seconds
- High latency (1-5 seconds between polls)
- Wasted requests (99% return "no new messages")
- **Risk:** Poor UX, high server load, increased costs

**Problem 2: SSE is Unidirectional**
- Server-Sent Events (SSE) only server → client
- Client must use HTTP POST for messages (two connections)
- Can't send actions mid-stream (pause, interrupt, clarification)
- **Risk:** Complex client logic, poor mobile battery life

**Problem 3: No Streaming Standard**
- OpenAI, Anthropic, Google each have different streaming formats
- Custom protocols hard to maintain
- No ecosystem support (libraries, debuggers)
- **Risk:** Vendor lock-in, poor developer experience

**Problem 4: Text-Based Protocols are Inefficient**
- JSON text: ~2x larger than binary
- UTF-8 encoding overhead
- No native support for embeddings, audio, images
- **Risk:** High bandwidth costs, slow on mobile networks

**Real-World Scenario (Without WebSocket):**
```
User types: "What's the weather?"

Without WebSocket (HTTP Polling):
1. Client: POST /turns → {"text": "What's the weather?"}
2. Server: 202 Accepted, turn_id="turn-123", status="processing"
3. Client: GET /turns/turn-123 (poll every 500ms)
4. Server: 200 OK, status="processing" (×6 times, 3 seconds wasted)
5. Client: GET /turns/turn-123
6. Server: 200 OK, status="completed", response="It's sunny..."

- **6 HTTP requests** for one turn
- **3 seconds latency** (polling overhead)
- **No streaming** (user waits for full response)
- **Poor UX** ❌
```

**Desired Behavior (With WebSocket):**
```
User types: "What's the weather?"

With WebSocket:
1. Client → Server: UserMessage {"text": "What's the weather?"}
2. Server → Client: AgentMessageStart {"agent_name": "Concierge"}
3. Server → Client: AgentMessageChunk {"text_delta": "It's"}
4. Server → Client: AgentMessageChunk {"text_delta": " sunny"}
5. Server → Client: AgentMessageChunk {"text_delta": " in"}
6. Server → Client: AgentMessageChunk {"text_delta": " New York"}
7. Server → Client: AgentMessageEnd {"finish_reason": "STOP"}

- **1 connection** (bidirectional)
- **<200ms TTFT** (time to first token)
- **Streaming response** (tokens appear as typed)
- **Great UX** ✅
```

### System Constraints

1. **Performance Budget:**
   - Connection establishment: <500ms (TLS handshake + auth)
   - TTFT (Time to First Token): <200ms
   - Message serialization: <1ms (FlatBuffers)
   - Heartbeat interval: 30 seconds

2. **Protocol Requirements:**
   - Full-duplex: Client ↔ Server bidirectional
   - Binary protocol: FlatBuffers (ADR-0011)
   - 17 message types: Connection, Conversation, User, Agent, Tool, Error
   - Message acknowledgment: Optional ACKs for reliability

3. **Reliability:**
   - Auto-reconnect: Exponential backoff (1s, 2s, 4s, 8s, 16s max)
   - Message buffer: Server buffers last 100 messages (5-minute window)
   - Missed events: Client requests missed messages on reconnect

4. **Security:**
   - Authentication: JWT in handshake (query param or header)
   - Authorization: Validate session_id, user_id, space_id
   - Encryption: TLS 1.3 (wss://)

5. **Compliance:**
   - RFC 6455: WebSocket protocol
   - W3C WebSocket API: Browser compatibility
   - FlatBuffers: Binary serialization (ADR-0011)

## Decision

**We will implement WebSocket (RFC 6455) for real-time chat using FlatBuffers binary protocol with 17 message types, supporting full-duplex streaming, auto-reconnection, message buffering, and JWT authentication.**

### Core Principles

1. **Full-Duplex Communication:**
   - Client ↔ Server bidirectional (RFC 6455)
   - No polling: Server pushes messages as they arrive
   - Real-time actions: Pause, interrupt, clarification mid-stream

2. **FlatBuffers Binary Protocol:**
   - Zero-copy serialization (ADR-0011)
   - Schema evolution (backward/forward compatible)
   - ~2x smaller than JSON, ~10x faster to parse

3. **17 Message Types:**
   - **Connection:** ConnectionEstablished, Heartbeat, HeartbeatAck, RefreshToken, TokenRefreshed, Disconnect, Goodbye, MissedEvents
   - **Conversation:** StartConversation, ConversationCreated, SwitchConversation, CloseConversation, ConversationClosed, ListConversations, ConversationsListed
   - **User:** UserMessage, UserAction, UserTyping, ClarificationResponse
   - **Agent:** AgentMessageStart, AgentMessageChunk, AgentMessageEnd, AgentPresence
   - **Tool:** ToolCallStarted, ToolCallChunk, ToolCallCompleted
   - **Clarification:** ClarificationRequest
   - **Error:** Error

4. **Auto-Reconnection:**
   - Exponential backoff: 1s, 2s, 4s, 8s, 16s (max)
   - Request missed messages on reconnect
   - Server buffers last 100 messages (5-minute window)

5. **Security:**
   - JWT authentication in handshake (query param: `?token=<jwt>`)
   - Validate user_id, session_id, space_id
   - TLS 1.3 encryption (wss://)

6. **Performance:**
   - TTFT: <200ms (time to first token)
   - Message serialization: <1ms (FlatBuffers)
   - Heartbeat: 30 seconds (keep-alive)

```python
# k1/api/websocket/chat.py

from fastapi import FastAPI, WebSocket, WebSocketDisconnect, Query, HTTPException
import structlog
import time

app = FastAPI()
logger = structlog.get_logger()

class WebSocketConnectionManager:
    """
    Manage WebSocket connections for K1 chat.

    Handles connection lifecycle, message routing, heartbeat, reconnection.

    Research: RFC 6455 (WebSocket), W3C WebSocket API
    """

    def __init__(self):
        self.active_connections: Dict[str, WebSocket] = {}  # session_id → websocket
        self.message_buffers: Dict[str, deque] = {}  # session_id → last 100 messages
        self.heartbeat_tasks: Dict[str, asyncio.Task] = {}

    async def connect(self, websocket: WebSocket, session_id: str, user_id: str, token: str):
        """
        Accept WebSocket connection and authenticate.

        Args:
            websocket: FastAPI WebSocket instance
            session_id: K1 session ID
            user_id: User ID from JWT
            token: JWT access token
        """
        # Accept connection
        await websocket.accept()

        # Store connection
        self.active_connections[session_id] = websocket

        # Initialize message buffer
        if session_id not in self.message_buffers:
            self.message_buffers[session_id] = deque(maxlen=100)

        # Send ConnectionEstablished
        await self.send_message(
            session_id,
            ConnectionEstablished(
                session_id=session_id,
                user_id=user_id,
                server_version="1.0.0",
                protocol_version=1,
                capabilities=["streaming", "tool_calls", "clarification"],
                reconnection_window_seconds=300  # 5 minutes
            )
        )

        # Start heartbeat
        self.heartbeat_tasks[session_id] = asyncio.create_task(
            self._heartbeat_loop(session_id)
        )

        logger.info(
            "websocket_connected",
            session_id=session_id,
            user_id=user_id
        )

    async def disconnect(self, session_id: str, code: int = 1000, reason: str = "Normal closure"):
        """
        Close WebSocket connection gracefully.

        Args:
            session_id: K1 session ID
            code: WebSocket close code (RFC 6455 §7.4)
            reason: Close reason
        """
        # Send Goodbye
        await self.send_message(
            session_id,
            Goodbye(message=reason)
        )

        # Stop heartbeat
        if session_id in self.heartbeat_tasks:
            self.heartbeat_tasks[session_id].cancel()
            del self.heartbeat_tasks[session_id]

        # Close connection
        if session_id in self.active_connections:
            websocket = self.active_connections[session_id]
            await websocket.close(code=code, reason=reason)
            del self.active_connections[session_id]

        logger.info(
            "websocket_disconnected",
            session_id=session_id,
            code=code,
            reason=reason
        )

    async def send_message(self, session_id: str, payload):
        """
        Send message to client (FlatBuffers serialization).

        Args:
            session_id: K1 session ID
            payload: Message payload (FlatBuffers table)
        """
        if session_id not in self.active_connections:
            logger.warning("websocket_not_connected", session_id=session_id)
            return

        websocket = self.active_connections[session_id]

        # Serialize to FlatBuffers
        message = WebSocketMessage(
            version=1,
            message_id=str(uuid.uuid4()),
            conversation_id=session_id,
            timestamp_ms=int(time.time() * 1000),
            trace_id=structlog.contextvars.get_contextvars().get("trace_id"),
            payload=payload
        )

        binary_data = serialize_flatbuffers(message)

        # Send to client
        try:
            await websocket.send_bytes(binary_data)

            # Buffer message (for reconnection)
            self.message_buffers[session_id].append({
                "message_id": message.message_id,
                "payload": binary_data,
                "timestamp_ms": message.timestamp_ms
            })

        except Exception as e:
            logger.error("websocket_send_failed", session_id=session_id, error=str(e))

    async def receive_message(self, session_id: str) -> dict:
        """
        Receive message from client (FlatBuffers deserialization).

        Args:
            session_id: K1 session ID

        Returns:
            dict: Deserialized message payload
        """
        if session_id not in self.active_connections:
            raise RuntimeError(f"WebSocket not connected: {session_id}")

        websocket = self.active_connections[session_id]

        # Receive binary data
        binary_data = await websocket.receive_bytes()

        # Deserialize FlatBuffers
        message = deserialize_flatbuffers(binary_data, WebSocketMessage)

        return {
            "message_id": message.message_id,
            "conversation_id": message.conversation_id,
            "timestamp_ms": message.timestamp_ms,
            "trace_id": message.trace_id,
            "payload": message.payload
        }

    async def _heartbeat_loop(self, session_id: str):
        """
        Send heartbeat every 30 seconds to keep connection alive.

        Args:
            session_id: K1 session ID
        """
        while True:
            try:
                await asyncio.sleep(30)

                # Send Heartbeat
                await self.send_message(
                    session_id,
                    Heartbeat(timestamp_ms=int(time.time() * 1000))
                )

                logger.debug("heartbeat_sent", session_id=session_id)

            except asyncio.CancelledError:
                break
            except Exception as e:
                logger.error("heartbeat_failed", session_id=session_id, error=str(e))
                break

connection_manager = WebSocketConnectionManager()

@app.websocket("/v1/chat")
async def websocket_chat(
    websocket: WebSocket,
    token: str = Query(...),  # JWT in query param
    session_id: str = Query(None)  # Optional: resume existing session
):
    """
    WebSocket endpoint for real-time chat.

    URL: wss://k1.example.com/v1/chat?token=<jwt>&session_id=<session_id>

    Args:
        websocket: FastAPI WebSocket instance
        token: JWT access token (query param)
        session_id: K1 session ID (optional, for reconnection)
    """
    # Validate JWT
    try:
        jwt_payload = jwt_validator.validate_token_string(token)
        user_id = jwt_payload["sub"]
        space_id = jwt_payload["space_id"]
    except Exception as e:
        await websocket.close(code=1008, reason=f"Invalid token: {e}")
        return

    # Generate session_id if not provided (new conversation)
    if not session_id:
        session_id = f"session-{uuid.uuid4()}"

    # Connect
    try:
        await connection_manager.connect(websocket, session_id, user_id, token)

        # Main message loop
        while True:
            # Receive message from client
            message = await connection_manager.receive_message(session_id)

            # Route message to handler
            await handle_client_message(session_id, user_id, space_id, message)

    except WebSocketDisconnect:
        logger.info("websocket_client_disconnected", session_id=session_id)
        await connection_manager.disconnect(session_id, code=1000, reason="Client disconnected")

    except Exception as e:
        logger.error("websocket_error", session_id=session_id, error=str(e))
        await connection_manager.disconnect(session_id, code=1011, reason=f"Server error: {e}")

async def handle_client_message(session_id: str, user_id: str, space_id: str, message: dict):
    """
    Handle message from client.

    Args:
        session_id: K1 session ID
        user_id: User ID
        space_id: Space ID
        message: Deserialized message
    """
    payload = message["payload"]
    payload_type = payload.__class__.__name__

    logger.info(
        "websocket_message_received",
        session_id=session_id,
        user_id=user_id,
        payload_type=payload_type,
        trace_id=message["trace_id"]
    )

    # Route by message type
    if payload_type == "StartConversation":
        await handle_start_conversation(session_id, user_id, space_id, payload)

    elif payload_type == "UserMessage":
        await handle_user_message(session_id, user_id, space_id, payload, message["trace_id"])

    elif payload_type == "UserAction":
        await handle_user_action(session_id, user_id, payload)

    elif payload_type == "ClarificationResponse":
        await handle_clarification_response(session_id, user_id, payload)

    elif payload_type == "HeartbeatAck":
        # Client acknowledges heartbeat (no action needed)
        pass

    elif payload_type == "Disconnect":
        await connection_manager.disconnect(session_id, code=1000, reason=payload.reason)

    else:
        logger.warning("unknown_message_type", payload_type=payload_type)
```

```python
# k1/api/websocket/handlers.py

async def handle_start_conversation(session_id: str, user_id: str, space_id: str, payload):
    """
    Handle StartConversation message (create new conversation).

    Args:
        session_id: K1 session ID
        user_id: User ID
        space_id: Space ID
        payload: StartConversation payload
    """
    # Create session in K1
    orchestrator = get_orchestrator()
    agents = await orchestrator.create_session(
        session_id=session_id,
        user_id=user_id,
        space_id=space_id,
        persona=payload.persona,
        privacy_band=payload.privacy_band,
        capabilities=payload.capabilities
    )

    # Send ConversationCreated
    await connection_manager.send_message(
        session_id,
        ConversationCreated(
            conversation_id=payload.conversation_id,
            session_id=session_id,
            created_at_ms=int(time.time() * 1000),
            persona=payload.persona,
            privacy_band=payload.privacy_band,
            agents=[
                AgentInfo(
                    agent_id=agent.agent_id,
                    agent_name=agent.agent_name,
                    capabilities=agent.capabilities,
                    status=agent.status
                )
                for agent in agents
            ]
        )
    )

    logger.info(
        "conversation_started",
        session_id=session_id,
        conversation_id=payload.conversation_id,
        persona=payload.persona
    )

async def handle_user_message(session_id: str, user_id: str, space_id: str, payload, trace_id: str):
    """
    Handle UserMessage (process user's text message).

    Args:
        session_id: K1 session ID
        user_id: User ID
        space_id: Space ID
        payload: UserMessage payload
        trace_id: Cognitive trace ID
    """
    # Execute turn in K1
    orchestrator = get_orchestrator()

    # Send AgentMessageStart
    await connection_manager.send_message(
        session_id,
        AgentMessageStart(
            turn_id=trace_id,
            agent_id="agent-001",
            agent_name="Concierge",
            estimated_tokens=100,
            estimated_duration_ms=2000
        )
    )

    # Stream response chunks
    async for chunk in orchestrator.execute_turn_streaming(
        session_id=session_id,
        user_message=payload.text,
        trace_id=trace_id
    ):
        # Send AgentMessageChunk
        await connection_manager.send_message(
            session_id,
            AgentMessageChunk(
                turn_id=trace_id,
                chunk_index=chunk.index,
                chunk_type=ChunkType.TEXT,
                text_delta=chunk.text,
                thinking_delta=chunk.thinking
            )
        )

    # Send AgentMessageEnd
    await connection_manager.send_message(
        session_id,
        AgentMessageEnd(
            turn_id=trace_id,
            finish_reason=FinishReason.STOP,
            total_tokens=150,
            latency_ms=1847
        )
    )

    logger.info(
        "user_message_processed",
        session_id=session_id,
        turn_id=trace_id,
        latency_ms=1847
    )

async def handle_user_action(session_id: str, user_id: str, payload):
    """
    Handle UserAction (pause, resume, interrupt, cancel).

    Args:
        session_id: K1 session ID
        user_id: User ID
        payload: UserAction payload
    """
    action = payload.action  # "pause" | "resume" | "interrupt" | "cancel"

    orchestrator = get_orchestrator()

    if action == "pause":
        await orchestrator.pause_turn(session_id)

    elif action == "resume":
        await orchestrator.resume_turn(session_id)

    elif action == "interrupt":
        await orchestrator.interrupt_turn(session_id)

    elif action == "cancel":
        await orchestrator.cancel_turn(session_id)

    logger.info(
```

**Pros:**
- Simple implementation

**Cons:**

**Pros:**

**Cons:**

## Consequences

### Benefits

1. **Full-Duplex Communication (Primary Goal):**
   - Client ↔ Server bidirectional (RFC 6455)
   - No polling: Server pushes messages as they arrive
   - Real-time actions: Pause, interrupt, clarification mid-stream

2. **Low Latency:**
   - TTFT <200ms (time to first token)
   - No polling overhead
   - Single persistent connection

3. **Binary Efficiency:**
   - FlatBuffers: ~2x smaller than JSON
   - ~10x faster parsing
   - Mobile-friendly (lower bandwidth)

4. **Streaming Response:**
   - OpenAI-style delta chunks (text_delta)
   - Anthropic-style thinking chunks
   - Tokens appear as typed (great UX)

5. **Auto-Reconnection:**
   - Exponential backoff: 1s, 2s, 4s, 8s, 16s
   - Message buffering (last 100 messages, 5-minute window)
   - Request missed messages on reconnect

### Drawbacks

1. **Stateful Connections:**
   - Server must maintain connection state
   - Horizontal scaling requires sticky sessions or Redis
   - Mitigation: Use sticky sessions (session_id hashing)

2. **Message Ordering:**
   - WebSocket doesn't guarantee ordering (TCP does, but app-level doesn't)
   - Need sequence numbers (chunk_index)
   - Mitigation: Add chunk_index to AgentMessageChunk

3. **Reconnection Complexity:**
   - Client must implement exponential backoff
   - Server must buffer messages
   - Mitigation: Provide client SDKs (TypeScript, Python)

4. **Firewall/Proxy Issues:**
   - Some corporate firewalls block WebSocket
   - Need fallback to HTTP polling
   - Mitigation: Provide fallback mechanism (rare issue)

5. **Mobile Battery:**
   - Persistent connection drains battery
   - Mitigation: Use heartbeat (30s), close connection on idle

```rust
// k1/api/websocket/ws_handler.rs
use tokio_tungstenite::{accept_async, WebSocketStream};
use flatbuffers::FlatBufferBuilder;

pub struct WebSocketHandler {
    jwt_validator: Arc<JWTValidator>,
    message_router: Arc<MessageRouter>,
    connection_registry: Arc<RwLock<HashMap<String, WebSocketConnection>>>,
}

pub struct WebSocketConnection {
    pub session_id: String,
    pub user_id: String,
    pub tx: mpsc::Sender<WebSocketMessage>,
    pub last_heartbeat: Instant,
}

impl WebSocketHandler {
    /// Handle new WebSocket connection
    pub async fn handle_connection(&self, stream: TcpStream, auth_token: String) -> Result<(), WSError> {
        // 1. Authenticate via JWT (ADR-0037)
        let claims = self.jwt_validator.validate(&auth_token).await?;

        // 2. Upgrade HTTP → WebSocket
        let ws_stream = accept_async(stream).await?;

        // 3. Register connection
        let (tx, mut rx) = mpsc::channel(100);
        let conn = WebSocketConnection {
            session_id: claims.session_id.clone(),
            user_id: claims.sub.clone(),
            tx: tx.clone(),
            last_heartbeat: Instant::now(),
        };

        let mut registry = self.connection_registry.write().await;
        registry.insert(claims.session_id.clone(), conn);
        drop(registry);

        WEBSOCKET_CONNECTIONS_TOTAL.inc();

        // 4. Message loop (bidirectional)
        let (mut ws_sender, mut ws_receiver) = ws_stream.split();

        loop {
            tokio::select! {
                // Client → Server messages
                msg = ws_receiver.next() => {
                    match msg {
                        Some(Ok(Message::Binary(data))) => {
                            self.handle_client_message(&claims.session_id, data).await?;
                        }
                        Some(Ok(Message::Ping(_))) => {
                            ws_sender.send(Message::Pong(vec![])).await?;
                        }
                        Some(Ok(Message::Close(_))) => break,
                        Some(Err(e)) => {
                            error!("WebSocket error: {:?}", e);
                            break;
                        }
                        None => break,
                    }
                }

                // Server → Client messages (from mpsc channel)
                msg = rx.recv() => {
                    match msg {
                        Some(ws_msg) => {
                            let binary_data = self.serialize_message(ws_msg).await?;
                            ws_sender.send(Message::Binary(binary_data)).await?;
                        }
                        None => break,
                    }
                }
            }
        }

        // 5. Cleanup on disconnect
        let mut registry = self.connection_registry.write().await;
        registry.remove(&claims.session_id);
        WEBSOCKET_CONNECTIONS_TOTAL.dec();

        Ok(())
    }

    /// Serialize message to FlatBuffers binary
    async fn serialize_message(&self, msg: WebSocketMessage) -> Result<Vec<u8>, WSError> {
        let mut builder = FlatBufferBuilder::new();

        match msg {
            WebSocketMessage::AgentMessageChunk { text_delta, trace_id } => {
                let text_delta_fb = builder.create_string(&text_delta);
                let trace_id_fb = builder.create_string(&trace_id);

                let chunk = AgentMessageChunk::create(&mut builder, &AgentMessageChunkArgs {
                    text_delta: Some(text_delta_fb),
                    trace_id: Some(trace_id_fb),
                    timestamp: Utc::now().timestamp(),
                });

                builder.finish(chunk, None);
            }
            // ... other message types
        }

        Ok(builder.finished_data().to_vec())
    }
}
```

```rust
// k1/api/websocket/reconnect_manager.rs
pub struct ReconnectManager {
    message_buffer: Arc<RwLock<HashMap<String, VecDeque<WebSocketMessage>>>>,
    buffer_size: usize, // 100 messages
    buffer_ttl: Duration, // 5 minutes
}

impl ReconnectManager {
    /// Buffer message for potential replay on reconnect
    pub async fn buffer_message(&self, session_id: &str, msg: WebSocketMessage) {
        let mut buffer = self.message_buffer.write().await;

        let session_buffer = buffer.entry(session_id.to_string()).or_insert(VecDeque::new());

        // Add message with timestamp
        session_buffer.push_back(msg);

        // Trim to last 100 messages
        if session_buffer.len() > self.buffer_size {
            session_buffer.pop_front();
        }
    }

    /// Get missed messages since last_message_id
    pub async fn get_missed_messages(&self, session_id: &str, last_message_id: &str) -> Vec<WebSocketMessage> {
        let buffer = self.message_buffer.read().await;

        if let Some(session_buffer) = buffer.get(session_id) {
            // Find messages after last_message_id
            let mut missed = Vec::new();
            let mut found_last = false;

            for msg in session_buffer.iter() {
                if found_last {
                    missed.push(msg.clone());
                }
                if msg.message_id == last_message_id {
                    found_last = true;
                }
            }

            return missed;
        }

        Vec::new()
    }
}
```

```rust
// k1/api/websocket/streaming_engine.rs
pub struct StreamingEngine {
    ws_connections: Arc<RwLock<HashMap<String, WebSocketConnection>>>,
    reconnect_manager: Arc<ReconnectManager>,
}

impl StreamingEngine {
    /// Stream agent response token-by-token (<200ms TTFT)
    pub async fn stream_agent_response(&self, session_id: &str, response: AgentResponse) -> Result<(), StreamError> {
        let connections = self.ws_connections.read().await;
        let conn = connections.get(session_id).ok_or(StreamError::NoConnection)?;

        let start = Instant::now();

        // 1. Send AgentMessageStart
        let start_msg = WebSocketMessage::AgentMessageStart {
            message_id: Uuid::new_v4().to_string(),
            agent_name: response.agent_name.clone(),
            trace_id: response.trace_id.clone(),
        };
        conn.tx.send(start_msg.clone()).await?;
        self.reconnect_manager.buffer_message(session_id, start_msg).await;

        // 2. Stream tokens (delta-based)
        let mut token_count = 0;
        for token in response.tokens {
            let chunk_msg = WebSocketMessage::AgentMessageChunk {
                message_id: Uuid::new_v4().to_string(),
                text_delta: token.text.clone(),
                trace_id: response.trace_id.clone(),
            };
            conn.tx.send(chunk_msg.clone()).await?;
            self.reconnect_manager.buffer_message(session_id, chunk_msg).await;

            token_count += 1;

            // Measure TTFT (time to first token)
            if token_count == 1 {
                let ttft_ms = start.elapsed().as_millis();
                WEBSOCKET_TTFT_MS.observe(ttft_ms as f64);
            }
        }

        // 3. Send AgentMessageEnd
        let end_msg = WebSocketMessage::AgentMessageEnd {
            message_id: Uuid::new_v4().to_string(),
            finish_reason: response.finish_reason.clone(),
            trace_id: response.trace_id.clone(),
        };
        conn.tx.send(end_msg.clone()).await?;
        self.reconnect_manager.buffer_message(session_id, end_msg).await;

        WEBSOCKET_MESSAGES_SENT_TOTAL
            .with_label_values(&["agent_response"])
            .inc_by(token_count as f64 + 2); // +2 for start/end

        Ok(())
    }
}
```

#### 4. **HeartbeatManager** (620 lines) — Connection Health Monitoring

```rust
// k1/api/websocket/heartbeat_manager.rs
pub struct HeartbeatManager {
    connections: Arc<RwLock<HashMap<String, WebSocketConnection>>>,
    heartbeat_interval: Duration, // 30 seconds
    timeout_threshold: Duration,  // 90 seconds (3× interval)
}

impl HeartbeatManager {
    /// Run heartbeat check loop (detects stale connections)
    pub async fn run_heartbeat_loop(&self) {
        let mut interval = tokio::time::interval(self.heartbeat_interval);

        loop {
            interval.tick().await;

            let mut connections = self.connections.write().await;
            let mut stale_sessions = Vec::new();

            for (session_id, conn) in connections.iter_mut() {
                let elapsed = conn.last_heartbeat.elapsed();

                if elapsed > self.timeout_threshold {
                    // Connection timed out (no heartbeat for 90s)
                    stale_sessions.push(session_id.clone());
                } else {
                    // Send ping (client must respond with pong)
                    let _ = conn.tx.send(WebSocketMessage::Ping).await;
                }
            }

            // Remove stale connections
            for session_id in stale_sessions {
                connections.remove(&session_id);
                WEBSOCKET_TIMEOUTS_TOTAL.inc();
            }
        }
    }
}
```
