## Context

### **IMPORTANT - Hybrid Architecture Context**

K1 uses a **hybrid Actor Model + AI architecture** (established in ADR-0001, ADR-0002, ADR-0004):

**Planner is an AI AGENT (ONE of 4 AI agents):**
- **USES Model Hub:** Planner calls Model Hub for LLM inference in Stage 1 (Sketch)
- **USES LLM Reasoning:** Stage 1 generates high-level plans via LLM creativity (temperature 0.3)
- **AI Agent Characteristics:**
  - WARMING state: Load Model Hub prompts (`plan_generation.jinja2`, 10ms)
  - ACTIVE state: LLM reasoning loop for sketch generation (150-500ms LLM inference)
  - Resource footprint: 150MB (model weights + KV cache)
  - Location: Layer 1 (`k1/planner/`) - One of 4 AI agents
- **Actor Model Foundation:** Planner still uses Actor Model (mailbox, message-passing, supervision)

**4-Stage Pipeline - AI Stage + Deterministic Stages:**

| Stage | Type | Model Hub | LLM | Latency | Description |
|-------|------|-----------|-----|---------|-------------|
| **1. Sketch** | 🤖 AI Agent | ✅ Yes | ✅ Yes | 150-500ms | LLM generates high-level plan outline (creative reasoning) |
| **2. Expand** | ⚡ Deterministic | ❌ No | ❌ No | <1ms | Lookup tool schemas from registry (pure dictionary lookup) |
| **3. Validate (Tier 1)** | ⚡ Deterministic | ❌ No | ❌ No | <1ms | Rule-based checks (structure, deps, caps, budget) |
| **3. Validate (Tier 2 Arbiter)** | 🤖 AI Agent | ✅ Yes | ✅ Yes | 50-100ms | LLM safety check for AMBER/RED plans (Safety Watch agent) |
| **4. Commit** | ⚡ Deterministic | ❌ No | ❌ No | <10ms | Serialize to FlatBuffers, persist to K0 WAL |

**Key Distinction for Planning Pipeline:**

| Aspect | Stage 1 (Sketch) - AI Agent | Stages 2-4 - Deterministic |
|--------|----------------------------|----------------------------|
| **Reasoning** | LLM creativity (Model Hub inference) | Rule-based logic (registry lookups, validation rules) |
| **Latency** | 150-500ms (LLM inference TTFT + E2E) | <12ms total (expand <1ms + validate <1ms + commit <10ms) |
| **Determinism** | Non-deterministic (LLM sampling, temperature 0.3) | Fully deterministic (same input → same output) |
| **Fallback** | Retry with refined prompt (max 2×) | Validation failure → rejection or arbiter escalation |
| **Resource** | High (model weights, KV cache, GPU/NPU) | Low (CPU, memory for registry lookups) |

**This ADR focuses on the 4-stage pipeline:** AI-powered Sketch (Stage 1) + deterministic Expand/Validate/Commit (Stages 2-4).

### Problem Statement

K1 Intelligence Module requires robust planning to convert user intents into executable task graphs:

1. **Creativity + Safety:** Leverage LLM creativity while ensuring safety through rule validation
2. **Structured Output:** Generate valid JSON plans (not free-form text)
3. **Fallback Strategies:** Gracefully handle invalid plans, missing tools, budget violations
4. **Fast Planning:** Complete planning <2.5s P95 (within E2E 2000ms budget)
5. **Audit Trail:** Persist committed plans to K0 WAL for compliance and debugging

**Key Challenges:**

- **LLM Hallucination:** Models generate invalid tool calls, circular dependencies, unsafe actions
- **Incomplete Plans:** Missing steps, undefined dependencies, incomplete slot filling
- **Budget Violations:** Plans exceed latency/cost budgets (user expectations misaligned)
- **Tool Availability:** Plans reference tools not available in current session (band/caps)
- **Safety Risks:** Plans contain harmful actions, PII leaks, unauthorized access

### Current Landscape

**Industry Patterns:**

1. **ReAct (Yao et al., 2022)**:
   - **Pattern:** Interleave reasoning and acting (Thought → Action → Observation loop)
   - **Strength:** Simple, autonomous, works well for single-agent tasks
   - **Weakness:** No upfront planning (inefficient), no validation (unsafe), sequential only

2. **Chain-of-Thought (Wei et al., 2022)**:
   - **Pattern:** Prompt LLM to "think step-by-step" before answering
   - **Strength:** Improves reasoning quality, reduces errors
   - **Weakness:** Free-form text (not structured plans), no validation

3. **Tree of Thoughts (Yao et al., 2023)**:
   - **Pattern:** Explore multiple reasoning paths (tree search), backtrack on failure
   - **Strength:** More thorough exploration than linear CoT
   - **Weakness:** Expensive (many LLM calls), slow (10+ seconds), overkill for simple tasks

4. **LangGraph Planning (LangChain, 2023)**:
   - **Pattern:** Static graph definition + runtime execution
   - **Strength:** Visual editing, deterministic routing
   - **Weakness:** Static graphs (cannot adapt to runtime conditions), no LLM-based planning

5. **AutoGPT Loop (Significant Gravitas, 2023)**:
   - **Pattern:** Plan → Execute → Observe → Replan (continuous loop)
   - **Strength:** Autonomous, adaptive
   - **Weakness:** No upfront validation, expensive (many LLM calls), slow convergence

6. **OpenAI Structured Outputs (2024)**:
   - **Pattern:** Constrained decoding with JSON schema enforcement
   - **Strength:** Guaranteed valid JSON output
   - **Weakness:** Still needs semantic validation (schemas don't catch circular deps, budget violations)

### Research Foundations

**Structured LLM Outputs**:

- **JSON Mode** (OpenAI, 2024) — Force JSON output via constrained decoding
- **Constrained Decoding** (Hokamp & Liu, 2017) — Grammar-based output constraints
- **Schema-Guided Generation** (Nye et al., 2021) — Generate outputs matching schemas

**Planning Under Uncertainty**:

- **HTN Planning** (Ghallab et al., 2004) — Hierarchical task networks with decomposition
- **PDDL** (McDermott et al., 1998) — Planning Domain Definition Language
- **GraphPlan** (Blum & Furst, 1997) — Graph-based planning with parallel actions

**Validation & Safety**:

- **Constitutional AI** (Anthropic, 2022) — LLM-based safety checks against principles
- **Red-Teaming** (Perez et al., 2022) — Adversarial testing for safety
- **Formal Verification** (Clarke et al., 2018) — Prove properties of plans (e.g., no deadlocks)

**Durable Execution**:

- **Write-Ahead Logging** (Gray, 1978) — Durability without blocking writes
- **Event Sourcing** (Fowler, 2005) — Store all state changes as events
- **Temporal Workflows** (Uber, 2020) — Durable workflows with replay

### K1 Requirements

**Performance Targets (from whiteboard.md L5500-5800):**

- **Stage 1 (Sketch):** <500ms (fast SLM or remote LLM)
- **Stage 2 (Expand):** <1ms (deterministic lookup, no LLM)
- **Stage 3 (Validate - Tier 1):** <1ms (rule-based checks)
- **Stage 3 (Validate - Tier 2 Arbiter):** 50-100ms (only for risky plans)
- **Stage 4 (Commit):** <10ms (persistence)
- **Total P95:** <2.5s (within E2E budget)

**Operational Requirements:**

- **Max plan complexity:** 12 steps (configurable)
- **Fallback retries:** 2 max (avoid latency spiral)
- **Arbiter invocation:** Only for AMBER/RED band plans (safety-critical)
- **Audit trail:** All committed plans logged to K0 WAL
- **Replanning:** Support mid-execution replanning (user interrupts, tool failures)

**Capability Requirements (whiteboard.md L1830-1840):**

- **Tool registry:** Schemas with latency hints, cost hints, band requirements, capability requirements
- **Prompt registry:** Prompt templates by role (router, planner, summarizer) and size (lite, standard, reasoning)
- **Capability matching:** Plans validated against session capabilities (tools, models, bands)

## Decision

We will implement a **4-stage planning pipeline** that balances LLM creativity with rule-based safety:

### Pipeline Overview

```
User Input
    ↓
┌────────────────────────────────────────────────────┐
│ STAGE 1: SKETCH (LLM, Creative)                   │
│  - Generate high-level plan outline               │
│  - Structured JSON output (steps, intent)         │
│  - Low temperature (0.3) for consistency          │
│  Duration: ~150-500ms                             │
└──────────────────┬─────────────────────────────────┘
                   ↓
┌────────────────────────────────────────────────────┐
│ STAGE 2: EXPAND (Deterministic, Fast)             │
│  - Fill tool schemas from registry                │
│  - Add caps/bands/latency/cost estimates          │
│  - No LLM call (pure lookup)                      │
│  Duration: <1ms                                   │
└──────────────────┬─────────────────────────────────┘
                   ↓
┌────────────────────────────────────────────────────┐
│ STAGE 3: VALIDATE (Two-Tier)                      │
│  Tier 1: Rules (<1ms, always run)                 │
│   - Structure, deps, caps, budget, bands          │
│  Tier 2: Arbiter (50-100ms, risky plans only)     │
│   - LLM safety check for AMBER/RED plans          │
│  Duration: <1ms (GREEN) or 50-100ms (AMBER/RED)   │
└──────────────────┬─────────────────────────────────┘
                   ↓
         [VALIDATION PASS?]
                   ↓
              ┌────┴────┐
              │  YES    │  NO → FALLBACK LOGIC

└──────────────────┬─────────────────────────────────┘
                   ↓
            TURN_PLAN → Orchestrator
```

## Stage 1: Sketch (LLM-Based High-Level Planning)

### Research Background

**Structured LLM Outputs**:

- **OpenAI JSON Mode** (2024) — Guarantees valid JSON output
- **Constrained Decoding** (Hokamp & Liu, 2017) — Force grammar compliance during generation
- **Schema-Guided Generation** (Nye et al., 2021) — LLM generates output matching JSON schema

**Prompt Engineering**:

- **Few-Shot Learning** (Brown et al., 2020) — Provide examples in prompt for better output
- **Chain-of-Thought** (Wei et al., 2022) — "Think step-by-step" improves reasoning
- **Role Prompting** (Reynolds & McDonell, 2021) — Assign LLM a role for specialized behavior

#### Sketch Implementation

```python
# k1/planner/sketch.py

from dataclasses import dataclass
import json
from typing import List, Dict

@dataclass
class SketchResult:
    """Result of sketch stage"""
    intent: str
    steps: List[Dict]
    complexity: str
    raw_output: str
    latency_ms: float

class Sketcher:
    """
    Stage 1: Generate high-level plan using LLM

    Research: Structured outputs (OpenAI 2024), Few-shot learning (Brown et al. 2020)
    """

    def __init__(self, model_hub, config):
        self.model_hub = model_hub
        self.config = config

    async def sketch(self, user_input, session, trace_id):
        """
        Generate high-level plan from user input

        Returns: SketchResult
        """
        start_time = perf_counter()

        # 1. Build prompt
        prompt = self._build_prompt(
            user_input=user_input,
            tool_list=self._format_tool_list(session.available_tools),
            context_summary=session.state.get_context_summary(),
        )

        # 2. Call LLM (structured output mode)
        try:
            response = await self.model_hub.infer(
                model=self.config.sketch_model,  # "gpt-4o-mini" or "gemma-2b"
                prompt=prompt,
                temperature=self.config.sketch_temperature,  # 0.3
                max_tokens=self.config.sketch_max_tokens,  # 800
                response_format={"type": "json_object"},  # Force JSON
                timeout_ms=self.config.sketch_timeout_ms,  # 2000ms
                trace_id=trace_id,
            )

            # 3. Parse JSON output
            sketch_json = json.loads(response.content)

            # 4. Validate structure (basic checks)
            self._validate_sketch_structure(sketch_json)

            # 5. Success
            latency_ms = (perf_counter() - start_time) * 1000

            logger.info(
                f"Sketch complete: {len(sketch_json['steps'])} steps",
                extra={
                    "intent": sketch_json["intent"],
                    "step_count": len(sketch_json["steps"]),
                    "complexity": sketch_json["complexity"],
                    "latency_ms": latency_ms,
                    "trace_id": trace_id,
                }
            )

            # Emit metrics
            self.metrics.histogram(
                "sketch_latency_ms",
                latency_ms,
                labels={"model": self.config.sketch_model}
            )

            return SketchResult(
                intent=sketch_json["intent"],
                steps=sketch_json["steps"],
                complexity=sketch_json.get("complexity", "medium"),
                raw_output=response.content,
                latency_ms=latency_ms,
            )

        except json.JSONDecodeError as e:
            # Invalid JSON output
            logger.error(f"Sketch produced invalid JSON: {e}", extra={"trace_id": trace_id})
            raise SketchError(f"Invalid JSON: {e}")

        except Exception as e:
            # Other error (model timeout, API error)
            logger.error(f"Sketch failed: {e}", extra={"trace_id": trace_id})
            raise SketchError(f"Sketch failed: {e}")

    def _build_prompt(self, user_input, tool_list, context_summary):
        """Build sketch prompt with few-shot examples"""
        return SKETCH_PROMPT_TEMPLATE.format(
            user_input=user_input,
            tool_list=tool_list,
            context_summary=context_summary,
        ) + "\n\n" + SKETCH_EXAMPLE

    def _format_tool_list(self, available_tools):
        """Format tool list for prompt (names + descriptions)"""
        return "\n".join([
            f"- {tool.name}: {tool.description}"
            for tool in available_tools
        ])

    def _validate_sketch_structure(self, sketch_json):
        """
        Basic structure validation

        Checks:
        - Required fields present (intent, steps)
        - Steps is array
        - Each step has id, op, description
        """
        if "intent" not in sketch_json:
            raise SketchError("Missing 'intent' field")

        if "steps" not in sketch_json or not isinstance(sketch_json["steps"], list):
            raise SketchError("Missing or invalid 'steps' field")

        for step in sketch_json["steps"]:
            if "id" not in step:
                raise SketchError(f"Step missing 'id': {step}")
            if "op" not in step:
                raise SketchError(f"Step missing 'op': {step}")
            if step["op"] not in ["Tool", "Model", "Ask"]:
                raise SketchError(f"Invalid op: {step['op']}")
```

## Stage 2: Expand (Deterministic Schema Filling)

### Research Background

**Deterministic Lookup**:

- No LLM call needed — pure lookup from registries
- **Tool Registry:** Schemas with latency/cost hints, band requirements
- **Prompt Registry:** Prompt templates with model class hints

### K1 Expand Stage

```python
# k1/planner/expand.py

class Expander:
    """
    Stage 2: Fill in tool schemas and estimates (deterministic)

    Research: Registry-based lookup (no LLM needed)
    """

    def __init__(self, tool_registry, prompt_registry):
        self.tool_registry = tool_registry
        self.prompt_registry = prompt_registry

    def expand(self, sketch, session, trace_id):
        """
        Fill in missing details from registries

        Returns: ExpandedPlan
        """
        start_time = perf_counter()

        expanded_steps = []

        for step in sketch.steps:
            try:
                if step["op"] == "Tool":
                    # Lookup tool spec
                    tool_spec = self.tool_registry.get(step["tool"])
                    if not tool_spec:
                        raise ExpansionError(f"Unknown tool: {step['tool']}")

                    # Add tool metadata
                    step["schema_in"] = tool_spec.schema_in
                    step["schema_out"] = tool_spec.schema_out
                    step["band_required"] = tool_spec.band_required
                    step["caps_required"] = tool_spec.caps_required
                    step["est_latency_ms"] = tool_spec.latency_hint_ms
                    step["cost_hint"] = tool_spec.cost_hint
                    step["critical"] = tool_spec.critical  # Can plan proceed if this fails?

                elif step["op"] == "Model":
                    # Lookup prompt template
                    prompt = self.prompt_registry.match(step["description"])
                    if not prompt:
                        raise ExpansionError(f"No prompt matched: {step['description']}")

                    # Add prompt metadata
                    step["prompt_id"] = prompt.id
                    step["model_class"] = prompt.model_class  # lite/standard/reasoning
                    step["est_latency_ms"] = prompt.latency_hint_ms
                    step["cost_hint"] = prompt.cost_hint
                    step["critical"] = True  # Model calls always critical

                elif step["op"] == "Ask":
                    # User clarification
                    step["timeout_s"] = step.get("timeout_s", 120)  # 2 min default
                    step["critical"] = True  # Cannot proceed without user input

                expanded_steps.append(step)

            except ExpansionError as e:
                # Log error and continue (validation will catch)
                logger.warning(
                    f"Expansion error for step {step['id']}: {e}",
                    extra={"trace_id": trace_id}
                )
                expanded_steps.append(step)  # Keep step (will fail validation)

        latency_ms = (perf_counter() - start_time) * 1000

        logger.info(
            f"Expansion complete: {len(expanded_steps)} steps",
            extra={"latency_ms": latency_ms, "trace_id": trace_id}
        )

        # Emit metrics

            intent=sketch.intent,
            steps=expanded_steps,
            complexity=sketch.complexity,
```

**LLM-Based Safety (Arbiter)**:

#### Tier 1: Rule-Based Validation (<1ms)

```python
# k1/planner/validate.py

class PlanValidator:
    """
    Stage 3 (Tier 1): Rule-based validation (fast, deterministic)

    Research: Constraint satisfaction (Russell & Norvig), Static analysis
    """

    def __init__(self, config):
        self.config = config

    def validate(self, plan, session, trace_id):
        """
        Validate plan against rules

        Returns: ValidationResult
        """
        start_time = perf_counter()
        errors = []

        # 1. Structural validation
        if len(plan.steps) == 0:
            errors.append("Plan has no steps")
        if len(plan.steps) > self.config.max_steps:
            errors.append(f"Plan too complex (max {self.config.max_steps} steps)")

        # 2. Dependency validation (DAG check)
        if self._has_cycle(plan.steps):
            errors.append("Plan has circular dependencies")

        # 3. Capability validation
        for step in plan.steps:
            if step["op"] == "Tool":
                # Check tool availability
                if step["tool"] not in session.available_tools:
                    errors.append(f"Tool '{step['tool']}' not available")

                # Check capabilities
                required_caps = step.get("caps_required", [])
                if not session.has_caps(required_caps):
                    errors.append(f"Missing caps for {step['tool']}: {required_caps}")

                # Check band
                required_band = step.get("band_required", "GREEN")
                if not session.band_allows(required_band):
                    errors.append(f"Step '{step['id']}' requires {required_band} band")

        # 4. Budget validation
        total_latency = sum(s.get("est_latency_ms", 0) for s in plan.steps)
        if total_latency > session.budget.latency_ms:
            errors.append(f"Plan exceeds latency budget: {total_latency}ms")

        total_cost = sum(s.get("cost_hint", 0) for s in plan.steps)
        if total_cost > session.budget.cost:
            errors.append(f"Plan exceeds cost budget: ${total_cost}")

        # 5. Step schema validation
        for step in plan.steps:
            if "schema_in" in step and "inputs" in step:
                # Validate inputs match schema
                schema_errors = self._validate_schema(step["inputs"], step["schema_in"])
                errors.extend(schema_errors)

        latency_ms = (perf_counter() - start_time) * 1000

        logger.info(
            f"Validation (Tier 1) complete: {len(errors)} errors",
            extra={"error_count": len(errors), "latency_ms": latency_ms, "trace_id": trace_id}
        )

        # Emit metrics
        self.metrics.histogram("validation_tier1_latency_ms", latency_ms)
        self.metrics.counter(
            "validation_tier1_errors_total",
            len(errors),
            labels={"has_errors": len(errors) > 0}
        )

        return ValidationResult(
            valid=len(errors) == 0,
            errors=errors,
            latency_ms=latency_ms,
        )

    def _has_cycle(self, steps):
        """
        Detect circular dependencies using DFS

        Returns: bool (True if cycle detected)
        """
        # Build adjacency list
        graph = defaultdict(list)
        for step in steps:
            step_id = step["id"]
            for dep in step.get("needs", []):
                graph[dep].append(step_id)

        # DFS cycle detection
        visited = set()
        rec_stack = set()

        def dfs(node):
            if node in rec_stack:
                return True  # Cycle detected
            if node in visited:
                return False

            visited.add(node)
            rec_stack.add(node)

            for neighbor in graph.get(node, []):
                if dfs(neighbor):
                    return True

            rec_stack.remove(node)
            return False

        # Check all nodes
        for step in steps:
            if dfs(step["id"]):
                return True

        return False

    def _validate_schema(self, inputs, schema):
        """
        Validate inputs match JSON schema

        Returns: List[str] (errors)
        """
        errors = []

        # Check required fields
        for field in schema.get("required", []):
            if field not in inputs:
                errors.append(f"Missing required field: {field}")

        # Check field types
        for field, value in inputs.items():
            if field in schema.get("properties", {}):
                expected_type = schema["properties"][field].get("type")
                actual_type = type(value).__name__
                # Simple type check (could use jsonschema library)
                if expected_type == "string" and not isinstance(value, str):
                    errors.append(f"Field {field} expected string, got {actual_type}")

        return errors
```

#### Tier 2: Arbiter (LLM Safety Check, 50-100ms, Risky Plans Only)

```python
# k1/planner/arbiter.py

ARBITER_PROMPT_TEMPLATE = """
You are a safety arbiter for a family AI system.

Review this plan and answer ONE question: "Is this plan safe to execute?"

Plan:
{plan_json}

User context:
- Age: {user_age}
- Space: {space_type} (home, child, restricted)
- Privacy band: {current_band} (GREEN, AMBER, RED, BLACK)

Answer with JSON:
{
  "safe": true|false,
  "reason": "brief explanation if unsafe"
}

Unsafe examples:
- Sharing private info without consent
- Actions that violate parental controls
- Plans that could harm user or family
- Unauthorized access to sensitive tools
"""

class SafetyArbiter:
    """
    Stage 3 (Tier 2): LLM-based safety check (only for risky plans)

    Research: Constitutional AI (Anthropic 2022), Red-teaming (Perez et al. 2022)
    """

    def __init__(self, model_hub, config):
        self.model_hub = model_hub
        self.config = config

    async def check_safety(self, plan, session, trace_id):
        """
        Use LLM to check plan safety

        Returns: SafetyResult
        """
        # Only invoke for risky plans (AMBER/RED band or restricted spaces)
        if not self._should_invoke(plan, session):
            return SafetyResult(safe=True, reason="Plan is GREEN band, skipping arbiter")

        start_time = perf_counter()

        # Build arbiter prompt
        prompt = ARBITER_PROMPT_TEMPLATE.format(
            plan_json=json.dumps(plan.to_dict(), indent=2),
            user_age=session.user.age,
            space_type=session.space.type,
            current_band=session.band.value,
        )

        try:
            # Call fast model (gpt-4o-mini)
            response = await self.model_hub.infer(
                model=self.config.arbiter_model,  # "gpt-4o-mini"
                prompt=prompt,
                temperature=0.0,  # Deterministic
                max_tokens=100,
                response_format={"type": "json_object"},
                timeout_ms=self.config.arbiter_timeout_ms,  # 1500ms
                trace_id=trace_id,
            )

            # Parse result
            safety_check = json.loads(response.content)

            latency_ms = (perf_counter() - start_time) * 1000

            logger.info(
                f"Arbiter check: {'SAFE' if safety_check['safe'] else 'UNSAFE'}",
                extra={
                    "safe": safety_check["safe"],
                    "reason": safety_check.get("reason", ""),
                    "latency_ms": latency_ms,
                    "trace_id": trace_id,
                }
            )

            # Emit metrics
            self.metrics.histogram("arbiter_latency_ms", latency_ms)
            self.metrics.counter(
                "arbiter_decisions_total",
                labels={"safe": safety_check["safe"]}
            )

            return SafetyResult(
                safe=safety_check["safe"],
                reason=safety_check.get("reason", ""),
                latency_ms=latency_ms,
            )

        except Exception as e:
            # Arbiter failed, default to unsafe (fail-closed)
            logger.error(f"Arbiter check failed: {e}", extra={"trace_id": trace_id})
            return SafetyResult(safe=False, reason=f"Arbiter error: {e}")

    def _should_invoke(self, plan, session):
        """
        Decide if arbiter check needed

        Invoke if:
        - Plan touches AMBER/RED band tools
        - Plan involves children or sensitive topics
        - User in restricted space
        """
        # Check plan band
        plan_band = max((step.get("band_required", "GREEN") for step in plan.steps), default="GREEN")
        if plan_band in ["AMBER", "RED", "BLACK"]:
            return True

        # Check space restrictions
        if session.space.type in ["child", "restricted"]:
            return True

        # Check user age (minors always get arbiter check)
        if session.user.age < 18:
            return True

        return False
```

```python
# k1/planner/commit.py

class Committer:
    """
    Stage 4: Persist validated plan to K0 (audit trail)

    Research: Write-ahead logging (Gray 1978), Event sourcing (Fowler 2005)
    """

    def __init__(self, k0_bridge, config):
        self.k0_bridge = k0_bridge
        self.config = config

    async def commit(self, plan, session, trace_id):
        """
        Commit validated plan to K0 and SessionState

        Returns: CommitResult
        """
        start_time = perf_counter()

        # 1. Serialize to FlowDef (FlatBuffers for efficiency)
        flow_def = FlowDef(
            flow_id=str(uuid4()),
            intent=plan.intent,
            steps=plan.steps,
            created_at=now(),
            trace_id=trace_id,
            session_id=session.id,
            space=session.space.id,
        )

        # 2. Write to K0 WAL (durable audit trail)
        await self.k0_bridge.persist(
            topic="PLAN_COMMITTED",
            payload=flow_def.to_flatbuffer(),
            space=session.space,
            trace_id=trace_id,
        )

        # 3. Lock SessionState (mark plan as active)
        session.state.current_flow = flow_def.flow_id
        session.state.flow_step_idx = 0
        session.state.flow_status = "ACTIVE"

        # 4. Emit STATE_DELTA (sync to K0)
        await session.state.emit_delta(
            field="current_flow",
            old_value=None,
            new_value=flow_def.flow_id,
            trace_id=trace_id,
        )

        latency_ms = (perf_counter() - start_time) * 1000

        logger.info(
            f"Plan committed: {flow_def.flow_id}",
            extra={
                "flow_id": flow_def.flow_id,
                "intent": plan.intent,
                "step_count": len(plan.steps),
                "latency_ms": latency_ms,
                "trace_id": trace_id,
            }
        )

        # Emit metrics
        self.metrics.histogram("commit_latency_ms", latency_ms)
        self.metrics.counter("plans_committed_total", labels={"intent": plan.intent})

        return CommitResult(
            flow_def=flow_def,
            latency_ms=latency_ms,
        )
```

## Fallback Logic (Handling Invalid Plans)

### Research Background

**Cascade Fallbacks** (Lu et al., 2024 - Chameleon):
- Try simpler methods when complex fails
- Graceful degradation instead of hard failure

**SEDA Graceful Degradation** (Welsh et al., 2001):
- Degrade service quality, don't fail hard

### K1 Fallback Strategies

```python
# k1/planner/fallbacks.py

class PlannerFallbackStrategy:
    """
    Fallback strategies for invalid/incomplete plans

    Research: Cascade fallbacks (Chameleon, Lu et al. 2024), SEDA degradation
    """

    def __init__(self, planner, config):
        self.planner = planner
        self.config = config
        self.retry_count = 0

    async def handle_failure(self, failure_type, context, trace_id):
        """
        Handle planning failure with fallback strategies

        Returns: Plan (recovered) or raises PlanningError
        """
        # Fallback 1: Retry with stricter constraints
        if failure_type == "INVALID_STRUCTURE" and self.retry_count < self.config.retry_max:
            logger.info(f"Fallback 1: Retry with constraints (attempt {self.retry_count + 1})")
            self.retry_count += 1
            return await self._retry_with_constraints(context, trace_id)

        # Fallback 2: Simplify plan (remove unavailable tools)
        if failure_type == "MISSING_TOOLS":
            logger.info("Fallback 2: Simplify plan")
            return await self._simplify_plan(context, trace_id)

        # Fallback 3: Optimize for cost (cheaper alternatives)
        if failure_type == "BUDGET_EXCEEDED":
            logger.info("Fallback 3: Optimize for cost")
            return await self._optimize_for_cost(context, trace_id)

        # Fallback 4: Ask user to refine (arbiter rejected)
        if failure_type == "UNSAFE":
            logger.info("Fallback 4: Ask user for clarification")
            return await self._ask_user_to_refine(context, trace_id)

        # Fallback 5: Graceful degradation (simple response, no plan)
        if self.retry_count >= self.config.retry_max or failure_type == "RETRY_EXHAUSTED":
            logger.warning("All fallbacks exhausted, degrading to simple reply")
            return await self._degrade_to_simple_reply(context, trace_id)

        # Unknown failure type
        raise PlanningError(f"Unknown failure type: {failure_type}")

    async def _retry_with_constraints(self, context, trace_id):
        """
        Retry sketch with stricter prompt
        """
        # Add constraint examples to prompt
        constrained_prompt = f"""
        PREVIOUS ATTEMPT FAILED: {context.error}

        You MUST output valid JSON with these fields:
        - "intent": string
        - "steps": array of objects with id, op, description, needs

        Example:
        {json.dumps(EXAMPLE_VALID_PLAN, indent=2)}

        Now try again for: "{context.user_input}"
        """

        # Retry with temperature=0 (deterministic)
        return await self.planner.sketch(
            constrained_prompt,
            session=context.session,
            temperature=0.0,
            trace_id=trace_id,
        )

    async def _simplify_plan(self, context, trace_id):
        """
        Remove steps with unavailable tools
        """
        plan = context.plan
        available_tools = set(context.session.available_tools)

        simplified_steps = []
        removed_tools = []

        for step in plan.steps:
            if step["op"] == "Tool" and step["tool"] not in available_tools:
                # Tool not available, try to find alternative
                alt_tool = self._find_alternative_tool(step["tool"], available_tools)
                if alt_tool:
                    step["tool"] = alt_tool
                    simplified_steps.append(step)
                else:
                    removed_tools.append(step["tool"])
            else:
                simplified_steps.append(step)

        # Notify user of simplification
        if removed_tools:
            disclaimer = f"I don't have access to {', '.join(removed_tools)}, but I can still help with {self._describe_plan(simplified_steps)}"
            context.session.add_disclaimer(disclaimer)

        plan.steps = simplified_steps
        return plan

    async def _optimize_for_cost(self, context, trace_id):
        """
        Swap expensive model calls for cheaper alternatives
        """
        plan = context.plan
        budget = context.session.budget

        for step in plan.steps:
            if step["op"] == "Model":
                # Downgrade: reasoning → standard → lite
                if step["model_class"] == "reasoning" and budget.allows("standard"):
                    step["model_class"] = "standard"
                    step["cost_hint"] /= 5  # Approximate 5x cheaper
                elif step["model_class"] == "standard" and budget.allows("lite"):
                    step["model_class"] = "lite"
                    step["cost_hint"] /= 3  # Approximate 3x cheaper

        return plan

    async def _ask_user_to_refine(self, context, trace_id):
        """
        Ask user to clarify request (arbiter rejected plan)
        """
        safety_reason = context.safety_result.reason

        clarification = {
            "op": "Ask",
            "prompt": f"I want to make sure I understand correctly. {safety_reason}. Can you clarify what you'd like me to do?",
            "slot": "refined_request",
        }

        # Return simple clarification plan
        return Plan(
            intent="clarify_request",
            steps=[clarification],
            complexity="simple",
        )

    async def _degrade_to_simple_reply(self, context, trace_id):
        """
        Graceful degradation: simple response without plan execution
        """
        # Use fast model for simple reply
        simple_reply = await self.model_hub.infer(
            model="gpt-4o-mini",
            prompt=f"Give a helpful but simple reply to: '{context.user_input}'",
            max_tokens=150,
            temperature=0.7,
            trace_id=trace_id,
        )

        # Return simple reply (no plan)
        return SimpleReply(
            text=simple_reply.content,
            disclaimer="I'm having trouble planning that right now. Here's what I can tell you:"
        )
```

### **Decision Matrix**

**Six alternatives evaluated for planning pipeline design:**

| Alternative | LLM Creativity | Safety (Validation) | Latency | Complexity | Maintainability | K1 Fit |
|-------------|----------------|-------------------|---------|------------|-----------------|--------|

| **6. 4-Stage (Sketch → Expand → Validate → Commit)** | ✅ Yes | ✅ High (2-tier) | ✅ Fast (<600ms) | ⚠️ Medium | ✅ High | ✅ **9/10** |

**Decision: Alternative 6 (4-Stage Pipeline) selected.**

**Key Decision Factors:**

1. **LLM Creativity:** Stage 1 (Sketch) leverages LLM for high-level planning, enables open-ended user requests
2. **Safety Validation:** 2-tier validation (Tier 1 rules <1ms always, Tier 2 arbiter 50-100ms AMBER/RED only) balances speed + safety
3. **Latency Budget:** 4 stages complete <600ms P95 (Stage 1: 150-500ms, Stages 2-4: <12ms) ✅ within 2.5s turn budget
4. **Separation of Concerns:** Sketch (LLM creative) → Expand (deterministic lookups) → Validate (rules + arbiter) → Commit (persistence) = clear boundaries
5. **Fallback Strategies:** Retry sketch (max 2×), simplify plan, degrade to simple response = graceful degradation
6. **Observability:** Each stage logged with latency, success/failure, validation errors = full audit trail

**Rejection Rationale:**

- **Alternative 1 (Single-Stage LLM):** Unsafe - no validation means hallucinated tools executed, circular dependencies undetected, budget violations ignored
- **Alternative 2 (Pure Rule-Based):** No creativity - cannot handle novel requests like "book dinner with my wife at 7pm and check if it'll rain"
- **Alternative 3 (Tree of Thoughts):** Latency unacceptable - 5-10s planning exceeds 2.5s budget by 2-4×, overkill for most tasks
- **Alternative 4 (2-Stage):** Incomplete plans - no schema filling means missing metadata (latency hints, cost hints, capability requirements), harder validation
- **Alternative 5 (6-Stage with Simulation):** Latency overhead - simulation adds +2-3s for dry-run execution, exceeds budget, over-engineering for deterministic validation

**Research Foundation:**
- **Structured LLM Outputs (OpenAI, 2024):** Stage 1 uses JSON mode for valid JSON plans
- **Two-Tier Validation:** Stage 3 uses rule-based (Tier 1) + LLM-based arbiter (Tier 2) for speed + safety balance
- **Write-Ahead Logging (Gray, 1978):** Stage 4 persists to K0 WAL for durability + audit trail
