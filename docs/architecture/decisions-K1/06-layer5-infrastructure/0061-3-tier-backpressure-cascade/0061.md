# ADR-0061: 3-Tier Backpressure Cascade for K1 Intelligence Module

**Status:** Proposed
**Date:** 2025-10-15
**Last Updated:** 2025-01-15 (M4 Context: See ADR-0078 for backpressure handling in tool batching)
**Tier:** 1
**Umbrella ADR**

## Context

K1 Intelligence Module must operate under strict resource constraints while providing responsive user experience across multiple concurrent sessions. The system faces three fundamental challenges:

1. **Resource Contention**: Multiple agents (1-3 per session), concurrent sessions (10-15), voice processing (ASR/TTS), tool execution, and K0 bridge communication all compete for CPU, memory, and I/O bandwidth
2. **Latency Sensitivity**: User-facing operations require tight latency budgets (TTFT <150ms, turn completion <2000ms), but resource exhaustion causes unbounded delays
3. **Graceful Degradation**: System must degrade gracefully under overload rather than crashing or hanging, maintaining partial functionality

**Current Situation:**

Traditional chatbot systems handle overload using one of these anti-patterns:
- **No backpressure**: Accept all requests until OOM crash (99% → 0% availability cliff)
- **Simple rejection**: Binary "503 Service Unavailable" at capacity (no graceful degradation)
- **Global rate limiting**: Fixed requests/second limit (no differentiation by priority or cost)
- **Retry storms**: Clients retry immediately, amplifying overload (thundering herd)

These approaches fail for multi-modal agentic systems:
- ❌ **Catastrophic failure**: No backpressure = OOM crash = complete outage
- ❌ **Poor UX**: Binary rejection = user sees error, no partial response
- ❌ **No priority**: Critical operations (RED band arbiter approval) treated same as background tasks
- ❌ **No observability**: No early warning signals before crash
- ❌ **No voice-specific handling**: Audio pipeline failures invisible to generic backpressure

**Constraints:**

- **Performance**: Backpressure checks <5ms overhead (<1% of turn latency)
- **Memory**: Backpressure state tracking <5MB total (queue depths, watermark states)
- **Latency Budgets**: TTFT <150ms P95, E2E turn <2000ms P95 (must preserve under load)
- **Availability**: 99.9% uptime target (43.2 min/month downtime)
- **Privacy**: RED band operations must bypass limits (arbiter approval, emergency safety)

**Forces:**

- 📈 **Reactive backpressure benefits**: Prevents OOM, provides early warning, enables graceful degradation (SEDA, Reactive Streams, TCP congestion control)
- 📉 **Overhead**: Every operation must check backpressure state
- 📈 **Industry proven**: Netflix Hystrix (circuit breakers), Kafka (broker quotas), WebRTC (adaptive bitrate), Envoy (global rate limiting)
- 📉 **Complexity**: 3-tier cascade (per-stream + voice + global) requires careful tuning
- 📈 **Voice-specific needs**: Audio pipeline has unique backpressure signals (frame drops, TTS degradation, barge-in preemption)

---

## Decision

We adopt a **3-tier backpressure cascade** with per-stream watermarks, voice-specific overload actions, and global resource monitoring. This provides:

- **Tier 1**: Per-stream watermark monitoring (audio_frames, agent_mailbox, k0_outbox, sse_subscribers)
- **Tier 2**: Voice pipeline overload handling (ASR input, intent queue, tool executor, TTS queue, audio output)
- **Tier 3**: Global backpressure (total memory, total queue items, sustained overload alerts)

### **Decision Matrix**

**Five alternatives evaluated for backpressure management:**

| Alternative                 | Graceful Degradation | Observability   | Voice Support | Complexity | Overhead | K1 Fit     |
| --------------------------- | -------------------- | --------------- | ------------- | ---------- | -------- | ---------- |
| **1. No Backpressure**      | ❌ None               | ❌ None          | ❌ No          | ✅ Low      | ✅ 0ms    | ❌ 1/10     |
| **2. Simple Rate Limiting** | ⚠️ Binary             | ⚠️ Counter only  | ❌ No          | ✅ Low      | ✅ <1ms   | ⚠️ 4/10     |
| **3. Circuit Breakers**     | ⚠️ Binary             | ✅ State machine | ❌ No          | ⚠️ Medium   | ⚠️ 2ms    | ⚠️ 6/10     |
| **4. Token Bucket**         | ⚠️ Binary             | ⚠️ Token count   | ❌ No          | ✅ Low      | ✅ <1ms   | ⚠️ 5/10     |
| **5. 3-Tier Cascade**       | ✅ Progressive        | ✅ Multi-level   | ✅ Yes         | ⚠️ High     | ✅ <5ms   | ✅ **9/10** |

**Decision: Alternative 5 (3-Tier Cascade) selected.**

**Key Decision Factors:**

1. **Progressive Degradation**: 3 levels (warn at 80%, degrade at 90%, reject at 95%) provide gradual quality reduction vs binary failure
2. **Voice-Specific Handling**: Tier 2 handles voice pipeline uniquely (frame drops, TTS degradation, barge-in) which generic solutions miss
3. **Observability**: Per-stream, per-stage, and global metrics enable precise diagnosis of bottlenecks
4. **Priority Support**: RED band operations bypass limits (critical for safety/privacy arbiter approval)
5. **Industry Proven**: Combines reactive streams (SEDA), adaptive QoS (WebRTC), and circuit breakers (Hystrix)

**Rejection Rationale:**

- **Alternative 1 (No Backpressure)**: Unacceptable - leads to OOM crashes and complete outages
- **Alternative 2 (Simple Rate Limiting)**: Too coarse - no progressive degradation, no voice-specific handling
- **Alternative 3 (Circuit Breakers)**: Binary on/off, misses voice pipeline complexity, no per-stream watermarks
- **Alternative 4 (Token Bucket)**: Good for rate limiting but lacks progressive degradation and voice pipeline integration

### **Core Principles**

**1. Progressive Degradation (Not Binary Failure)**
- **80% watermark** (WARN): Emit alert, continue normal operation
- **90% watermark** (DEGRADE): Apply degradation actions (drop background tasks, reduce quality)
- **95% watermark** (REJECT): Block new requests, force shedding
- **Rationale**: Users prefer degraded service over no service

**2. Per-Stream Monitoring (Localized Bottlenecks)**
- Each stream monitored independently: `audio_frames`, `agent_mailbox`, `k0_outbox`, `sse_subscribers`
- Stream-specific overflow actions: drop_oldest (audio), block_sender (mailbox), merge_deltas (K0), disconnect_slow (SSE)
- **Rationale**: Audio frame loss tolerable, agent control messages are not

**3. Voice-Specific Overload Handling (Tier 2)**
- 5 voice pipeline stages monitored: ASR input, intent queue, tool executor, TTS queue, audio output
- Stage-specific actions: downsample ASR (90%), drop partial frames (80%), shed ephemeral tools (75%), degrade TTS quality (80%), fast-forward audio (95%)
- **Rationale**: Voice pipeline has unique characteristics (latency-sensitive, high throughput, graceful degradation opportunities)

**4. Global Resource Monitoring (System-Wide Protection)**
- Total memory limit: 512MB for all queues
- Total queue items limit: 5000 across all streams
- Sustained overload detection: >10s continuous backpressure triggers alerts
- **Rationale**: Prevents cascade failures, provides early warning for capacity planning

**5. Priority-Based Bypass (Critical Operations Protected)**
- RED band operations bypass limits: arbiter approval, safety checks, emergency shutdown
- Priority classes: CRITICAL (0) → REALTIME (1) → INTERACTIVE (2) → BACKGROUND (3)
- **Rationale**: Safety and privacy must never be blocked by backpressure

**6. Observability-Driven (Metrics → Alerts → Runbooks)**
- RED metrics (Rate, Errors, Duration) for all operations
- Grafana dashboards show real-time queue depths, watermark breaches, degradation actions
- Alerting rules trigger at 80% (warning), 90% (page on-call), 95% (critical incident)
- **Rationale**: Operators need visibility to diagnose and resolve bottlenecks

### **Tier 1: Per-Stream Watermark Monitoring**

**Purpose**: Detect and handle localized bottlenecks in specific queues before they propagate system-wide.

**Monitored Streams:**

1. **audio_frames** (ring buffer, 100 frames max)
   - **Overflow action**: `drop_oldest` - Newest audio most relevant for real-time processing
   - **Rationale**: Missing interim frames acceptable, final frames critical

2. **agent_mailbox** (MPSC queue, 50 messages max)
   - **Overflow action**: `block_sender` - Control messages must not be dropped
   - **Rationale**: Agent coordination requires reliable message delivery

3. **k0_outbox** (priority queue, 1000 receipts max)
   - **Overflow action**: `merge_deltas` - Multiple state deltas can be combined
   - **Rationale**: Reduces queue pressure through compression (2-3× reduction)

4. **sse_subscribers** (per-client buffer, 200 events max)
   - **Overflow action**: `disconnect_slow_clients` - Prevent one slow client blocking others
   - **Rationale**: Slow clients can reconnect, fast clients unaffected

**Watermark Evaluation (Continuous):**

```python
# k1/infrastructure/backpressure/watermark_checker.py
from dataclasses import dataclass
from enum import Enum
import asyncio

class WatermarkLevel(Enum):
    NORMAL = "NORMAL"      # <80%
    WARN = "WARN"          # 80-89%
    DEGRADE = "DEGRADE"    # 90-94%
    REJECT = "REJECT"      # ≥95%

@dataclass
class StreamState:
    stream_name: str
    current_depth: int
    max_depth: int
    watermark_level: WatermarkLevel
    action_taken: str | None
    timestamp_ms: int

class WatermarkChecker:
    """Continuous per-stream watermark monitoring"""

    def __init__(self, config: BackpressureConfig):
        self.config = config
        self.stream_states = {}
        self.metrics = PrometheusMetrics()

    async def monitor_streams(self):
        """Monitor all streams at 1ms poll frequency"""
        while True:
            for stream_name, stream_config in self.config.per_stream_watermarks.items():
                await self.check_stream(stream_name, stream_config)
            await asyncio.sleep(0.001)  # 1ms poll (1kHz)

    async def check_stream(self, stream_name: str, config: StreamConfig):
        """Evaluate watermarks for single stream"""

        # 1. Get current queue depth
        current_depth = await self.get_queue_depth(stream_name)

        # 2. Calculate watermark percentage
        pct = (current_depth / config.high) * 100

        # 3. Determine watermark level
        if pct >= 95:
            level = WatermarkLevel.REJECT
            action = config.action  # drop_oldest, block_sender, etc.
            await self.apply_action(stream_name, action)
        elif pct >= 90:
            level = WatermarkLevel.DEGRADE
            action = config.action
            await self.apply_action(stream_name, action)
        elif pct >= 80:
            level = WatermarkLevel.WARN
            action = None  # Just alert, no action
            self.emit_alert(stream_name, "approaching capacity")
        else:
            level = WatermarkLevel.NORMAL
            action = None

        # 4. Update state and metrics
        self.stream_states[stream_name] = StreamState(
            stream_name=stream_name,
            current_depth=current_depth,
            max_depth=config.high,
            watermark_level=level,
            action_taken=action,
            timestamp_ms=time.time_ns() // 1_000_000
        )

        self.metrics.backpressure_watermark_level.labels(
            stream=stream_name
        ).set(level.value)

        self.metrics.backpressure_queue_depth.labels(
            stream=stream_name
        ).set(current_depth)

    async def apply_action(self, stream_name: str, action: str):
        """Apply overflow action to stream"""

        if action == "drop_oldest":
            # Audio frames: Drop oldest frame from ring buffer
            await self.audio_buffer.drop_oldest()
            self.metrics.backpressure_frames_dropped_total.labels(
                stream=stream_name
            ).inc()

        elif action == "block_sender":
            # Agent mailbox: Return 503 Service Unavailable to sender
            await self.router.block_sender(stream_name, retry_after_ms=100)
            self.metrics.backpressure_blocked_sends_total.labels(
                stream=stream_name
            ).inc()

        elif action == "merge_deltas":
            # K0 outbox: Merge multiple StateDelta messages
            merged = await self.k0_bridge.merge_deltas(max_merge=10)
            self.metrics.backpressure_deltas_merged_total.labels(
                stream=stream_name
            ).inc(merged)

        elif action == "disconnect_slow":
            # SSE subscribers: Disconnect clients with >200 buffered events
            disconnected = await self.sse_manager.disconnect_slow_clients(threshold=200)
            self.metrics.backpressure_clients_disconnected_total.labels(
                stream=stream_name
            ).inc(disconnected)
```

### **Tier 2: Voice Pipeline Overload Handling**

**Purpose**: Voice pipeline has unique characteristics requiring specialized backpressure handling distinct from generic queues.

**5 Voice Pipeline Stages:**

1. **ASR Input Buffer** (200ms max, 16kHz audio)
   - **80% (160ms)**: Drop partial ASR frames (keep final frame only)
   - **90% (180ms)**: Downsample to 8kHz (50% data rate reduction)
   - **95% (190ms)**: Pause ASR, show "thinking..." spinner

2. **Intent Queue** (50 intents max, priority-based)
   - **70% (35 intents)**: Merge duplicate intents in 500ms window
   - **85% (42 intents)**: Drop BACKGROUND priority intents
   - **95% (47 intents)**: Block new intents, show "One moment..." message

3. **Tool Executor** (20 concurrent tools max)
   - **75% (15 tools)**: Shed ephemeral tools (weather, news, stocks, sports)
   - **90% (18 tools)**: Kill long-running tools (>2000ms execution time)

4. **TTS Queue** (500ms buffer max, neural voice)
   - **80% (400ms)**: Degrade voice quality (neural → concatenative, -3dB quality)
   - **90% (450ms)**: Speed up playback (1.15× faster, 15% faster speech)
   - **95% (475ms)**: Truncate response (first 3 sentences + "... (truncated due to load)")

5. **Audio Output Buffer** (400ms max, real-time playback)
   - **85% (340ms)**: Drop silence frames (>100ms silence trimmed)
   - **95% (380ms)**: Fast-forward to live (skip to current audio position, 50ms fade)

**Voice Pipeline Monitor Implementation:**

```python
# k1/infrastructure/backpressure/voice_pipeline_monitor.py
class VoicePipelineMonitor:
    """Monitor voice pipeline stages with specialized degradation actions"""

    def __init__(self, config: VoiceBackpressureConfig):
        self.config = config
        self.stage_states = {}
        self.metrics = PrometheusMetrics()

    async def monitor_voice_pipeline(self):
        """Monitor all 5 stages continuously"""
        while True:
            await asyncio.gather(
                self.monitor_asr_input(),
                self.monitor_intent_queue(),
                self.monitor_tool_executor(),
                self.monitor_tts_queue(),
                self.monitor_audio_output()
            )
            await asyncio.sleep(0.001)  # 1ms poll

    async def monitor_asr_input(self):
        """ASR input buffer monitoring"""
        stage_config = self.config.voice_pipeline_stages.asr_input
        current_buffer_ms = await self.asr_input.get_buffer_length_ms()

        pct = (current_buffer_ms / stage_config.buffer_ms) * 100

        if pct >= 95:
            # REJECT: Pause ASR, show spinner
            await self.asr_input.pause()
            await self.ui.show_spinner("Processing audio...")
            self.metrics.voice_asr_paused_total.inc()

        elif pct >= 90:
            # DEGRADE: Downsample to 8kHz
            await self.asr_input.set_sample_rate(8000)  # From 16kHz
            self.metrics.voice_asr_downsampled_total.inc()

        elif pct >= 80:
            # WARN: Drop partial frames
            await self.asr_input.drop_partial_frames()
            self.metrics.voice_asr_frames_dropped_total.inc()

        # Emit metrics
        self.metrics.voice_asr_buffer_ms.set(current_buffer_ms)
        self.metrics.voice_asr_buffer_pct.set(pct)

    async def monitor_intent_queue(self):
        """Intent queue monitoring"""
        stage_config = self.config.voice_pipeline_stages.intent_queue
        current_size = await self.intent_queue.size()

        pct = (current_size / stage_config.max_size) * 100

        if pct >= 95:
            # REJECT: Block new intents
            self.intent_queue.set_admission(False)
            await self.ui.show_message("One moment, processing...")
            self.metrics.voice_intents_blocked_total.inc()

        elif pct >= 85:
            # DEGRADE: Drop BACKGROUND intents
            dropped = await self.intent_queue.drop_by_priority(priority=3)
            self.metrics.voice_intents_dropped_total.labels(priority="BACKGROUND").inc(dropped)

        elif pct >= 70:
            # WARN: Merge duplicates
            merged = await self.intent_queue.merge_duplicates(window_ms=500)
            self.metrics.voice_intents_merged_total.inc(merged)

        self.metrics.voice_intent_queue_size.set(current_size)
        self.metrics.voice_intent_queue_pct.set(pct)

    async def monitor_tool_executor(self):
        """Tool executor monitoring"""
        stage_config = self.config.voice_pipeline_stages.tool_executor
        active_tools = await self.tool_executor.active_count()

        pct = (active_tools / stage_config.max_concurrent) * 100

        if pct >= 90:
            # REJECT: Kill long-running tools (>2000ms)
            killed = await self.tool_executor.kill_long_running(threshold_ms=2000)
            self.metrics.voice_tools_killed_total.inc(killed)

        elif pct >= 75:
            # DEGRADE: Shed ephemeral tools
            shed = await self.tool_executor.shed_ephemeral()
            self.metrics.voice_tools_shed_total.inc(shed)

        self.metrics.voice_tool_executor_active.set(active_tools)
        self.metrics.voice_tool_executor_pct.set(pct)

    async def monitor_tts_queue(self):
        """TTS queue monitoring"""
        stage_config = self.config.voice_pipeline_stages.tts_queue
        buffer_ms = await self.tts_queue.get_buffer_length_ms()

        pct = (buffer_ms / stage_config.buffer_ms) * 100

        if pct >= 95:
            # REJECT: Truncate response
            await self.tts_queue.truncate_response(max_sentences=3, suffix="... (truncated due to load)")
            self.metrics.voice_tts_truncated_total.inc()

        elif pct >= 90:
            # DEGRADE: Speed up playback
            await self.tts_queue.set_playback_speed(1.15)  # 15% faster
            self.metrics.voice_tts_speedup_total.inc()

        elif pct >= 80:
            # WARN: Degrade voice quality
            await self.tts_queue.set_voice_quality("concatenative")  # From "neural"
            self.metrics.voice_tts_degraded_total.inc()

        self.metrics.voice_tts_buffer_ms.set(buffer_ms)
        self.metrics.voice_tts_buffer_pct.set(pct)

    async def monitor_audio_output(self):
        """Audio output buffer monitoring"""
        stage_config = self.config.voice_pipeline_stages.audio_output
        buffer_ms = await self.audio_output.get_buffer_length_ms()

        pct = (buffer_ms / stage_config.buffer_ms) * 100

        if pct >= 95:
            # REJECT: Fast-forward to live
            await self.audio_output.fast_forward_to_live(fade_ms=50)
            self.metrics.voice_audio_ff_total.inc()

        elif pct >= 85:
            # WARN: Drop silence frames
            dropped = await self.audio_output.drop_silence(min_silence_ms=100)
            self.metrics.voice_audio_silence_dropped_total.inc(dropped)

        self.metrics.voice_audio_output_buffer_ms.set(buffer_ms)
        self.metrics.voice_audio_output_pct.set(pct)
```

### **Tier 3: Global Backpressure Monitoring**

**Purpose**: Protect system-wide resources and detect cascade failures before they cause OOM crashes.

**Global Limits:**
- **Total Memory**: 512MB max across all queues
- **Total Queue Items**: 5000 max across all streams
- **Sustained Threshold**: 10s continuous backpressure triggers alert

**Global Monitor Implementation:**

```python
# k1/infrastructure/backpressure/global_limits_enforcer.py
class GlobalLimitsEnforcer:
    """System-wide resource monitoring and protection"""

    def __init__(self, config: GlobalBackpressureConfig):
        self.config = config
        self.sustained_start_time = None
        self.metrics = PrometheusMetrics()

    async def monitor_global_limits(self):
        """Monitor total memory and queue items"""
        while True:
            await self.check_total_memory()
            await self.check_total_queue_items()
            await self.check_sustained_backpressure()
            await asyncio.sleep(0.1)  # 100ms poll (10Hz)

    async def check_total_memory(self):
        """Check total in-flight memory across all queues"""

        # Sum memory across all streams
        total_memory_mb = 0
        total_memory_mb += await self.audio_buffer.memory_usage_mb()
        total_memory_mb += await self.agent_mailboxes.total_memory_mb()
        total_memory_mb += await self.k0_outbox.memory_usage_mb()
        total_memory_mb += await self.sse_buffers.total_memory_mb()

        pct = (total_memory_mb / self.config.max_memory_mb) * 100

        if total_memory_mb >= self.config.critical_memory_mb:
            # CRITICAL: Shed non-critical work globally
            await self.shed_background_work()
            self.emit_critical_alert("OOM imminent", memory_mb=total_memory_mb)
            self.metrics.backpressure_global_memory_critical_total.inc()

        elif pct >= 90:
            # WARNING: Approaching memory limit
            self.emit_warning("memory pressure", memory_mb=total_memory_mb)

        self.metrics.backpressure_global_memory_mb.set(total_memory_mb)
        self.metrics.backpressure_global_memory_pct.set(pct)

    async def check_total_queue_items(self):
        """Check total queue items across all streams"""

        # Sum queue depths across all streams
        total_items = 0
        total_items += await self.audio_buffer.depth()
        total_items += await self.agent_mailboxes.total_depth()
        total_items += await self.k0_outbox.depth()
        total_items += await self.sse_buffers.total_depth()
        total_items += await self.intent_queue.depth()
        total_items += await self.tool_executor.queue_depth()

        pct = (total_items / self.config.max_total_queue_items) * 100

        if total_items >= self.config.critical_queue_items:
            # CRITICAL: Cascading degradation
            await self.apply_cascading_degradation()
            self.emit_critical_alert("cascade failure risk", queue_items=total_items)
            self.metrics.backpressure_global_items_critical_total.inc()

        elif pct >= 90:
            # WARNING: Approaching queue limit
            self.emit_warning("queue pressure", queue_items=total_items)

        self.metrics.backpressure_global_queue_items.set(total_items)
        self.metrics.backpressure_global_queue_pct.set(pct)

    async def check_sustained_backpressure(self):
        """Detect sustained backpressure (>10s continuous)"""

        # Check if ANY stream is in DEGRADE or REJECT state
        in_backpressure = any(
            state.watermark_level in [WatermarkLevel.DEGRADE, WatermarkLevel.REJECT]
            for state in self.watermark_checker.stream_states.values()
        )

        now = time.time()

        if in_backpressure:
            if self.sustained_start_time is None:
                self.sustained_start_time = now
            else:
                duration_s = now - self.sustained_start_time
                if duration_s >= self.config.sustained_threshold_sec:
                    # Sustained backpressure detected
                    self.emit_sustained_alert(duration_s=duration_s)
                    self.metrics.backpressure_sustained_duration_seconds.set(duration_s)
        else:
            # Backpressure cleared
            if self.sustained_start_time is not None:
                duration_s = now - self.sustained_start_time
                self.emit_recovery("backpressure cleared", duration_s=duration_s)
                self.sustained_start_time = None
                self.metrics.backpressure_sustained_duration_seconds.set(0)

    async def shed_background_work(self):
        """Shed all BACKGROUND priority work globally"""

        # Drop BACKGROUND intents
        await self.intent_queue.drop_by_priority(priority=3)

        # Shed ephemeral tools
        await self.tool_executor.shed_ephemeral()

        # Drop oldest audio frames
        await self.audio_buffer.drop_n_oldest(n=20)

        # Disconnect slowest SSE clients
        await self.sse_manager.disconnect_slowest(n=5)

        logger.critical("shed_background_work", reason="OOM_IMMINENT")

    async def apply_cascading_degradation(self):
        """4-stage cascading degradation under extreme load"""

        # Stage 1: Drop BACKGROUND
        await self.intent_queue.drop_by_priority(priority=3)

        # Stage 2: Drop INTERACTIVE (non-user-facing)
        await self.intent_queue.drop_by_priority(priority=2)

        # Stage 3: Throttle REALTIME (rate limit)
        await self.router.set_rate_limit(priority=1, rate=10)  # 10 msg/s

        # Stage 4: Emergency mode (CRITICAL only)
        await self.router.set_admission_policy("CRITICAL_ONLY")

        logger.critical("cascading_degradation", stage=4, reason="CASCADE_FAILURE_RISK")
```

## Alternatives Considered

### **Alternative 1: No Backpressure (Accept Until Crash)**

**Description:**
- No backpressure checks, accept all requests
- Continue until OOM crash or hang
- Rely on OS to kill process (OOM killer)

**Pros:**
- ✅ Zero overhead (no checks)
- ✅ Maximum throughput (no artificial limits)
- ✅ Simple implementation

**Cons:**
- ❌ **Catastrophic failure**: 99% → 0% availability cliff
- ❌ **No graceful degradation**: Users see error/hang, no partial response
- ❌ **No observability**: No warning before crash
- ❌ **Poor UX**: Binary failure mode

**Rejection Reason:** Unacceptable for production system. OOM crashes violate 99.9% uptime target. Users deserve graceful degradation over binary failure.

---

### **Alternative 2: Simple Rate Limiting (Fixed Req/Sec)**

**Description:**
- Global rate limit: 100 req/sec
- Binary decision: accept (under limit) or reject (over limit)
- No progressive degradation, no priority support

**Example:**
```python
class SimpleRateLimiter:
    def __init__(self, rate_limit_rps: int):
        self.rate_limit = rate_limit_rps
        self.token_bucket = TokenBucket(rate=rate_limit_rps, burst=rate_limit_rps * 1.5)

    async def check(self, request) -> bool:
        if self.token_bucket.consume(1):
            return True  # Accept
        else:
            return False  # Reject with 503
```

**Pros:**
- ✅ Simple implementation (token bucket)
- ✅ Low overhead (<1ms per request)
- ✅ Prevents unbounded growth

**Cons:**
- ❌ **No progressive degradation**: Binary accept/reject
- ❌ **No priority support**: Critical operations rejected same as background
- ❌ **No voice-specific handling**: Audio pipeline invisible
- ❌ **Fixed limit**: Doesn't adapt to system capacity

**Rejection Reason:** Too coarse-grained. K1 needs progressive degradation (warn → degrade → reject) and priority support (RED band bypass).

---

### **Alternative 3: Circuit Breakers (Binary On/Off)**

**Description:**
- Circuit breaker per operation (agent_hire, tool_call, model_inference)
- States: CLOSED (healthy) → OPEN (failing) → HALF_OPEN (testing recovery)
- Open circuit rejects all requests for cooldown period

**Example:**
```python
class CircuitBreaker:
    def __init__(self, failure_threshold: int, timeout_s: int):
        self.state = "CLOSED"
        self.failure_count = 0
        self.failure_threshold = failure_threshold
        self.timeout_s = timeout_s

    async def call(self, operation):
        if self.state == "OPEN":
            raise CircuitOpenError("circuit breaker open")

        try:
            result = await operation()
            self.on_success()
            return result
        except Exception as e:
            self.on_failure()
            raise
```

**Pros:**
- ✅ Industry proven (Netflix Hystrix, Resilience4j)
- ✅ Prevents cascade failures
- ✅ Auto-recovery after cooldown

**Cons:**
- ❌ **Binary on/off**: No progressive degradation
- ❌ **No per-stream watermarks**: Operates at operation level, not queue level
- ❌ **No voice-specific handling**: Generic circuit breaker doesn't understand audio pipeline
- ❌ **All-or-nothing**: Open circuit blocks all requests, no priority support

**Rejection Reason:** Circuit breakers excellent for distributed systems (microservices) but insufficient for K1's needs (per-stream watermarks, voice pipeline, progressive degradation).

---

### **Alternative 4: Token Bucket Rate Limiting**

**Description:**
- Per-sender token bucket (rate + burst)
- Tokens refill at fixed rate (e.g., 100 tokens/sec)
- Request consumes tokens, rejected if bucket empty

**Implementation:**
```python
class TokenBucket:
    def __init__(self, rate: float, burst: float):
        self.rate = rate        # tokens/second
        self.burst = burst      # max tokens
        self.tokens = burst
        self.last_refill = time.time()

    def consume(self, tokens: int) -> bool:
        # Refill tokens based on elapsed time
        now = time.time()
        elapsed = now - self.last_refill
        self.tokens = min(self.burst, self.tokens + elapsed * self.rate)
        self.last_refill = now

        # Try to consume
        if self.tokens >= tokens:
            self.tokens -= tokens
            return True
        else:
            return False
```

**Pros:**
- ✅ Smooth rate limiting (burst + sustained)
- ✅ Low overhead (<1ms per check)
- ✅ Industry standard (AWS, GCP, Azure)
- ✅ Prevents sender overload

**Cons:**
- ❌ **Binary accept/reject**: No progressive degradation
- ❌ **No queue-aware**: Doesn't monitor queue depths, just request rate
- ❌ **No voice-specific handling**: Generic rate limiter
- ❌ **No priority support**: All requests consume same tokens

**Rejection Reason:** Token bucket excellent for API gateways (external rate limiting) but insufficient for K1 internal backpressure (needs queue depth awareness, voice pipeline integration, progressive degradation).

---

### **Alternative 5: 3-Tier Backpressure Cascade — SELECTED**

**Description:**
- **Tier 1**: Per-stream watermark monitoring (80/90/95% thresholds)
- **Tier 2**: Voice pipeline overload handling (5 stages, 3 watermarks each)
- **Tier 3**: Global resource monitoring (total memory, total queue items, sustained alerts)
- Progressive degradation, priority support, voice-specific actions

**Pros:**
- ✅ **Progressive degradation**: Warn at 80%, degrade at 90%, reject at 95%
- ✅ **Voice-specific**: 5-stage voice pipeline with specialized actions
- ✅ **Observability**: Per-stream, per-stage, and global metrics
- ✅ **Priority support**: RED band operations bypass limits
- ✅ **Industry-proven patterns**: SEDA (reactive streams) + WebRTC (adaptive QoS) + Hystrix (circuit breakers)

**Cons:**
- ⚠️ **Complexity**: 3 tiers require careful configuration and tuning
- ⚠️ **Overhead**: <5ms backpressure checks per operation
- ⚠️ **Learning curve**: Operators must understand 3-tier cascade

**Selection Reason:** Best fit for K1 requirements. Only alternative providing progressive degradation, voice-specific handling, and priority support. Complexity justified by production-grade graceful degradation.

## Consequences

### **Positive Consequences**

**✅ Graceful Degradation (UX)**
- Progressive: 80% warn → 90% degrade → 95% reject
- Users see degraded service (lower quality TTS, slower responses) vs no service
- **Benefit**: Better UX than binary failure

**✅ Early Warning (Observability)**
- 80% watermark triggers alerts before critical failure
- Operators have 10-15s to respond before rejection starts
- **Benefit**: Proactive capacity planning

**✅ Priority Protection (Safety)**
- RED band operations bypass all limits
- Critical safety/privacy operations always succeed
- **Benefit**: Compliance with safety requirements

**✅ Voice-Specific Handling (Quality)**
- 5-stage voice pipeline with specialized actions
- Audio degradation (downsample, frame drops) vs generic queue management
- **Benefit**: Better voice quality under load

**✅ System Resilience (Reliability)**
- Prevents OOM crashes (global memory limit)
- Prevents cascade failures (global queue limit)
- **Benefit**: 99.9% uptime maintained under load

---

### **Negative Consequences**

**⚠️ Complexity**
- 3-tier cascade requires careful configuration
- **Mitigation**: Comprehensive documentation, Grafana dashboards, runbooks
- **Risk Level**: MEDIUM (requires operator training)

**⚠️ Overhead**
- <5ms backpressure checks per operation
- **Mitigation**: Optimized checks, batching, caching
- **Risk Level**: LOW (<1% of turn latency)

**⚠️ False Positives**
- Aggressive watermarks may reject valid requests
- **Mitigation**: Tuning watermarks based on production metrics
- **Risk Level**: MEDIUM (requires 2-4 weeks tuning)
