# k006.1 - Write-Path Salience (Social + Affect + Recency Formula)

**Status**: ACCEPTED | **Parent**: [k006 - Salience Scoring Architecture](k006-salience-scoring.md)

---

## Executive Summary

**M06 (Salience Scorer)** assigns **attention priority** to each episodic memory in the P02 write path. This module determines **HOW important** each event is for working memory, consolidation, and future retrieval.

**Key Design Points**:

1. **Weighted Formula**: `0.50 × social + 0.40 × affect + 0.10 × recency`
2. **No Novelty in P02**: Novelty detection deferred to P03 (read path, requires corpus comparison)
3. **Fast Computation**: <5ms P95 (pure computation, no I/O or ML inference)
4. **Three-Band Classification**: HIGH (≥0.7), MED (0.4-0.7), LOW (<0.4)
5. **Interpretable Reasons**: Structured explanations for why score was assigned

**Performance Budget**: <5ms P95 (no I/O), deterministic

---

## Context

### The Attention Problem

After P02 writes an event to long-term memory (`st_hipp_events`), downstream systems need to know:

1. **Working Memory (P06)**: Which events should stay "top of mind" for queries?
2. **Consolidation (P08)**: Which events should be prioritized for semantic integration?
3. **Retrieval (P03)**: Which events should surface first in search results?

**Salience scoring** solves this by ranking events from 0.0 (ignore) to 1.0 (critical).

### Why Not Just Recency?

**Problem**: Recent events are not always important.

**Example**:

- **Recent but low-salience**: "Checked email" (10 minutes ago, social=0.2, affect=0.1) → salience=0.15
- **Older but high-salience**: "Daughter's graduation" (1 hour ago, social=1.0, affect=0.9) → salience=0.86

Recency is **necessary** (recent events are more relevant) but **not sufficient** (must weigh social/emotional importance).

### Why Not Novelty in P02?

**Novelty detection** (how unexpected/unusual is this event?) requires:

1. Comparing against historical corpus ("Is this type of event rare?")
2. Semantic similarity search (e.g., "Never seen a memory like this")
3. Potentially ML inference (e.g., outlier detection)

**Performance implications**:

- Corpus comparison: 20-50ms (vector DB queries)
- Semantic similarity: 10-30ms (embedding + search)
- ML inference: 5-20ms (model prediction)

**Total**: 35-100ms (exceeds P02 write-path budget of 100ms total)

**Decision**: Defer novelty to **P03 (read path)** where it can be computed lazily during retrieval. P02 write path uses only **fast, deterministic components** (social, affect, recency).

### Performance Requirements

P02 write path budget: 100ms total, salience scoring gets <5ms:

- **Target**: <5ms P95 per event
- **No I/O**: Pure computation (no DB queries, no cache lookups, no network calls)
- **Deterministic**: Same inputs always produce same output (no ML randomness)

### Biological Inspiration: Attention Networks

In neuroscience, **salience networks** prioritize stimuli based on:

1. **Social Relevance**: Family, friends, high-status individuals (ventromedial prefrontal cortex)
2. **Emotional Intensity**: High arousal, strong valence (amygdala, anterior cingulate cortex)
3. **Recency**: Recent events remain active in working memory (dorsolateral prefrontal cortex)

Our SalienceScorer mimics this by:

- Weighing social importance (family > friends > solo)
- Incorporating affect intensity (high arousal + strong valence)
- Boosting recent events (1-hour decay curve)

**Research Foundation**: Corbetta & Shulman (2002) describe two attention systems:

- **Bottom-up (stimulus-driven)**: Affect, recency (captured here)
- **Top-down (goal-directed)**: Novelty, relevance (deferred to P03 read path)

## Decision

### Component Architecture

**Module Path**: `k0/modules/salience/salience_scorer.py`
**Contract**: `k0/contracts/modules/salience.score.v1.yaml`
**Pipeline Stage**: P02 Stage 15 (`stage_15_salience_score`)
**Latency Budget**: <5ms P95 (pure computation)

### Formula: Weighted Components

```python
salience_score = (
        0.50 × social_importance_score +
        0.40 × affect_intensity_score +
        0.10 × recency_score
)
```

**Weight Rationale**:

| Component | Weight | Justification |
|-----------|--------|---------------|
| **Social** | 0.50 | Dominant factor - humans prioritize social interactions (family > solo) |
| **Affect** | 0.40 | Strong signal - emotional events are memorable (Cahill & McGaugh, 1998) |
| **Recency** | 0.10 | Weak signal - recent events decay quickly (working memory has limited capacity) |

**Total**: 0.50 + 0.40 + 0.10 = 1.0 (normalized)

### Algorithm: Component Scoring

```python
async def compute_salience(
        social_context: str,
        affect_intensity: float,
        timestamp: datetime
) -> SalienceResult:
        """
        Compute salience score from social, affect, recency components.

        Performance: <5ms P95 (pure computation, no I/O)
        """
        # Step 1: Social importance score
        social_score = compute_social_importance(social_context)

        # Step 2: Affect intensity score (from M04 - Tier-0 Fast Affect)
        affect_score = affect_intensity  # Already normalized 0-1

        # Step 3: Recency score (time decay)
        recency_score = compute_recency_score(timestamp)

        # Step 4: Weighted sum
        salience_score = (
                0.50 * social_score +
                0.40 * affect_score +
                0.10 * recency_score
        )

        # Step 5: Classify into bands
        salience_band = classify_salience_band(salience_score)

        # Step 6: Generate interpretable reasons
        reasons = generate_salience_reasons(
                social_score, affect_score, recency_score, salience_band
        )

        return SalienceResult(
                salience_score=salience_score,
                salience_band=salience_band,
                salience_reasons=reasons,
                component_scores={
                        "social": social_score,
                        "affect": affect_score,
                        "recency": recency_score
                }
        )
```

### Component 1: Social Importance Scoring

**Social Context Types** (from envelope `social_context`):

| Social Context | Score | Example |
|----------------|-------|---------|
| `family` | 1.0 | "Dinner with spouse and kids" |
| `extended_family` | 0.7 | "Holiday with grandparents" |
| `friends` | 0.5 | "Coffee with college friend" |
| `acquaintance` | 0.3 | "Chat with neighbor" |
| `solo` | 0.2 | "Reading alone in journal" |

**Mapping**:

```python
SOCIAL_IMPORTANCE_MAP = {
        "family": 1.0,
        "extended_family": 0.7,
        "friends": 0.5,
        "acquaintance": 0.3,
        "solo": 0.2,
        "unknown": 0.4  # Default (between solo and friends)
}

def compute_social_importance(social_context: str) -> float:
        return SOCIAL_IMPORTANCE_MAP.get(social_context, 0.4)
```

**Justification**: Humans prioritize family > extended family > friends > solo (evolutionary psychology, kin selection theory).

### Component 2: Affect Intensity Scoring

**Input**: `affect_intensity` from M04 (Tier-0 Fast Affect), already normalized 0-1.

**Affect Intensity** (from k004.1):

| Arousal | Valence | Intensity | Example |
|---------|---------|-----------|---------|
| High | Positive | 1.0 | "Ecstatic at daughter's wedding" |
| High | Negative | 0.9 | "Terrified during car accident" |
| Medium | Positive/Negative | 0.6 | "Mildly annoyed by traffic" |
| Low | Neutral | 0.3 | "Calm walk in park" |

**No additional processing**: Use `affect_intensity` directly (already computed by M04).

### Component 3: Recency Scoring

**Recency Decay Curve** (time since event):

| Time Since Event | Recency Score | Justification |
|------------------|---------------|---------------|
| 0-1 hour | 1.0 | Still in working memory |
| 1-24 hours | 0.5 | Recent, but fading |
| 1-7 days | 0.2 | Recent past |
| 7+ days | 0.1 | Long-term memory (baseline) |

**Formula**:

```python
def compute_recency_score(timestamp: datetime) -> float:
        now = datetime.utcnow()
        delta_hours = (now - timestamp).total_seconds() / 3600.0

        if delta_hours <= 1.0:
                return 1.0
        elif delta_hours <= 24.0:
                return 0.5
        elif delta_hours <= 168.0:  # 7 days
                return 0.2
        else:
                return 0.1  # Baseline for older events
```

**Justification**: Working memory decay (Atkinson & Shiffrin, 1968 multi-store model). Recent events have higher activation, older events require retrieval.

### Salience Band Classification

**Three Bands** (for query optimization and working memory ranking):

| Band | Score Range | Meaning | Example Use Case |
|------|-------------|---------|------------------|
| `HIGH` | ≥0.7 | Critical, keep in working memory | "Show me recent important events" |
| `MED` | 0.4-0.7 | Moderate, consider for consolidation | "Events worth reviewing" |
| `LOW` | <0.4 | Low priority, background | "Routine events, archive" |

**Mapping**:

```python
def classify_salience_band(salience_score: float) -> str:
        if salience_score >= 0.7:
                return "HIGH"
        elif salience_score >= 0.4:
                return "MED"
        else:
                return "LOW"
```

**Use Cases**:

- **Working Memory (P06)**: Keep only HIGH-band events active (limit 50-100 items)
- **Consolidation (P08)**: Prioritize HIGH/MED events for semantic integration
- **Query Optimization**: "Show me only high-salience events from last week"

### Salience Reasons (Interpretability)

**Purpose**: Explain why a score was assigned (for debugging, user transparency, query refinement).

**Example Output**:

```json
{
    "salience_score": 0.86,
    "salience_band": "HIGH",
    "salience_reasons": [
        "Family event (social=1.0)",
        "High emotional intensity (affect=0.9)",
        "Recent event within 1 hour (recency=1.0)"
    ],
    "component_scores": {
        "social": 1.0,
        "affect": 0.9,
        "recency": 1.0
    }
}
```

**Generation Logic**:

```python
def generate_salience_reasons(
        social_score: float,
        affect_score: float,
        recency_score: float,
        salience_band: str
) -> list[str]:
        reasons = []

        # Social reason
        if social_score >= 0.7:
                reasons.append(f"High social importance (social={social_score:.1f})")
        elif social_score <= 0.3:
                reasons.append(f"Solo/low social context (social={social_score:.1f})")

        # Affect reason
        if affect_score >= 0.7:
                reasons.append(f"Strong emotional intensity (affect={affect_score:.1f})")
        elif affect_score <= 0.3:
                reasons.append(f"Low emotional intensity (affect={affect_score:.1f})")

        # Recency reason
        if recency_score >= 0.8:
                reasons.append(f"Very recent event (recency={recency_score:.1f})")
        elif recency_score <= 0.2:
                reasons.append(f"Older event (recency={recency_score:.1f})")

        # Band summary
        reasons.append(f"Overall salience: {salience_band}")

        return reasons
```

### Weight Sensitivity Analysis

**Question**: How sensitive are salience scores to weight changes?

**Test Cases** (family event, high affect, recent):
```python
# Baseline: 0.50 social + 0.40 affect + 0.10 recency
# Input: social=1.0, affect=0.9, recency=1.0

# Current weights
salience = 0.50*1.0 + 0.40*0.9 + 0.10*1.0 = 0.96  # HIGH band

# Alternative weights (more social emphasis)
salience = 0.60*1.0 + 0.30*0.9 + 0.10*1.0 = 0.97  # HIGH band (Δ +0.01)

# Alternative weights (more affect emphasis)
salience = 0.40*1.0 + 0.50*0.9 + 0.10*1.0 = 0.95  # HIGH band (Δ -0.01)

# Alternative weights (more recency emphasis)
salience = 0.45*1.0 + 0.35*0.9 + 0.20*1.0 = 0.97  # HIGH band (Δ +0.01)
```

**Observation**: ±0.10 weight shift causes ≤0.02 score change (2%). Bands (HIGH/MED/LOW) remain stable.

**Test Cases** (solo event, low affect, old):
```python
# Input: social=0.2, affect=0.3, recency=0.1

# Current weights
salience = 0.50*0.2 + 0.40*0.3 + 0.10*0.1 = 0.23  # LOW band

# Alternative weights (more social emphasis)
salience = 0.60*0.2 + 0.30*0.3 + 0.10*0.1 = 0.22  # LOW band (Δ -0.01)

# Alternative weights (more affect emphasis)
salience = 0.40*0.2 + 0.50*0.3 + 0.10*0.1 = 0.24  # LOW band (Δ +0.01)
```

**Observation**: Low-salience events remain LOW even with ±0.10 weight shifts. Formula is **robust**.

**Conclusion**: Current weights (0.50/0.40/0.10) are stable. Future A/B testing can explore ±0.05 shifts without major impact.

### Expected Salience Distribution (Validation)

**Hypothesis** (based on weights):
- **HIGH band (≥0.7)**: 15-25% of events
    - Family + high affect + recent (most memorable experiences)
- **MED band (0.4-0.7)**: 50-60% of events
    - Friends + moderate affect, or family + low affect
- **LOW band (<0.4)**: 20-30% of events
    - Solo + low affect + old (routine activities)

**Monitoring Query**:
```sql
SELECT
        salience_band,
        COUNT(*) AS event_count,
        ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (), 1) AS percentage
FROM st_hipp_events
WHERE tenant_id = ?
GROUP BY salience_band
ORDER BY salience_band DESC;
```

**Expected Output**:
```
salience_band | event_count | percentage
--------------|-------------|------------
HIGH          | 2000        | 20.0%
MED           | 5500        | 55.0%
LOW           | 2500        | 25.0%
```

**Alert Thresholds**:
- HIGH band <10% → **Too few important events** (weights may over-penalize)
- HIGH band >40% → **Too many important events** (weights may be too generous)
- LOW band >50% → **Most events low-priority** (user engagement issue?)

**Corrective Actions**:
1. **If HIGH <10%**: Consider lowering HIGH threshold from 0.7 → 0.65
2. **If HIGH >40%**: Consider raising HIGH threshold from 0.7 → 0.75
3. **If LOW >50%**: Investigate data quality (missing affect scores? solo events only?)

### Boundary Case Examples

**Case 1: Just Below HIGH Threshold** (0.69 vs 0.70)
```python
# Input: social=0.5 (friends), affect=0.8, recency=0.5 (12h ago)
salience = 0.50*0.5 + 0.40*0.8 + 0.10*0.5 = 0.62  # MED band

# If affect slightly higher (0.9 instead of 0.8)
salience = 0.50*0.5 + 0.40*0.9 + 0.10*0.5 = 0.66  # Still MED

# If social upgraded (family=1.0 instead of friends=0.5)
salience = 0.50*1.0 + 0.40*0.8 + 0.10*0.5 = 0.87  # HIGH (crosses threshold!)
```

**Observation**: Social context has largest impact on band transitions (weight=0.50). Upgrading friends→family shifts MED→HIGH.

**Case 2: Band Stability Under Recency Decay**
```python
# Day 1: Recent family high-affect event
# Input: social=1.0, affect=0.9, recency=1.0 (30 min ago)
salience_day1 = 0.50*1.0 + 0.40*0.9 + 0.10*1.0 = 0.96  # HIGH

# Day 2: Same event, now 1 day old (recency=0.5)
salience_day2 = 0.50*1.0 + 0.40*0.9 + 0.10*0.5 = 0.91  # Still HIGH

# Week 1: Same event, now 7 days old (recency=0.2)
salience_week1 = 0.50*1.0 + 0.40*0.9 + 0.10*0.2 = 0.88  # Still HIGH

# Week 2: Same event, now 14 days old (recency=0.1)
salience_week2 = 0.50*1.0 + 0.40*0.9 + 0.10*0.1 = 0.87  # Still HIGH
```

**Observation**: Recency decay is **gradual** (weight=0.10). High-importance events (family + high affect) stay HIGH for weeks.

**Case 3: Solo Event with High Affect** (low social, high emotion)
```python
# Input: social=0.2 (solo), affect=1.0 (intense), recency=1.0
salience = 0.50*0.2 + 0.40*1.0 + 0.10*1.0 = 0.60  # MED band

# Example: "Panic attack while alone" or "Ecstatic moment during solo hike"
```

**Observation**: Solo events **rarely reach HIGH band** (social=0.2 caps at 0.10 contribution). Even with perfect affect (1.0) + recency (1.0), max is 0.60 (MED). This is **intentional** - social context is weighted highest.

**Design Question**: Should solo high-affect events reach HIGH band?
- **Current**: No (social=0.5 weight dominates)
- **Alternative**: Lower social weight to 0.40, raise affect to 0.50 (would allow solo high-affect → HIGH)
- **Decision**: Keep current weights (social prioritization aligns with evolutionary psychology)

## Alternatives Considered

### Alternative 1: Include Novelty in P02 (Rejected)

**Approach**: Add novelty detection (0.25 weight) to formula in P02 write path.

**Formula**: `0.40 × social + 0.30 × affect + 0.20 × novelty + 0.10 × recency`

**Pros**:
- Captures "surprising" events (novel experiences are memorable)
- More complete salience model (novelty is a key attention signal)

**Cons**:
- ❌ **Latency**: Novelty detection requires corpus comparison (20-50ms) → exceeds 5ms budget
- ❌ **Complexity**: Requires vector DB for semantic similarity search
- ❌ **Cold start**: No historical corpus for new users (cannot compute novelty)

- ❌ **Inconsistency**: Novelty changes as corpus grows (same event gets different scores over time)

**Rejection Rationale**: P02 write path must be fast (<100ms total, <5ms for salience). Novelty detection is expensive (corpus queries, embeddings, ML). Defer to **P03 read path** where latency is acceptable. Reserve ML for **P03 read path** (learned re-ranking).

### Alternative 2: Affect-Only Scoring (Rejected)

**Approach**: Use only `affect_intensity` (ignore social, recency).

**Formula**: `salience_score = affect_intensity`

**Pros**:
- Simplest implementation (no additional logic)
- Fastest performance (<1ms, single field passthrough)

**Cons**:
- ❌ **Ignores social context**: Solo low-affect event gets same score as solo high-affect event (misses social dimension)
- ❌ **No recency boost**: 1-year-old high-affect event ranks equal to 1-hour-old high-affect event (working memory needs recency)

- ❌ **Poor working memory ranking**: Cannot distinguish "important now" from "important ever"

**Rejection Rationale**: Social context is a critical signal (family events > solo events). Recency is necessary for working memory prioritization (recent events decay faster).

### Alternative 3: ML-Based Salience Model (Rejected)

**Approach**: Train neural network to predict salience from features (social, affect, recency, metadata).

**Pros**:
- Could learn non-linear interactions (e.g., social × affect)
- Potentially more accurate (if trained on labeled data)

**Cons**:
- ❌ **Latency**: ML inference 5-20ms (exceeds budget, close to limit)
- ❌ **Training data**: No labeled salience dataset (would need user annotations)
- ❌ **Non-deterministic**: Model may produce inconsistent scores (different inference runs)
- ❌ **Opaqueness**: Cannot explain why score was assigned (no interpretability)
- ❌ **Drift**: Model may degrade over time without retraining

**Rejection Rationale**: We don't have labeled training data for salience. Deterministic formula is interpretable, debuggable, and sufficient for P02 write path. Reserve ML for **P03 read path** (learned re-ranking).

### Alternative 4: Chosen - Weighted Formula (Social + Affect + Recency)

**Approach**: Simple weighted sum of 3 fast, deterministic components.

**Formula**: `0.50 × social + 0.40 × affect + 0.10 × recency`

**Pros**:
- ✅ <5ms P95 performance (pure computation, no I/O)
- ✅ Deterministic (same inputs → same output)
- ✅ Interpretable (can explain scores with component breakdown)
- ✅ No cold-start problem (works for first event)

**Cons**:
- ⚠️ Weights are manually tuned (not learned from data)
- ⚠️ No novelty component (deferred to P03)

**Why Chosen**: Balances speed, interpretability, and correctness. Fast enough for P02 write path, good enough for working memory/consolidation prioritization.

## Consequences

### Positive Consequences

✅ **Fast Performance: <5ms P95**
- Pure computation (no I/O, no network, no DB queries)
- Deterministic (no ML randomness)

✅ **Interpretable: Component Breakdown**
- Users can see why event got HIGH/MED/LOW band
- Debugging: Can trace social=1.0, affect=0.9, recency=1.0 → salience=0.86

✅ **No Cold-Start Problem**
- Works for first event (no historical corpus needed)
- No training data requirements

✅ **Deterministic: Same Inputs → Same Output**
- Reproducible (same event at same time gets same score)
- Testable (unit tests can verify exact scores)

### Negative Consequences (with Mitigations)

⚠️ **Manual Weight Tuning: Not Data-Driven**
- **Issue**: Weights (0.50/0.40/0.10) are manually chosen, not learned from data
- **Mitigation**: Collect user feedback (implicit signals like query patterns, consolidation effectiveness) to validate weights
- **Future Work**: A/B test alternative weights (e.g., 0.60 social vs. 0.50 social)

⚠️ **No Novelty Component: Misses "Surprising" Events**
- **Issue**: Novel experiences (first time at location, unusual person) not captured
- **Mitigation**: Defer novelty to **P03 read path** (k006.2) where latency is acceptable
- **Example**: "First time meeting friend's spouse" gets scored same as "Routine dinner with spouse" (both family=1.0)

⚠️ **Recency Bias: Older High-Salience Events Decay**
- **Issue**: 1-week-old family high-affect event gets salience=0.86 → 0.72 (due to recency=0.2)
- **Mitigation**: Recency weight is low (0.10), so impact is small (-0.08 score drop)
- **Future Work**: Time-decay consolidation (move high-salience older events to semantic memory)

⚠️ **No User-Specific Calibration: Same Weights for All Users**
- **Issue**: User A may prioritize social (0.60) while User B prioritizes affect (0.50)
- **Mitigation**: Start with population-level weights, collect per-user feedback
- **Future Work**: k006.3 (attention networks) learns per-user weights

## Failure Modes & Mitigation

### 1. Salience Scoring Fails (Exception in Formula)

**Symptom**: P02 Stage 15 raises exception, blocks write pipeline

**Root Cause**: Division by zero, NULL pointer, invalid timestamp

**Detection**:
```python
try:
        salience_result = await salience_scorer.compute_salience(
                social_context=envelope.social_context,
                affect_intensity=envelope.affect_intensity,
                timestamp=envelope.timestamp
        )
except Exception as e:
        log.error(f"Salience scoring failed: {e}, using default")
        salience_result = SalienceResult(
                salience_score=0.5,  # Neutral default
                salience_band="MED",
                salience_reasons=["Scoring failed, using default"],
                component_scores={"social": 0.4, "affect": 0.5, "recency": 0.5}
        )
```

**Mitigation**:
- Graceful fallback to neutral score (0.5, MED band)
- Log error for investigation (but don't block write)
- Alert if failure rate >1% of events

### 2. All Events Score HIGH (Weights Too Generous)

**Symptom**: 80%+ events in HIGH band (expected: 20%)

**Root Cause**: Weights miscalibrated, or affect scores inflated

**Detection**:
```sql
SELECT
        100.0 * COUNT(*) FILTER (WHERE salience_band = 'HIGH') / COUNT(*) AS high_pct
FROM st_hipp_events
WHERE tenant_id = ? AND event_time_utc > (NOW() - INTERVAL '7 days');
```

**Mitigation**:
1. **Investigate affect scores**: Check if M04 is over-estimating affect_intensity
2. **Adjust HIGH threshold**: Raise from 0.7 → 0.75 or 0.8
3. **Tune weights**: Reduce social weight from 0.50 → 0.45 (shifts distribution down)

### 3. Clock Skew Causes Future Timestamps

**Symptom**: `recency_score` computes negative delta (future timestamp)

**Root Cause**: User device clock ahead of server, or manual event creation

**Detection**:
```python
delta_hours = (now - timestamp).total_seconds() / 3600.0
if delta_hours < 0:
        log.warning(f"Future timestamp: {timestamp}, delta_hours={delta_hours}")
```

**Mitigation**:
```python
# Clamp future timestamps to "now"
if delta_hours < 0:
        return 1.0  # Treat as maximally recent
```

### 4. Missing Social Context (NULL or Invalid)

**Symptom**: `compute_social_importance()` gets `None` or unrecognized value

**Root Cause**: Upstream module (ACL resolution) fails to set social_context

**Detection**:
```python
if social_context is None or social_context not in SOCIAL_IMPORTANCE_MAP:
        log.warning(f"Invalid social_context: {social_context}, using default")
```

**Mitigation**:
```python
SOCIAL_IMPORTANCE_MAP.get(social_context, 0.4)  # Default: between solo and friends
```

### 5. Salience Score Exceeds 1.0 (Formula Bug)

**Symptom**: `salience_score > 1.0` (impossible with normalized components)

**Root Cause**: Component score not normalized (affect_intensity > 1.0)

**Detection**:
```python
if salience_score > 1.0:
        log.error(f"Salience score out of range: {salience_score}, clamping to 1.0")
        salience_score = 1.0
```

**Mitigation**:
- Validate component scores at input (assert 0 ≤ affect_intensity ≤ 1)
- Clamp output to [0, 1] range as safety check
