# k009.1 - HippEvents Row Builder (st_hipp_events Assembly)

**Status**: ACCEPTED | **Parent**: [k009 - Pipeline Builders Architecture](k009-pipeline-builders.md)

---

## Executive Summary

**M13 (HippEvents Row Builder)** assembles the complete `st_hipp_events` row from all 12 enrichment modules (M01-M12, M15), performing JSON serialization, validation, and final mapping.

**Key Design Points**:
1. **60-70 Column Assembly**: Consolidate outputs from M01-M12 into unified row
2. **Pure Transformation**: No I/O, no syscalls (deterministic mapping)
3. **JSON Serialization**: Convert complex structures to TEXT columns
4. **Validation**: Ensure NOT NULL constraints satisfied
5. **CA3 Deferred**: Leave dedup/cluster columns NULL (populated by P03)

**Performance Budget**: <10ms P95 (pure assembly, no I/O)

---

## Context

### Row Assembly Problem

P02 produces **12 enrichment outputs** from independent modules:
- **M01 (DG)**: simhash_hex, minhash32
- **M02 (CA1)**: entities_json, kg_triples_json, embedding_id
- **M04 (Affect)**: affect_valence, affect_arousal, affect_band, dominant_emotions
- **M05 (Space)**: owner_id, co_owners, author_role, visible_to
- **M06 (Salience)**: salience_score, salience_reasons, salience_band
- **M07 (Social)**: num_participants, participant_roles_json, social_context
- **M08 (Temporal)**: event_time_utc, write_time_utc, local_date, day_of_week, circadian_slot (11 columns)
- **M09 (Device)**: device_kind, device_platform, client_version
- **M10 (Ingress)**: ingress_topic, activity_type, content_type
- **M11 (Retention)**: retention_policy_id, retention_bucket
- **M12 (Geo)**: geohash_6, location_name, geo_precision_external

**Challenge**: Map these outputs → 60-70 `st_hipp_events` columns.

### st_hipp_events Schema

**9 Column Groups** (65 total columns):

1. **Identity & Trace** (9): event_id, wal_pos, cognitive_trace_id, tenant_id, space_id, ...
2. **Integrity & Audit** (6): envelope_sha256, sig_alg, idem_key, ingested_at, ...
3. **Policy & Visibility** (10): policy_decision, policy_band, visible_to_json, owner_id, ...
4. **Actor & Device** (6): actor_id, device_id, device_kind, device_os, ...
5. **Temporal** (11): event_time_utc, write_time_utc, local_date, day_of_week, circadian_slot, ...
6. **Spatial & Place** (5): location_name, geohash_6, geo_precision_external, ...
7. **Social & Relationships** (7): num_participants, participant_roles_json, social_context, ...
8. **Hippocampus** (8): simhash_hex, minhash32, embedding_id, entities_json, kg_triples_json, ...
9. **Affect & Salience** (6): affect_valence, salience_score, salience_band, ...

**Deferred Columns** (CA3 outputs, populated by P03):
- is_near_duplicate (NULL in P02)
- episode_cluster_id (NULL in P02)
- cluster_confidence (NULL in P02)
- clustering_version (NULL in P02)

### JSON Serialization

**TEXT Columns Requiring JSON Encoding**:
- obligations_json: `[\"mask.location.precision\", \"retention.sensitive\"]`
- visible_to_json: `[\"person_dad\", \"person_mom\"]`
- co_owners_json: `[\"person_mom\"]`
- participants_json: `[\"person_dad\", \"person_mom\", \"person_sharvi\"]`
- participant_roles_json: `{\"person_dad\": \"OWNER\", \"person_mom\": \"SPOUSE\"}`
- entities_json: `[\"Olive_Garden_Market_St\", \"person_mom\"]`
- kg_triples_json: `[[\"person_dad\", \"had_dinner_with\", \"person_mom\"]]`
- salience_reasons_json: `[\"social_family\", \"positive_affect\"]`
- dominant_emotions_json: `[\"joy\", \"contentment\"]`

**JSON Encoding Rules**:
- Use `json.dumps()` for serialization (standard library, deterministic)
- No pretty-printing (compact JSON)
- Null values → `None` → JSON `null`

## Decision

### Algorithm

```python
async def build_hipp_events_row(
    envelope: Envelope,
    dg_output: DGPatternOutput,
    ca1_output: CA1SemanticOutput,
    affect_output: AffectOutput,
    space_output: SpaceOutput,
    salience_output: SalienceOutput,
    temporal_output: TemporalOutput,
    device_output: DeviceOutput,
    ingress_output: IngressOutput,
    retention_output: RetentionOutput,
    geo_output: GeoOutput,
    social_output: SocialOutput
) -> dict:
    \"\"\"
    Assemble complete st_hipp_events row from all module outputs.

    Performance: <10ms P95 (pure assembly, no I/O)
    \"\"\"
    # Step 1: Identity & Trace (from envelope)
    row = {
        \"event_id\": envelope.event_id,
        \"wal_pos\": envelope.wal_pos,
        \"cognitive_trace_id\": envelope.cognitive_trace_id,
        \"tenant_id\": envelope.tenant_id,
        \"space_id\": envelope.space_id,
        \"effective_space_id\": space_output.effective_space_id,
        \"topic\": envelope.topic,
        \"uow_id\": envelope.uow_id,
        \"schema_version\": \"1.0.0\"
    }

    # Step 2: Integrity & Audit (from envelope)
    row.update({
        \"envelope_sha256\": envelope.envelope_sha256,
        \"sig_alg\": envelope.sig_alg,
        \"sig_kid\": envelope.sig_kid,
        \"idem_key\": envelope.idem_key,
        \"ingested_at\": envelope.ingested_at,
        \"clock_skew_ms\": envelope.clock_skew_ms
    })

    # Step 3: Policy & Visibility (from envelope + M05)
    row.update({
        \"policy_decision\": envelope.policy_stamp.decision,  # Always 'ALLOW' in P02
        \"policy_band\": envelope.policy_stamp.band,
        \"policy_version\": envelope.policy_stamp.version,
        \"obligations_json\": json.dumps(envelope.policy_stamp.obligations),
        \"visible_to_json\": json.dumps(space_output.visible_to),
        \"visibility_scope\": space_output.visibility_scope,
        \"owner_id\": space_output.owner_id,
        \"co_owners_json\": json.dumps(space_output.co_owners),
        \"retention_policy_id\": retention_output.retention_policy_id,
        \"retention_bucket\": retention_output.retention_bucket
    })

    # Step 4: Actor & Device (from envelope + M09)
    row.update({
        \"actor_id\": envelope.actor_id,
        \"actor_role\": envelope.actor_role,
        \"device_id\": envelope.device_id,
        \"device_kind\": device_output.device_kind,
        \"device_os\": device_output.device_os,
        \"ingress_channel\": ingress_output.ingress_channel
    })

    # Step 5: Temporal (from M08 - 11 columns)
    row.update({
        \"event_time_utc\": temporal_output.event_time_utc,
        \"write_time_utc\": temporal_output.write_time_utc,
        \"write_lag_ms\": temporal_output.write_lag_ms,
        \"local_date\": temporal_output.local_date,
        \"local_time\": temporal_output.local_time,
        \"day_of_week\": temporal_output.day_of_week,
        \"is_weekend\": temporal_output.is_weekend,
        \"time_of_day_bucket\": temporal_output.time_of_day_bucket,
        \"circadian_slot\": temporal_output.circadian_slot,
        \"is_backdated\": temporal_output.is_backdated,
        \"created_at\": int(time.time())
    })

    # Step 6: Spatial & Place (from M12)
    row.update({
        \"location_name\": geo_output.location_name,
        \"location_type\": geo_output.location_type,
        \"geohash_6\": geo_output.geohash_6,
        \"geo_precision_external\": geo_output.geo_precision_external,
        \"geo_masking_reason\": geo_output.geo_masking_reason
    })

    # Step 7: Social & Relationships (from M07)
    row.update({
        \"participants_json\": json.dumps(envelope.body.participants),
        \"num_participants\": social_output.num_participants,
        \"has_partner_present\": social_output.has_partner_present,
        \"has_parent_present\": social_output.has_parent_present,
        \"is_solo_event\": social_output.is_solo_event,
        \"participant_roles_json\": json.dumps(social_output.participant_roles_json),
        \"social_context\": social_output.social_context,
        \"social_intimacy\": social_output.social_intimacy
    })

    # Step 8: Hippocampus (from M01, M02)
    row.update({
        \"simhash_hex\": dg_output.simhash_hex,
        \"minhash32\": dg_output.minhash32,
        \"embedding_id\": ca1_output.embedding_id,
        \"entities_json\": json.dumps(ca1_output.entities),
        \"kg_triples_json\": json.dumps(ca1_output.kg_triples),
        # CA3 outputs (deferred to P03)
        \"is_near_duplicate\": None,
        \"novelty_score\": None,
        \"episode_cluster_id\": None,
        \"cluster_confidence\": None,
        \"clustering_version\": None
    })

    # Step 9: Affect & Salience (from M04, M06)
    row.update({
        \"affect_valence\": affect_output.valence,
        \"affect_arousal\": affect_output.arousal,
        \"affect_band\": affect_output.affect_band,
        \"dominant_emotions_json\": json.dumps(affect_output.dominant_emotions),
        \"salience_score\": salience_output.salience_score,
        \"salience_reasons_json\": json.dumps(salience_output.salience_reasons),
        \"salience_band\": salience_output.salience_band
    })

    # Step 10: Validate required fields
    validate_required_fields(row)

    return row
```

### Validation

```python
def validate_required_fields(row: dict):
    \"\"\"
    Ensure all NOT NULL columns are present and non-null.

    Raises: ValueError if validation fails
    \"\"\"
    required_fields = [
        \"event_id\", \"wal_pos\", \"tenant_id\", \"space_id\",
        \"policy_decision\", \"policy_band\", \"owner_id\",
        \"retention_policy_id\", \"actor_id\", \"device_id\",
        \"event_time_utc\", \"write_time_utc\"
    ]

    for field in required_fields:
        if field not in row or row[field] is None:
            raise ValueError(f\"Missing required field: {field}\")

    # Validate value ranges
    if not (0.0 <= row[\"affect_valence\"] <= 1.0):
        raise ValueError(f\"affect_valence out of range: {row['affect_valence']}\")

    if not (0.0 <= row[\"salience_score\"] <= 1.0):
        raise ValueError(f\"salience_score out of range: {row['salience_score']}\")
```

## Alternatives Considered

### Alternative 1: Incremental Row Building (Rejected)

**Approach**: Each module appends fields to growing dict.

**Pros**: Simpler module interfaces

**Cons**:
- ❌ Coupling: Modules must know row structure
- ❌ No validation: No single point to check completeness
- ❌ Ordering issues: Module execution order affects final row

**Rejected**: Single builder ensures clean separation of concerns.

### Alternative 2: Direct Database Writes Per Module (Rejected)

**Approach**: Each module writes columns directly to DB.

**Pros**: No intermediate dict structure

**Cons**:
- ❌ No transactionality: Partial writes on failure
- ❌ Performance: 12 separate UPDATE statements
- ❌ No validation: Cannot validate complete row

**Rejected**: UnitOfWork requires single atomic write.

### Alternative 3: Schema-Driven Assembly (Rejected)

**Approach**: Define JSON schema, auto-generate builder from schema.

**Pros**: Less manual code

**Cons**:
- ❌ Complexity: Schema generation adds build steps
- ❌ Debugging: Generated code harder to trace
- ❌ Flexibility: Hard to add custom validation rules

**Rejected**: Explicit builder is clearer and easier to debug.

### Alternative 4: Chosen - Single Builder Module

**Pros**:
- ✅ Clean separation: Enrichment modules produce outputs, builder assembles
- ✅ Single validation point: Catch missing fields before DB write
- ✅ Easy testing: Deterministic mapping (no I/O)
- ✅ Fast: <10ms P95 (pure dict operations + JSON encoding)

**Cons**:
- ⚠️ Large function: 60-70 field mappings
- ⚠️ Maintenance: Schema changes require builder updates

**Why Chosen**: Simplicity, testability, single validation point.

---

## Consequences

### Positive

✅ **Clean Separation**: Enrichment modules independent of row structure
✅ **Single Validation Point**: Catch missing fields before DB write
✅ **Deterministic**: No I/O, pure transformation (easy testing)
✅ **Fast**: <10ms P95 (pure assembly)

### Negative (with Mitigations)

⚠️ **Large Dict Structure**: 60-70 keys per row
- **Mitigation**: Use dataclass or Pydantic model for type safety
- **Benefit**: Large dict is temporary (exists only during assembly)

⚠️ **Schema Evolution**: Adding columns requires builder updates
- **Mitigation**: Use automated tests to detect missing fields
- **Tooling**: Schema diff tool to verify builder matches st_hipp_events
