# k007.2 - Device Profiler (Multi-Device Family Support)

**Status**: ACCEPTED | **Parent**: [k007 - Context Enrichment Architecture](k007-context-enrichment.md)

---

## Executive Summary

**M09 (Device Profiler)** classifies device type and platform for multi-device family scenarios. This module enables device-specific retention policies, notification routing, and cross-device analytics.

**Key Design Points**:
1. **Device Kind Taxonomy**: phone/tablet/watch/web/api (5 categories)
2. **Platform Detection**: iOS/Android/web/unknown
3. **Input Method Tracking**: voice/text/photo/scan/import/api
4. **Client Version Parsing**: Semantic versioning (major.minor.patch)
5. **Pure String Parsing**: <2ms P95 (no I/O, no cache lookups)

**Performance Budget**: <2ms P95 (pure string parsing)

---

## Context

### Multi-Device Families

Modern families use multiple devices:
- **Dad**: iPhone (primary), MacBook (work), iPad (evening)
- **Mom**: Android phone (primary), web browser (desktop)
- **Teen**: iPhone (primary), Apple Watch (fitness)
- **Household**: Smart display (shared), API (scheduled imports)

**Device context affects**:
- **Retention policy**: Watch events (fitness data) may have shorter retention than phone events
- **Notification routing**: Push to primary device, not all devices
- **Analytics**: "User switches to laptop for work tasks at 9am"
- **Quality scoring**: Voice input vs. text input (different error rates)

### Device Kind Classification

| Device Kind | Definition | Examples |
|-------------|------------|----------|
| `phone` | Mobile smartphone | iPhone 15, Pixel 8 |
| `tablet` | Tablet device | iPad Pro, Samsung Tab |
| `watch` | Wearable device | Apple Watch, Wear OS |
| `web` | Browser-based client | Chrome, Safari, Firefox |
| `api` | Server-to-server API | Scheduled import, connector |

**Use Cases**:
- **Retention lookup**: (band, topic, device_kind) → retention_policy_id
- **Notification routing**: Send push to phone (not watch)
- **Analytics**: "User logs 80% meals from phone, 20% from web"

### Platform Detection

| Platform | Identifier Pattern | Example User-Agent |
|----------|-------------------|--------------------|
| iOS | Contains "iOS" or "iPhone" or "iPad" | FamilyOS/2.3.1 (iOS 17.1; iPhone15,2) |
| Android | Contains "Android" | FamilyOS/2.3.1 (Android 14; Pixel 8) |
| web | Contains "Mozilla" or "Chrome" | Mozilla/5.0 ... FamilyOS/2.3.1 |
| unknown | No match | Custom client |

**Use Cases**:
- **Feature rollout**: "Enable feature X only on iOS 17+"
- **Bug tracking**: "Crash rate on Android 14"
- **Client version support**: "Warn users on iOS 15 (deprecated)"

### Input Method Tracking

| Input Method | Description | Example |
|--------------|-------------|---------||
| voice | Voice memo/transcription | "Hey family, we're having pasta tonight" |
| text | Manual text entry | User types "Had breakfast at 8am" |
| photo | Photo capture + caption | Photo of receipt with caption |
| scan | Document/receipt scanning | OCR scanned receipt |
| import | Bulk import from external | CSV import from Google Calendar |
| api | Programmatic API call | Scheduled sync from fitness tracker |

**Use Cases**:
- **Quality scoring**: Voice input has higher transcription error rate (quality score penalty)
- **Analytics**: "User prefers voice input in morning (hands-free)"
- **Retention**: Voice memos may have different retention than text entries

## Decision

### Algorithm

```python
async def profile_device_context(
    envelope: Envelope
) -> DeviceProfile:
    """
    Extract device and client metadata from envelope.

    Performance: <2ms P95 (pure string parsing, no I/O)
    """
    # Step 1: Extract user-agent and metadata
    user_agent = envelope.metadata.get("user_agent", "")
    client_version = envelope.metadata.get("client_version", "unknown")
    input_source = envelope.metadata.get("input_source", "text")

    # Step 2: Classify device kind
    device_kind = classify_device_kind(user_agent)

    # Step 3: Detect platform
    device_platform = detect_platform(user_agent)

    # Step 4: Parse client version
    client_build = parse_client_build(client_version)

    # Step 5: Map input method
    input_method = map_input_method(input_source)

    return DeviceProfile(
        device_kind=device_kind,
        device_platform=device_platform,
        client_version=client_version,
        client_build=client_build,
        input_method=input_method
    )
```

### Device Kind Classification

```python
def classify_device_kind(user_agent: str) -> str:
    """
    Classify device kind from user-agent string.

    Pattern matching (case-insensitive):
    - watch: "Watch" or "Wearable"
    - tablet: "iPad" or "Tablet"
    - phone: "iPhone" or "Android" (without "Tablet")
    - web: "Mozilla" or "Chrome" or "Safari" (without mobile keywords)
    - api: Empty user-agent or "API" or "Connector"
    """
    ua_lower = user_agent.lower()

    # API clients (no user-agent or explicit API marker)
    if not user_agent or "api" in ua_lower or "connector" in ua_lower:
        return "api"

    # Wearables
    if "watch" in ua_lower or "wearable" in ua_lower:
        return "watch"

    # Tablets (check before phones, since some tablets include "mobile")
    if "ipad" in ua_lower or "tablet" in ua_lower:
        return "tablet"

    # Phones
    if "iphone" in ua_lower or ("android" in ua_lower and "tablet" not in ua_lower):
        return "phone"

    # Web browsers
    if "mozilla" in ua_lower or "chrome" in ua_lower or "safari" in ua_lower:
        return "web"

    # Default: Assume phone (most common)
    return "phone"
```

### Platform Detection

```python
def detect_platform(user_agent: str) -> str:
    """
    Detect platform from user-agent.

    Priority order:
    1. iOS: "iOS" or "iPhone" or "iPad" or "iPod"
    2. Android: "Android"
    3. Web: "Mozilla" or "Windows" or "Macintosh" or "Linux"
    4. Unknown: No match
    """
    ua_lower = user_agent.lower()

    # iOS devices
    if any(marker in ua_lower for marker in ["ios", "iphone", "ipad", "ipod"]):
        return "iOS"

    # Android devices
    if "android" in ua_lower:
        return "Android"

    # Web browsers
    if any(marker in ua_lower for marker in ["mozilla", "windows", "macintosh", "linux", "chrome"]):
        return "web"

    return "unknown"
```

### Input Method Mapping

```python
def map_input_method(input_source: str) -> str:
    """
    Map input source to standardized method.

    Valid values: voice, text, photo, scan, import, api
    Default: text
    """
    input_lower = input_source.lower()

    # Voice input
    if "voice" in input_lower or "audio" in input_lower or "transcription" in input_lower:
        return "voice"

    # Photo input
    if "photo" in input_lower or "image" in input_lower or "camera" in input_lower:
        return "photo"

    # Scan input
    if "scan" in input_lower or "ocr" in input_lower:
        return "scan"

    # Import input
    if "import" in input_lower or "bulk" in input_lower or "sync" in input_lower:
        return "import"

    # API input
    if "api" in input_lower or "connector" in input_lower or "scheduled" in input_lower:
        return "api"

    # Default: text
    return "text"
```

## Alternatives Considered

### Alternative 1: No Device Tracking (Rejected)

**Approach**: Store no device metadata, treat all events as device-agnostic.

**Pros**: Simplest implementation

**Cons**:
- ❌ Cannot apply device-specific retention policies
- ❌ Loses multi-device analytics (device switching patterns)
- ❌ Cannot route notifications to primary device

**Rejected**: Device context essential for multi-device families.

### Alternative 2: Query st_devices Table Every Event (Rejected)

**Approach**: JOIN st_devices on every event write.

**Pros**: Always fresh device metadata

**Cons**:
- ❌ Latency: 5-10ms per event (DB query overhead)
- ❌ Database load: 10K events/day × queries
- ❌ Unnecessary: Device metadata rarely changes

**Rejected**: User-agent string parsing is faster (<2ms vs. 5-10ms).

### Alternative 3: External Device Fingerprinting Service (Rejected)

**Approach**: Call external API (e.g., DeviceAtlas, WURFL) for device detection.

**Pros**: More accurate device detection (detailed specs)

**Cons**:
- ❌ Latency: 50-100ms per API call
- ❌ Cost: External API fees
- ❌ Privacy: Sends user-agent to third party
- ❌ Overkill: Don't need detailed specs (just kind + platform)

**Rejected**: Simple regex matching sufficient for our needs.

### Alternative 4: Chosen - User-Agent Parsing

**Pros**:
- ✅ <2ms P95 (pure string parsing)
- ✅ No external dependencies
- ✅ Privacy-preserving (no external calls)
- ✅ Good enough accuracy (5 categories sufficient)

**Cons**:
- ⚠️ Less detailed than external services
- ⚠️ May misclassify custom clients

**Why Chosen**: Fast, simple, good enough for retention policy + analytics.

## Consequences

### Positive

✅ **Fast Parsing**: <2ms P95 (no I/O)
✅ **Multi-Device Support**: Enables device-specific policies
✅ **Input Method Tracking**: Voice vs. text analytics
✅ **Privacy-Preserving**: No external API calls

### Negative (with Mitigations)

⚠️ **Pattern Matching Fragility**: Custom clients may not match patterns
- **Mitigation**: Default to "phone" (most common), log unknown patterns
- **Monitoring**: Track device_kind distribution (alert if >20% "phone" default)

⚠️ **User-Agent Spoofing**: Clients can lie about device type
- **Mitigation**: Accept spoofing (not security-critical, only for analytics)
- **Note**: Retention policy uses band (security) + device_kind (hint)

⚠️ **No Device Registry Sync**: Device metadata not updated on profile changes
- **Mitigation**: Acceptable (device kind rarely changes, client version parsed fresh)
- **Future**: Consider st_devices cache if needed (currently overkill)

## Testing Strategy

```python
def test_device_kind_classification():
    test_cases = [
        ("FamilyOS/2.3.1 (iOS 17.1; iPhone15,2)", "phone"),
        ("FamilyOS/2.3.1 (iOS 17.1; iPad13,1)", "tablet"),
        ("FamilyOS/2.3.1 (watchOS 10.0; Watch6,1)", "watch"),
        ("Mozilla/5.0 ... FamilyOS/2.3.1", "web"),
        ("", "api"),  # Empty user-agent
    ]
    for user_agent, expected in test_cases:
        assert classify_device_kind(user_agent) == expected

def test_platform_detection():
    assert detect_platform("iPhone") == "iOS"
    assert detect_platform("Android 14") == "Android"
    assert detect_platform("Mozilla/5.0") == "web"
    assert detect_platform("CustomClient") == "unknown"

def test_input_method_mapping():
    assert map_input_method("voice_memo") == "voice"
    assert map_input_method("photo_capture") == "photo"
    assert map_input_method("manual_entry") == "text"
```
