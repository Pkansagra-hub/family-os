# k005.1 - ACL Resolution (Visibility Intersection & Space Ownership)

**Status**: ACCEPTED | **Parent**: [k005 - Space Resolver Architecture](k005-space-resolver.md)

---

## Executive Summary

**M05 (Space Resolution Module)** resolves **access control lists (ACLs)** and **space ownership** in the P02 write path. This module determines **WHO can see** each episodic memory by computing `visible_to` lists through intersection of envelope policy and space rules.

**Key Design Points**:

1. **Visibility Intersection**: Never expands visibility beyond policy-allowed viewers (security guarantee)
2. **Space Ownership Resolution**: Identifies `owner_id` and `co_owners` for each space
3. **Author Role Determination**: Resolves whether author is OWNER, CO_OWNER, or GUEST in space
4. **Cache-First Performance**: <3ms P95 via space metadata caching
5. **Fail-Secure Defaults**: Defaults to author-only visibility on lookup failures

**Performance Budget**: <3ms P95 (cache hit), <10ms P99 (cold cache)

---

## Context

### The Access Control Problem

After P02 receives a WAL-committed envelope, it must determine:

1. **Who owns this space?** (`owner_id`)
2. **Who are co-owners?** (`co_owners` list)
3. **What is the author's role?** (OWNER, CO_OWNER, GUEST)
4. **Who can see this event?** (`visible_to` list - final ACL)

Unlike policy enforcement (already done by PEP in Command Port), space resolution operates on **space-specific rules**:

- Home space: owner=dad, co_owners=[mom] → family events visible to both
- Private journal: owner=teen, co_owners=[] → teen-only visibility
- Shared calendar: owner=mom, co_owners=[dad, teen] → household visibility

### Security Requirement: Never Expand Visibility

**Critical Guarantee**: `actual_visibility ⊆ policy_allowed_visibility`

**Example**:
- Envelope `policy_stamp.visible_to = ["person_dad", "person_mom", "person_teen"]` (policy says these 3 can see it)
- Space rules: home space allows `["person_dad", "person_mom"]` (no teen access to this space)
- **Result**: `visible_to = ["person_dad", "person_mom"]` (intersection, security preserved)

**Why This Matters**:
- PEP (Command Port) already enforced global policy (band-based rules, consent, data minimization)
- Space resolution adds **space-specific constraints** (e.g., "teen's private journal" excludes parents)
- We NEVER override policy decisions; we can only **narrow** visibility further

### Performance Requirements

Unlike write-hot-path latency (P02 background with 100ms budget), space resolution must be fast:

- **Target**: <3ms P95 per event
- **Cache hit ratio**: >95% (space metadata changes infrequently)
- **Cold cache penalty**: <10ms P99 (rare, acceptable)

### Biological Inspiration: Prefrontal Context

In neuroscience, the **prefrontal cortex** provides contextual framing:

- **What situation am I in?** (space identification)
- **What role do I play here?** (author role: owner, guest, etc.)
- **Who else is appropriate in this context?** (visibility rules)

Our SpaceResolver mimics this by:

- Looking up space metadata (contextual framing)
- Determining author's relationship to space (role awareness)
- Applying space-specific visibility rules (social appropriateness)

## Decision

### Component Architecture

**Module Path**: `k0/modules/space/space_resolver.py`
**Contract**: `k0/contracts/modules/space.resolve_visibility.v1.yaml`
**Pipeline Stage**: P02 Stage 30 (`stage_30_space_resolve`)
**Latency Budget**: <3ms P95 (cache hit), <10ms P99 (cold cache)

### Algorithm: Visibility Intersection

```python
async def resolve_visibility(
    actor_id: str,
    space_id: str,
    policy_visible_to: list[str]
) -> SpaceResolution:
    """
    Compute visibility intersection and space ownership.

    Security guarantee: actual_visibility ⊆ policy_visible_to
    """
    # Step 1: Lookup space metadata (cached)
    space_meta = await cache.get_space_metadata(space_id)
    if not space_meta:
        # Fail-secure: Default to author-only visibility
        return SpaceResolution(
            owner_id=actor_id,
            co_owners=[],
            author_role="OWNER",
            visible_to=[actor_id],
            visibility_scope="OWNER_ONLY"
        )

    # Step 2: Determine author role
    is_owner = (actor_id == space_meta.owner_id)
    is_co_owner = (actor_id in space_meta.co_owners)
    author_role = (
        "OWNER" if is_owner
        else "CO_OWNER" if is_co_owner
        else "GUEST"
    )

    # Step 3: Get space's allowed viewers (default visibility)
    space_allowed_viewers = space_meta.default_visible_to  # e.g., [owner, co_owners]

    # Step 4: Compute intersection (NEVER expand beyond policy)
    visible_to = list(set(policy_visible_to) & set(space_allowed_viewers))

    # Step 5: Classify visibility scope pattern
    visibility_scope = classify_visibility_scope(
        visible_to, space_meta.owner_id, space_meta.co_owners
    )

    return SpaceResolution(
        owner_id=space_meta.owner_id,
        co_owners=space_meta.co_owners,
        author_role=author_role,
        visible_to=visible_to,
        visibility_scope=visibility_scope
    )
```

### Visibility Scope Classification

**Purpose**: High-level pattern for understanding visibility breadth (NOT used for ACL enforcement, just analytics)

| Scope | Definition | Example |
|-------|-----------|---------|
| `OWNER_ONLY` | Only space owner can see | Private journal (visible_to=[owner]) |
| `SPACE_DEFAULT` | Matches space's default policy | Home space (visible_to=[owner, co_owners]) |
| `HOUSEHOLD_ALL` | All household members | Shared calendar (visible_to=[all_family]) |
| `CUSTOM_SUBSET` | Arbitrary subset (neither owner-only nor full household) | Partial sharing (visible_to=[owner, friend1]) |
| `EXTERNAL_SHARE` | Includes external principals outside household | Public post (visible_to=[owner, external_person]) |

**Use Cases**:
- Query optimization (e.g., "show me only OWNER_ONLY events")
- Analytics (e.g., "what % of memories are private vs. shared?")
- NOT for ACL enforcement (use `visible_to` list directly)

### Space Metadata Cache

**Cache Structure**:
```python
@dataclass
class SpaceMetadata:
    space_id: str
    owner_id: str
    co_owners: list[str]
    default_visible_to: list[str]  # Default ACL for this space
    space_type: str  # "home", "journal", "work", etc.
    policy_version: str
    created_at: datetime
    updated_at: datetime
```

**Cache Key**: `space:{space_id}` (Redis or in-memory cache)
**TTL**: 5 minutes (300 seconds)
**Invalidation**: On space metadata updates (via `space.metadata.updated.v1` event)

**Cache Miss Handling**:
1. Query database (`SELECT * FROM spaces WHERE space_id = ?`)
2. Populate cache with TTL
3. If DB query fails → fail-secure to author-only visibility

### Output Schema

Fields written to `st_hipp_events`:

```sql
-- Space ownership
owner_id TEXT NOT NULL,
co_owners_json TEXT,  -- JSON array: ["person_mom", "person_dad"]

-- Author role in space
author_role TEXT NOT NULL CHECK(author_role IN ('OWNER', 'CO_OWNER', 'GUEST')),

-- Final visibility (ACL enforcement)
visible_to_json TEXT NOT NULL,  -- JSON array: ["person_dad", "person_mom"]

-- Visibility pattern (analytics only, NOT ACL)
visibility_scope TEXT CHECK(visibility_scope IN ('OWNER_ONLY', 'SPACE_DEFAULT', 'HOUSEHOLD_ALL', 'CUSTOM_SUBSET', 'EXTERNAL_SHARE'))
```

**Note**: `visible_to_json` is the **authoritative ACL** for queries. `visibility_scope` is a derived pattern for analytics/optimization.

## Alternatives Considered

### Alternative 1: No Space Resolution (Policy-Only Visibility) (Rejected)

**Approach**: Use only `policy_stamp.visible_to` from envelope, skip space-specific rules.

**Pros**:
- Simplest implementation (no space lookup)
- Fastest performance (no cache query)
- No cache invalidation complexity

**Cons**:
- ❌ **No space-specific privacy**: Can't have "private journal" separate from "home" space
- ❌ **No ownership tracking**: Don't know who "owns" each memory
- ❌ **No author role**: Can't determine if author is owner/guest (needed for future features like editing permissions)
- ❌ **Poor user experience**: Users expect space-based privacy (e.g., teen wants journal separate from parents)

**Rejection Rationale**: Spaces are a core UX requirement. Users need ability to separate "private journal" from "family calendar". Policy alone provides global rules (band-based); spaces provide **contextual privacy**.

### Alternative 2: Database Join Every Event (Rejected)

**Approach**: Query `spaces` table on every event write (no caching).

**Pros**:
- Always fresh data (no cache staleness)
- Simpler infrastructure (no cache layer)

**Cons**:
- ❌ **Latency**: 10-20ms per event for DB query (exceeds 3ms budget)
- ❌ **Database load**: 10K events/day × DB queries = unnecessary load
- ❌ **Scalability**: DB becomes bottleneck for high-throughput tenants

**Rejection Rationale**: Space metadata changes infrequently (user creates "home" space once, rarely updates). Caching with 5-minute TTL provides >95% hit ratio with <3ms latency.

### Alternative 3: Expand Visibility to All Space Members (Rejected)

**Approach**: Ignore `policy_stamp.visible_to`, use space's `default_visible_to` directly.

**Pros**:
- Simpler logic (no intersection)
- Potentially faster (skip set intersection)

**Cons**:
- ❌ **Security violation**: Overrides policy decisions (violates least privilege)
- ❌ **Band leakage**: RED-band event could become visible beyond policy-allowed viewers
- ❌ **Audit failures**: Cannot prove visibility ≤ policy (compliance risk)

**Rejection Rationale**: **NEVER expand visibility beyond policy**. This is a security guarantee. If policy says only [dad, mom] can see, space resolution cannot add [teen]. We can only **narrow** visibility, never expand.

### Alternative 4: Chosen - Cache Lookup + Intersection

**Approach**: Cache space metadata, compute intersection of policy + space rules.

**Pros**:
- ✅ <3ms P95 performance (cache hit)
- ✅ Security guarantee: visibility ≤ policy
- ✅ Fresh enough (5-minute TTL acceptable for space metadata)
- ✅ Scalable (cache absorbs read load)

**Cons**:
- ⚠️ Cache invalidation complexity (need event-driven updates)
- ⚠️ Cold cache penalty (<10ms P99, rare)

**Why Chosen**: Balances performance, security, and UX. Cache provides speed, intersection provides security, fail-secure defaults provide safety.

## Consequences

### Positive Consequences

✅ **Security Guarantee: Visibility ≤ Policy**
- Space resolution never expands ACLs beyond policy-allowed viewers
- Audit trail: Can prove compliance with least-privilege principle

✅ **Fast Performance: <3ms P95 (Cache Hit)**
- Cache-first design keeps write path fast
- 95%+ cache hit ratio (space metadata changes infrequently)

✅ **Fail-Secure Defaults: Author-Only on Failure**
- If cache miss AND DB query fails → default to author-only visibility
- Privacy-preserving: Better to under-share than over-share

✅ **Role Awareness: Owner/Co-Owner/Guest**
- Enables future features (editing permissions, delegation, etc.)
- Supports social dynamics (e.g., guests cannot modify space rules)

### Negative Consequences (with Mitigations)

⚠️ **Cache Invalidation Complexity**
- **Issue**: Space metadata updates must invalidate cache entries
- **Mitigation**: Subscribe to `space.metadata.updated.v1` events, invalidate on receipt
- **Monitoring**: Track cache hit ratio (alert if <90%)

⚠️ **Cold Cache Penalty: <10ms P99**
- **Issue**: First access after cache expiry requires DB query (10-20ms)
- **Mitigation**: Acceptable for P99 (background pipeline, not hot path)
- **Optimization**: Pre-warm cache for active spaces during off-hours

⚠️ **Visibility Scope Classification May Diverge**
- **Issue**: `visibility_scope` pattern is derived (OWNER_ONLY, SPACE_DEFAULT, etc.), may not match intent
- **Mitigation**: Use `visible_to_json` for ACL enforcement, `visibility_scope` for analytics only
- **Validation**: Periodic audit to ensure scope classifications are accurate

⚠️ **No Hierarchical Spaces (Flat Model Only)**
- **Issue**: Cannot represent "workspace → household → family" hierarchy
- **Mitigation**: Deferred to k005.2 (Ownership Derivation) and future work
- **Current Scope**: Flat space model (one level, no inheritance)

### Performance Impact Analysis

**Latency Breakdown**:

| Operation | P50 | P95 | P99 | Notes |
|-----------|-----|-----|-----|-------|
| Cache hit | 0.5ms | 2ms | 3ms | Redis GET (in-memory) |
| Cache miss + DB query | 8ms | 12ms | 18ms | SQLite SELECT + cache populate |
| Intersection computation | 0.1ms | 0.2ms | 0.3ms | Set intersection (typically <10 items) |
| **Total (cache hit)** | **0.6ms** | **2.2ms** | **3.3ms** | ✅ Within 3ms budget |
| **Total (cache miss)** | **8.1ms** | **12.2ms** | **18.3ms** | ⚠️ P99 acceptable (rare) |

**Cache Hit Ratio**:
- Expected: >95% (space metadata changes ~1× per day per user)
- Monitoring threshold: Alert if <90%

**Security Validation**:
- Intersection ensures: `|visible_to| ≤ |policy_visible_to|`
- Unit test: Assert no visibility expansion in 1,000 test cases

## Testing Strategy

### Unit Tests

```python
def test_visibility_intersection():
    """Verify intersection never expands beyond policy."""
    policy_visible_to = ["person_dad", "person_mom", "person_teen"]
    space_allowed_viewers = ["person_dad", "person_mom"]  # Home space excludes teen

    result = await space_resolver.resolve_visibility(
        actor_id="person_dad",
        space_id="space_home",
        policy_visible_to=policy_visible_to
    )

    # Intersection: {dad, mom, teen} ∩ {dad, mom} = {dad, mom}
    assert set(result.visible_to) == {"person_dad", "person_mom"}
    assert len(result.visible_to) <= len(policy_visible_to)  # Never expand

def test_fail_secure_on_cache_miss():
    """Verify fail-secure defaults to author-only on lookup failure."""
    # Simulate cache miss + DB failure
    with mock.patch("cache.get_space_metadata", return_value=None):
        result = await space_resolver.resolve_visibility(
            actor_id="person_teen",
            space_id="space_unknown",
            policy_visible_to=["person_teen", "person_dad"]
        )

    # Should default to author-only (fail-secure)
    assert result.visible_to == ["person_teen"]
    assert result.visibility_scope == "OWNER_ONLY"

def test_author_role_resolution():
    """Verify author role is correctly determined."""
    space_meta = SpaceMetadata(
        space_id="space_home",
        owner_id="person_dad",
        co_owners=["person_mom"],
        default_visible_to=["person_dad", "person_mom"]
    )

    # Test owner
    result = await resolve_visibility("person_dad", "space_home", ["person_dad"])
    assert result.author_role == "OWNER"

    # Test co-owner
    result = await resolve_visibility("person_mom", "space_home", ["person_mom"])
    assert result.author_role == "CO_OWNER"

    # Test guest
    result = await resolve_visibility("person_teen", "space_home", ["person_teen"])
    assert result.author_role == "GUEST"
```
