# k007.1 - Temporal Profiler (11-Dimension Time Indexing)

**Status**: ACCEPTED | **Parent**: [k007 - Context Enrichment Architecture](k007-context-enrichment.md)

---

## Executive Summary

**M08 (Temporal Profiler)** precomputes **11 temporal dimensions** in the P02 write path to enable fast date-range queries, circadian analysis, and write-lag monitoring.

**Key Design Points**:
1. **11 Temporal Dimensions**: UTC, local date/time, day_of_week, is_weekend, time_of_day_bucket, circadian_slot, write_lag_ms, is_backdated, ingested_at
2. **Timezone Normalization**: Tenant-aware UTC → local conversion
3. **Circadian Bucketing**: breakfast/lunch/dinner/sleep windows
4. **Write Lag Detection**: Tracks event_time → write_time latency
5. **Query Optimization**: Precomputed indexes eliminate runtime conversions

**Performance Budget**: <4ms P95 (timezone lookup + date math)

---

## Context

### Temporal Query Problem

Users query memories by time: "yesterday's meals", "last weekend", "morning routines". Without precomputation, every query requires expensive UTC → local conversion (5-10ms per event × thousands). With precomputation, queries become indexed lookups (<50ms vs. 2-3 seconds).

### 11 Temporal Dimensions

| Dimension | Purpose | Example |
|-----------|---------|---------|
| event_time_utc | Canonical event time | 2025-11-16 15:30:00 UTC |
| write_time_utc | DB commit time | 2025-11-16 15:30:02 UTC |
| ingested_at | Envelope received | 2025-11-16 15:29:58 UTC |
| local_date | Tenant timezone date | 2025-11-16 |
| local_time | Tenant timezone time | 07:30:00 |
| day_of_week | ISO 8601 (0=Mon) | 5 (Saturday) |
| is_weekend | Sat/Sun flag | TRUE |
| time_of_day_bucket | morning/afternoon/evening/night | morning |
| circadian_slot | breakfast/lunch/dinner/sleep/unstructured | breakfast_window |
| write_lag_ms | write_time - event_time | 2000 (2 sec) |
| is_backdated | write_lag > 24 hours | FALSE |

### Circadian Rhythm

Humans have 24-hour cycles affecting mood, energy, memory consolidation:
- **breakfast_window** (06:00-09:00): Morning routines
- **lunch_window** (11:30-13:30): Midday meals
- **dinner_window** (17:30-20:30): Evening meals
- **sleep_window** (22:00-06:00): Sleep/consolidation

Use cases: Mood analysis ("negative affect in afternoon dip"), habit detection ("breakfast at 07:15 daily"), sleep hygiene ("no events during sleep_window").

### Write Lag Analysis

**Three timestamps**:
1. **ingested_at**: Envelope arrives at K0
2. **event_time_utc**: When event happened
3. **write_time_utc**: DB commit time

**Write lag** = write_time - event_time. Large write_lag indicates bulk import, not real-time capture. Backdating flag (>24 hours) affects retention policy.

## Decision

### Algorithm

```python
async def profile_temporal_context(
    event_time_utc: datetime,
    write_time_utc: datetime,
    ingested_at: datetime,
    tenant_id: str
) -> TemporalProfile:
    # Step 1: Tenant timezone lookup (cached)
    tenant_tz = await cache.get_tenant_timezone(tenant_id)
    if not tenant_tz:
        tenant_tz = "America/Los_Angeles"  # Default

    # Step 2: UTC → local conversion
    local_dt = event_time_utc.astimezone(pytz.timezone(tenant_tz))
    local_date = local_dt.date()
    local_time = local_dt.time()

    # Step 3: Day of week (ISO 8601)
    day_of_week = local_dt.weekday()
    is_weekend = (day_of_week >= 5)

    # Step 4: Time of day bucket
    hour = local_dt.hour
    time_of_day_bucket = classify_time_of_day(hour)

    # Step 5: Circadian slot
    circadian_slot = classify_circadian_slot(local_time)

    # Step 6: Write lag
    write_lag_ms = int((write_time_utc - event_time_utc).total_seconds() * 1000)
    is_backdated = (write_lag_ms > 24 * 3600 * 1000)

    return TemporalProfile(...)
```

### Time of Day Classification

```python
def classify_time_of_day(hour: int) -> str:
    if 6 <= hour < 12: return "morning"
    elif 12 <= hour < 17: return "afternoon"
    elif 17 <= hour < 22: return "evening"
    else: return "night"
```

### Circadian Slot Classification

```python
def classify_circadian_slot(local_time: time) -> str:
    hour, minute = local_time.hour, local_time.minute

    # breakfast_window: 06:00-09:00
    if (6 <= hour < 9) or (hour == 9 and minute == 0):
        return "breakfast_window"

    # lunch_window: 11:30-13:30
    if (hour == 11 and minute >= 30) or (12 <= hour < 13) or (hour == 13 and minute <= 30):
        return "lunch_window"

    # dinner_window: 17:30-20:30
    if (hour == 17 and minute >= 30) or (18 <= hour < 20) or (hour == 20 and minute <= 30):
        return "dinner_window"

    # sleep_window: 22:00-06:00
    if hour >= 22 or hour < 6:
        return "sleep_window"

    return "unstructured"
```

### Tenant Timezone Cache

**Cache key**: `tenant:{tenant_id}:config` → `{"timezone": "America/Los_Angeles"}`
**TTL**: 1 hour (3600 seconds)
**Fallback**: Cache miss → query st_tenants → default "America/Los_Angeles"

## Alternatives Considered

### Alternative 1: Compute on Query (Rejected)

**Approach**: Store only event_time_utc, compute local_date/day_of_week at query time.

**Pros**: Minimal storage (1 column vs. 11)

**Cons**:
- ❌ Query latency: 5-10ms per event × thousands
- ❌ CPU waste: Repeated conversions
- ❌ No indexing: Full table scans required

**Rejected**: Queries 100× more frequent than writes. Optimize for reads.

### Alternative 2: Application-Layer Conversion (Rejected)

**Approach**: DB stores only UTC, app converts during rendering.

**Pros**: Simpler DB schema

**Cons**:
- ❌ No SQL filtering: Cannot query "9am-5pm local time"
- ❌ Network overhead: Fetch all, filter in app
- ❌ No indexes: Cannot leverage B-tree

**Rejected**: DB-level filtering essential for performance.

### Alternative 3: Store Only Local Time (Rejected)

**Approach**: Store only local_date/local_time, discard UTC.

**Pros**: Simple queries

**Cons**:
- ❌ Multi-tenant issues: Cannot query across timezones
- ❌ DST ambiguity: Duplicate/missing hours
- ❌ No canonical time: Cannot sort globally

**Rejected**: UTC is canonical. Local time is derived view.

### Alternative 4: Chosen - Precompute All 11

**Pros**:
- ✅ <4ms P95 write overhead
- ✅ <50ms indexed queries
- ✅ No repeated computation
- ✅ Circadian analysis ready

**Cons**:
- ⚠️ Storage overhead (88 bytes/event, <1% total)
- ⚠️ Write-time complexity

**Why Chosen**: Query performance critical. 11 columns provide 100× speedup.

---

## Consequences

### Positive

✅ **Fast Queries**: <50ms for date ranges (indexed)
✅ **Circadian Analysis**: Precomputed slots for mood tracking
✅ **Write Lag Monitoring**: P02 performance tracking
✅ **Timezone-Aware**: local_date/local_time ready

### Negative (with Mitigations)

⚠️ **Storage Overhead**: 11 columns × 8 bytes = 88 bytes/event
- **Mitigation**: Acceptable (<1%, ~350MB for 4M events)

⚠️ **Cache Invalidation**: Tenant timezone changes
- **Mitigation**: Subscribe to tenant.config.updated events
- **Rare**: Users rarely change timezones (1×/year)

⚠️ **DST Edge Cases**: Spring forward/fall back
- **Mitigation**: pytz handles correctly, store UTC canonical
- **Testing**: Unit tests for March/November transitions

⚠️ **Slot Drift**: Dinner time changes
- **Mitigation**: Allow tenant-level slot overrides (future)

### Performance

| Operation | P50 | P95 | P99 |
|-----------|-----|-----|-----|
| Timezone lookup (cache) | 0.5ms | 1ms | 2ms |
| UTC → local | 0.3ms | 0.5ms | 1ms |
| Day of week | 0.1ms | 0.1ms | 0.2ms |
| Time of day | 0.1ms | 0.1ms | 0.2ms |
| Circadian slot | 0.2ms | 0.3ms | 0.5ms |
| Write lag | 0.1ms | 0.1ms | 0.2ms |
| **Total** | **1.3ms** | **2.1ms** | **4.1ms** |

**Storage**: 88 bytes/event × 4M = 352MB (<1% total storage)

## Testing Strategy

```python
def test_timezone_conversion():
    event_time_utc = datetime(2025, 11, 16, 15, 30, 0, tzinfo=pytz.UTC)
    result = await temporal_profiler.profile_temporal_context(
        event_time_utc, write_time_utc, ingested_at, "tenant_test"
    )
    assert result.local_time == time(7, 30, 0)  # Pacific UTC-8

def test_circadian_slot():
    test_cases = [
        (time(7, 30), "breakfast_window"),
        (time(12, 15), "lunch_window"),
        (time(18, 45), "dinner_window"),
        (time(23, 30), "sleep_window"),
        (time(10, 0), "unstructured"),
    ]
    for local_time, expected in test_cases:
        assert classify_circadian_slot(local_time) == expected

def test_backdating():
    event_time = datetime(2025, 11, 10, 12, 0, 0, tzinfo=pytz.UTC)
    write_time = datetime(2025, 11, 16, 12, 0, 0, tzinfo=pytz.UTC)  # 6 days
    result = await temporal_profiler.profile_temporal_context(...)
    assert result.is_backdated == True  # >24 hours
```
