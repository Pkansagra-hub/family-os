# k007.3 - Ingress Classifier (Channel & Activity Attribution)

**Status**: ACCEPTED | **Parent**: [k007 - Context Enrichment Architecture](k007-context-enrichment.md)

---

## Executive Summary

**M10 (Ingress Classifier)** categorizes episodic memory input type and activity context for provenance tracking, retention policy, and analytics.

**Key Design Points**:
1. **Ingress Topic Classification**: cognitive.memory.write/photo/voice/import
2. **Activity Type Detection**: meal/conversation/routine/milestone/social/work
3. **Content Type Categorization**: episodic/semantic/procedural
4. **Source Attribution**: mobile_app/web_app/api/connector
5. **Rule-Based Logic**: <3ms P95 (no ML, pure pattern matching)

**Performance Budget**: <3ms P95 (rule-based classification)

---

## Context

### Channel Attribution Problem

Episodic memories arrive from multiple channels:
- **k1.conversation**: User chat with AI ("Had pasta for dinner")
- **k1.journal**: Private journal entry ("Feeling anxious today")
- **k1.photo**: Photo upload with caption (receipt photo)
- **k1.voice**: Voice memo transcription ("Remind me to buy milk")
- **external.import**: Bulk CSV import from Google Calendar
- **api.connector**: Scheduled sync from fitness tracker

**Channel affects**:
- **Retention policy**: (band, topic, device_kind) → retention_policy_id
- **Analytics**: "User prefers journal for private thoughts, conversation for meal logging"
- **Provenance**: "This memory came from voice import, not manual entry"

### Activity Type Classification

| Activity Type | Definition | Examples |
|---------------|------------|----------|
| `meal` | Food-related events | "Breakfast at 8am", "Dinner with family" |
| `conversation` | Social interactions | "Chat with friend", "Family discussion" |
| `routine` | Daily activities | "Morning shower", "Bedtime routine" |
| `milestone` | Significant events | "Graduation", "First birthday", "Anniversary" |
| `social` | Group gatherings | "Party", "Family reunion", "Game night" |
| `work` | Professional activities | "Client meeting", "Project deadline" |
| `unknown` | Cannot classify | Default fallback |

**Use Cases**:
- **Retention policy**: Milestones may have longer retention than routines
- **Analytics**: "User logs 30% meals, 20% conversations, 10% milestones"
- **Query optimization**: "Show me social events last month"

### Content Type Categorization

**Three Memory Systems** (Schacter & Tulving, 1994):

1. **Episodic Memory**: Time-bound personal experiences ("What happened?")
   - Example: "Had dinner at Olive Garden on 2025-11-15 at 18:30"
   - **P02 focus**: 95% of P02 events are episodic

2. **Semantic Memory**: Facts and knowledge ("What do I know?")
   - Example: "Olive Garden is an Italian restaurant chain"
   - **P09 focus**: Semantic enrichment happens in P09 (connector ingestion)

3. **Procedural Memory**: How-to skills ("How do I do it?")
   - Example: "Recipe for making pasta"
   - **Rare in P02**: Few how-to memories captured in write path

**P02 Assumption**: Default to `episodic` (time-bound personal experiences). Semantic/procedural handled by P09.

## Decision

### Algorithm

```python
async def classify_ingress(
    envelope: Envelope
) -> IngressClassification:
    """
    Classify ingress channel, activity type, and content type.

    Performance: <3ms P95 (rule-based, no ML)
    """
    # Step 1: Extract ingress topic from envelope
    ingress_topic = envelope.topic  # e.g., "cognitive.memory.write.v1"

    # Step 2: Classify activity type from body.text keywords
    activity_type = classify_activity_type(envelope.body.text)

    # Step 3: Determine content type (default: episodic)
    content_type = determine_content_type(envelope.body)

    # Step 4: Infer ingress source
    ingress_source = infer_ingress_source(envelope.metadata)

    # Step 5: User-initiated flag
    is_user_initiated = not ("import" in ingress_topic or "api" in ingress_topic)

    return IngressClassification(
        ingress_topic=ingress_topic,
        activity_type=activity_type,
        content_type=content_type,
        ingress_source=ingress_source,
        is_user_initiated=is_user_initiated
    )
```

### Activity Type Classification

```python
def classify_activity_type(text: str) -> str:
    """
    Rule-based activity classification from keywords.

    Priority order:
    1. meal (highest specificity)
    2. milestone
    3. work
    4. social
    5. conversation
    6. routine
    7. unknown (default)
    """
    text_lower = text.lower()

    # Meal keywords
    meal_keywords = ["breakfast", "lunch", "dinner", "ate", "food", "meal", "snack", "restaurant"]
    if any(kw in text_lower for kw in meal_keywords):
        return "meal"

    # Milestone keywords
    milestone_keywords = ["birthday", "anniversary", "graduation", "wedding", "first time", "milestone"]
    if any(kw in text_lower for kw in milestone_keywords):
        return "milestone"

    # Work keywords
    work_keywords = ["meeting", "project", "deadline", "presentation", "client", "work"]
    if any(kw in text_lower for kw in work_keywords):
        return "work"

    # Social keywords
    social_keywords = ["party", "gathering", "reunion", "event", "celebration"]
    if any(kw in text_lower for kw in social_keywords):
        return "social"

    # Conversation keywords
    conversation_keywords = ["chat", "talked", "discussed", "conversation", "call"]
    if any(kw in text_lower for kw in conversation_keywords):
        return "conversation"

    # Routine keywords
    routine_keywords = ["shower", "brushed", "bedtime", "woke up", "commute", "routine"]
    if any(kw in text_lower for kw in routine_keywords):
        return "routine"

    # Default: unknown
    return "unknown"
```

### Content Type Determination

```python
def determine_content_type(body: dict) -> str:
    """
    Determine content type (episodic/semantic/procedural).

    P02 assumption: Default to episodic (time-bound personal experiences).
    Semantic/procedural handled by P09 (connector ingestion).
    """
    # Check for semantic markers
    if body.get("is_fact") or body.get("is_knowledge_base_entry"):
        return "semantic"

    # Check for procedural markers
    if body.get("is_recipe") or body.get("is_how_to"):
        return "procedural"

    # Default: episodic (time-bound personal experience)
    return "episodic"
```

### Ingress Source Inference

```python
def infer_ingress_source(metadata: dict) -> str:
    """
    Infer ingress source from metadata.

    Sources:
    - mobile_app: FamilyOS mobile client
    - web_app: FamilyOS web browser
    - api: Programmatic API call
    - connector: External data connector (Google Calendar, Fitbit, etc.)
    """
    user_agent = metadata.get("user_agent", "").lower()
    source_hint = metadata.get("source", "").lower()

    # Connector sources
    if "connector" in source_hint or "sync" in source_hint:
        return "connector"

    # API sources
    if "api" in source_hint or not user_agent:
        return "api"

    # Mobile app
    if "iphone" in user_agent or "android" in user_agent:
        return "mobile_app"

    # Web app
    if "mozilla" in user_agent or "chrome" in user_agent:
        return "web_app"

    # Default: mobile_app (most common)
    return "mobile_app"
```

## Alternatives Considered

### Alternative 1: No Ingress Classification (Rejected)

**Approach**: Store no ingress metadata, treat all events as generic.

**Pros**: Simplest implementation

**Cons**:
- ❌ Loses provenance (cannot track where memory came from)
- ❌ Cannot apply topic-specific retention policies
- ❌ No analytics on channel usage

**Rejected**: Provenance essential for debugging, analytics, retention.

### Alternative 2: ML-Based Activity Classification (Rejected)

**Approach**: Train classifier (e.g., BERT) to predict activity type from text.

**Pros**: Higher accuracy (potentially 80-90% vs. 70% for keywords)

**Cons**:
- ❌ Latency: 10-50ms (ML inference)
- ❌ Complexity: Model training, deployment, versioning
- ❌ Training data: Need labeled examples (expensive)

**Rejected**: Keyword matching good enough (70% accuracy acceptable). Defer ML to P09 if needed.

### Alternative 3: User-Specified Activity Type (Rejected)

**Approach**: Require users to select activity type (meal/conversation/etc.) on every entry.

**Pros**: Highest accuracy (user knows best)

**Cons**:
- ❌ UX friction: Extra step on every entry
- ❌ Inconsistent: Users forget or skip
- ❌ Not applicable: Bulk imports cannot provide activity type

**Rejected**: Prefer automatic classification (frictionless UX).

### Alternative 4: Chosen - Rule-Based Keywords

**Pros**:
- ✅ <3ms P95 (no ML overhead)
- ✅ Deterministic (same text → same classification)
- ✅ Interpretable (can explain why classified as "meal")
- ✅ Good enough (70% accuracy acceptable)

**Cons**:
- ⚠️ Lower accuracy than ML (keyword mismatches)
- ⚠️ Keyword list maintenance (add new keywords over time)

**Why Chosen**: Fast, simple, good enough for retention + analytics.

## Consequences

### Positive

✅ **Fast Classification**: <3ms P95 (no ML)
✅ **Provenance Tracking**: Know where memories came from
✅ **Retention Policy Support**: (band, topic, device) → policy
✅ **Analytics Ready**: Channel usage trends

### Negative (with Mitigations)

⚠️ **Keyword Matching Fragility**: "Dinner party" misclassified as "meal" (should be "social")
- **Mitigation**: Prioritize high-specificity keywords ("party" before "dinner")
- **Monitoring**: Track activity_type distribution (alert if >50% "unknown")

⚠️ **No Intent Understanding**: Cannot distinguish "I had lunch" (fact) vs. "I want lunch" (desire)
- **Mitigation**: Acceptable (P02 captures what happened, not intent)
- **Future**: P09 intent classification if needed

⚠️ **Keyword List Maintenance**: New activities require new keywords
- **Mitigation**: Periodic review of "unknown" events (add missing keywords)
- **Monitoring**: Log misclassified examples for keyword expansion

## Testing Strategy

```python
def test_activity_classification():
    test_cases = [
        ("Had breakfast at 8am", "meal"),
        ("Birthday party today", "milestone"),  # Not "social" (milestone priority)
        ("Client meeting at 3pm", "work"),
        ("Talked with friend", "conversation"),
        ("Morning shower", "routine"),
        ("Random note", "unknown"),
    ]
    for text, expected in test_cases:
        assert classify_activity_type(text) == expected

def test_content_type():
    assert determine_content_type({"is_fact": True}) == "semantic"
    assert determine_content_type({"is_recipe": True}) == "procedural"
    assert determine_content_type({}) == "episodic"  # Default

def test_ingress_source():
    assert infer_ingress_source({"user_agent": "iPhone"}) == "mobile_app"
    assert infer_ingress_source({"user_agent": "Mozilla"}) == "web_app"
    assert infer_ingress_source({"source": "connector"}) == "connector"
```
