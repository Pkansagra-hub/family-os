# k003.2: CA1 Semantic Bridge - Entity Extraction and Knowledge Graph

**Status**: ACCEPTED | **Parent**: [k003 - Hippocampus Architecture](k003-hippocampus-architecture.md)

---

## Executive Summary

This ADR specifies the **CA1 Semantic Bridge** module (M02), implementing lightweight entity extraction and knowledge graph triple generation for the P02 write path. Using **spaCy NER + template-based rules**, CA1 achieves <20ms P95 latency while queueing embedding jobs for P08 vector generation.

**Key Design Points**:

- **spaCy NER**: Lightweight local model (80% accuracy, 10ms latency)
- **Template-based KG**: Rule-based triple extraction (subject-predicate-object)
- **Embedding queueing**: Defer vector generation to P08 (200-500ms)
- **Privacy-preserving**: No external API calls, local-first processing

---

## Context

### The Semantic Projection Problem

FamilyOS episodic memory requires **semantic indexing** to enable retrieval via semantic cues (not just episodic replay). For example:

- Query: "When did we last see mom?" → Retrieve events with entity "person_mom"
- Query: "What restaurants have we been to?" → Retrieve events with place entities
- Query: "Who was at the birthday party?" → Retrieve participants from KG triples

**Biological Inspiration**:
The mammalian **CA1 region** projects hippocampal representations to neocortex for semantic consolidation:

- Bidirectional flow: episodic → semantic (consolidation), semantic → episodic (recall)
- Enables retrieval via semantic cues (not requiring exact episodic match)
- Supports generalization and abstraction over episodes

### Performance Requirements

**P02 Write Path Budget**:

```
Total: 100ms P95
├─ M01 DG: 15ms
├─ M02 CA1: 20ms (this ADR)
├─ Context modules: 35ms
├─ Row builder: 10ms
└─ UnitOfWork: 20ms
```

**CA1 Module Constraints**:

- **Latency**: ≤20ms P95, ≤35ms P99
- **Memory**: <50MB per operation (spaCy model loaded once)
- **Accuracy**: 80%+ entity extraction recall (vs 95% for LLM-based)
- **Privacy**: No external API calls (local-first mandate)

### Why Not Use LLM for Entity Extraction?

**LLM-based extraction (GPT-4) rejected** because:

1. **200-500ms latency** (OpenAI API call + network round-trip)
2. **$0.002 per event** (100K events = $200/year cost)
3. **Non-deterministic** (same input may produce different outputs)
4. **Privacy violation** (text sent to external API)

**Trade-off**: Accept 80% accuracy for 10× speed improvement and privacy preservation.

## Decision

Implement **M02 CA1 Semantic Bridge** with lightweight **spaCy NER + template-based KG** extraction:

### Component Architecture

**Module**: `k0/modules/hippocampus/ca1_bridge.py`
**Contract**: `k0/contracts/modules/hippocampus.semantic_project.v1.yaml`
**Pipeline Stage**: P02 Stage 11
**Event Bus**: Subscribes to `p02.dg.complete.v1`, emits `p02.ca1.complete.v1`

### Algorithm: Entity Extraction (spaCy NER)

**Purpose**: Extract named entities (people, places, organizations) from event text.

**Model**: spaCy `en_core_web_sm` (50 MB, optimized for speed)

**Input**:

```python
@dataclass
class CA1Input:
    text: str                  # Envelope body
    participants: list[str]    # ["person_mom", "person_dad"]
    place: str | None          # "Olive_Garden_Market_St"
    activity_type: str | None  # "MEAL"
```

**Process**:

1. **Load spaCy model** (once at service startup):

   ```python
   import spacy
   nlp = spacy.load("en_core_web_sm")
   ```

2. **Run NER tagging** (10ms for 500-word text):

   ```python
   doc = nlp(text)
   entities = [(ent.text, ent.label_, ent._.confidence) for ent in doc.ents]
   ```

3. **Filter entity types** (PERSON, ORG, GPE, DATE, TIME):

   ```python
   entities = [e for e in entities if e.label_ in {"PERSON", "ORG", "GPE", "DATE", "TIME"}]
   ```

4. **Resolve to canonical IDs**:

   ```python
   resolved = []
   for text, label, confidence in entities:
       if confidence < 0.6:
           continue  # Filter low-confidence entities
       if label == "PERSON":
           resolved.append(resolve_person(text))  # "mom" → "person_mom"
       elif label == "GPE":
           resolved.append(resolve_place(text))   # "Olive Garden" → "Olive_Garden_Market_St"
   ```

5. **Output JSON array**:

   ```python
   entities_json = json.dumps(resolved)  # ["person_mom", "Olive_Garden_Market_St"]
   ```

**Entity Resolution Rules**:

- **PERSON**: Match against family graph ("mom", "dad", "son1" → canonical IDs)
- **GPE (location)**: Match against place registry (fuzzy match with Levenshtein distance)
- **ORG**: Store as-is (no resolution in Phase 1)
- **DATE/TIME**: Parse into ISO 8601 format

### Algorithm: Knowledge Graph Triple Generation

**Purpose**: Extract subject-predicate-object triples for knowledge graph storage.

**Approach**: Template-based rules (not LLM-based)

**Input**: Entities + envelope context (participants, place, activity_type)

**Process**:

1. **Activity templates** (actor → activity → place):

   ```python
   if activity_type == "MEAL" and place:
       triples.append((actor, "had_meal_at", place))
   if activity_type == "SOCIAL_EVENT":
       triples.append((actor, "attended_event_at", place))
   ```

2. **Participant templates** (actor → with → participant):

   ```python
   for participant in participants:
       if participant != actor:
           triples.append((actor, "had_activity_with", participant))
   ```

3. **Location templates** (event → occurred_at → place):

   ```python
   if place:
       triples.append((event_id, "occurred_at", place))
   ```

4. **Confidence scoring** (rule-based, >0.6 threshold):

   ```python
   scored_triples = [(s, p, o, confidence_score(s, p, o)) for s, p, o in triples]
   filtered = [(s, p, o) for s, p, o, conf in scored_triples if conf > 0.6]
   ```

5. **Output JSON array**:

   ```python
   kg_triples_json = json.dumps(filtered)  # [["person_dad", "had_meal_with", "person_mom"]]
   ```

**Why Template-Based (Not LLM)?**

| Approach | Latency | Accuracy | Cost | Determinism |
|----------|---------|----------|------|-------------|
| LLM-based (GPT-4) | 200-500ms | 95% | $0.002/event | ❌ Non-deterministic |
| spaCy NER + templates | 20ms | 80% | $0 | ✅ Deterministic |
| Regex patterns | 5ms | 60% | $0 | ✅ Deterministic |

**Trade-off**: Accept 80% accuracy for 10× speed improvement. P08 embeddings will capture semantic nuances missed by templates.

### Algorithm: Embedding Job Queueing

**Purpose**: Defer vector generation to P08 pipeline (200-500ms GPU inference).

**Process**:

1. **Allocate UUID** for embedding_id:

   ```python
   import uuid
   embedding_id = str(uuid.uuid4())
   ```

2. **Prepare payload**:

   ```python
   payload = {
       "embedding_id": embedding_id,
       "event_id": event_id,
       "text": text,
       "entities": entities_json,
       "kg_triples": kg_triples_json,
       "wal_pos": wal_pos  # FK to st_wal for ordering
   }
   ```

3. **Insert into st_embedding_queue**:

   ```sql
   INSERT INTO st_embedding_queue (
       embedding_id, event_id, wal_pos, status, created_at
   ) VALUES (?, ?, ?, 'PENDING', ?)
   ```

4. **Store embedding_id in st_hipp_events**:

   ```sql
   UPDATE st_hipp_events SET embedding_id = ? WHERE event_id = ?
   ```

**P08 Pipeline** (separate ADR):

- Subscribes to `p02.ca1.complete.v1` event
- Claims PENDING jobs from st_embedding_queue
- Batches 16-32 events for GPU efficiency
- Generates 1536-dim vectors using sentence-transformers
- Updates status to READY and emits `embedding.ready.v1`

### Performance Budget Breakdown

```
Total CA1 Latency: 20ms P95
├─ Entity extraction (spaCy NER): 10ms
│  ├─ Tokenization: 2ms
│  ├─ NER tagging: 6ms
│  └─ Entity resolution: 2ms
├─ KG triple generation: 5ms
│  ├─ Template matching: 3ms
│  └─ Confidence scoring: 2ms
├─ Embedding job queue: 5ms
│  ├─ UUID allocation: 1ms
│  └─ st_embedding_queue insert: 4ms
└─ Total: 20ms (no buffer needed)
```

### Output Schema

**Storage**: `st_hipp_events` table (SQLite)

```sql
-- CA1 columns (written by M02)
embedding_id TEXT NOT NULL,          -- UUID for P08 vector generation
entities_json TEXT,                  -- ["person_mom", "Olive_Garden_Market_St"]
kg_triples_json TEXT,                -- [["person_dad", "had_meal_with", "person_mom"]]

-- P08 columns (NULL in P02, filled later)
embedding_status TEXT,               -- PENDING/IN_PROGRESS/READY/FAILED (NULL)
embedding_vector BLOB                -- 1536-dim float32 vector (NULL)
```

**Separate Table**: `st_embedding_queue` (for P08 job tracking)

```sql
CREATE TABLE st_embedding_queue (
    embedding_id TEXT PRIMARY KEY,
    event_id TEXT NOT NULL,          -- FK to st_hipp_events
    wal_pos INTEGER NOT NULL,        -- FK to st_wal
    status TEXT NOT NULL,            -- PENDING/IN_PROGRESS/READY/FAILED
    attempt_count INTEGER DEFAULT 0,
    created_at INTEGER NOT NULL,
    updated_at INTEGER
);
```

## Alternatives Considered

### Alternative 1: LLM-Based Entity Extraction (GPT-4)

**Approach**: Use OpenAI GPT-4 API for entity extraction and KG triple generation.

**Pros**:

- ✅ **95% accuracy** for entity resolution (vs 80% for spaCy)
- ✅ Handles ambiguous entities ("mom" vs "my mom" vs "mother")
- ✅ Generates rich KG triples with reasoning

**Cons**:

- ❌ **200-500ms latency** (OpenAI API call + network round-trip)
- ❌ **$0.002 per event** (100K events = $200/year cost)
- ❌ **Non-deterministic** (same input may produce different outputs)
- ❌ **Privacy violation** (text sent to external API)

**Why Rejected**: Write path latency budget (100ms P95) prohibits external API calls. FamilyOS privacy mandate requires local-first processing.

**Hybrid Approach (Future)**:
Use spaCy (80% accuracy, 20ms) for P02 fast path, then enrich with local LLM (Llama 3.1 8B) during P03 consolidation.

---

### Alternative 2: Regex-Based Entity Extraction

**Approach**: Use regex patterns for simple entity extraction ("mom", "dad", "Olive Garden").

**Pros**:

- ✅ Fastest (5ms latency)
- ✅ No ML model required (zero memory footprint)
- ✅ Deterministic (same input → same output)

**Cons**:

- ❌ **60% accuracy** (misses variations: "my mom", "mother", "mommy")
- ❌ No context awareness (cannot disambiguate "John" vs "John Smith")
- ❌ Fragile (requires manual pattern maintenance)

**Why Rejected**: 60% accuracy insufficient for knowledge graph quality. spaCy provides 80% accuracy with context awareness.

---

### Alternative 3: External NER Service (Stanford CoreNLP)

**Approach**: Deploy Stanford CoreNLP as external HTTP service for NER.

**Pros**:

- ✅ Higher accuracy than spaCy (85-90%)
- ✅ More entity types (LOCATION, ORGANIZATION, DATE, TIME, MONEY, PERCENT)

**Cons**:

- ❌ **40-60ms latency** (network call + Java service overhead)
- ❌ Violates 20ms P95 budget (2-3× slower)
- ❌ Operational complexity (additional service to deploy)
- ❌ Java dependency (memory footprint 500MB+)

**Why Rejected**: Latency budget violation. spaCy in-process (10ms) preferred over external service (40ms).

---

### Alternative 4: Immediate Embedding Generation (P02)

**Approach**: Generate 1536-dim embeddings in P02 (no queueing to P08).

**Pros**:

- ✅ Simpler architecture (no P08 pipeline)
- ✅ Embeddings available immediately

**Cons**:

- ❌ **200-500ms latency** (sentence-transformers inference)
- ❌ Violates 100ms P95 write budget (2-5× slower)
- ❌ GPU contention with K1 LLM inference
- ❌ No batching optimization (inefficient GPU utilization)

**Why Rejected**: Write path latency non-negotiable. Embedding generation must be deferred to background pipeline (P08).

## Consequences

### Positive Consequences

**✅ Fast Write Path (<20ms P95)**

- CA1 semantic extraction: 20ms measured (within budget)
- No external API calls (pure local processing)
- Deterministic performance (no network variance)

**✅ Privacy-Preserving**

- spaCy NER runs locally (no text sent to cloud)
- No external dependencies (meets FamilyOS local-first mandate)
- Entity resolution uses local family graph

**✅ Embedding Decoupling**

- P08 can batch multiple events (16-32 batch size)
- GPU scheduling optimized for throughput
- Retry logic isolated from write path
- Model swapping without touching P02

**✅ Knowledge Graph Foundation**

- Entities enable semantic queries ("find events with person_mom")
- KG triples enable relationship queries ("who did person_dad have dinner with?")
- Foundation for future reasoning and inference

### Negative Consequences

**⚠️ 80% NER Accuracy (vs 95% with GPT-4)**

- spaCy misses ambiguous entities ("mom" vs "my mom")
- Template-based KG triples miss subtle relationships
- **Mitigation**: P08 embeddings capture semantic nuances
- **Acceptable**: 15% accuracy loss justified by 10× speed improvement

**⚠️ Delayed Embeddings (1-5 Minute Delay)**

- Embeddings not available immediately after write
- Semantic queries blocked until P08 completes
- **Mitigation**: Most queries use entities (not embeddings)
- **Acceptable**: 95%+ queries satisfied by entity/KG indexing

**⚠️ Template Brittleness**

- KG templates require manual maintenance
- New activity types require new templates
- **Mitigation**: Log template misses, iteratively improve
- **Acceptable**: 80% coverage for Phase 1 activity types

### Performance Impact

**Write Path Latency**:

- P02 total: 93ms P95 (within 100ms budget)
- CA1 contribution: 20ms (21% of budget)
- Headroom: 7ms remaining

**Embedding Queue Backlog**:

- P08 throughput: 10-20 events/sec (GPU batching)
- P02 ingestion: 5-10 events/sec (typical)
- Backlog: None expected (P08 faster than P02)

## Testing Strategy

**Unit Tests**:

```python
def test_entity_extraction():
    """CA1 must extract entities from text."""
    ca1 = CA1Bridge()
    input = CA1Input(text="Had dinner with mom at Olive Garden")
    result = ca1.project_semantic(input)
    entities = json.loads(result.entities_json)
    assert "person_mom" in entities
    assert "Olive_Garden_Market_St" in entities

def test_kg_triple_generation():
    """CA1 must generate KG triples."""
    ca1 = CA1Bridge()
    input = CA1Input(
        text="Had dinner with mom",
        participants=["person_mom"],
        activity_type="MEAL"
    )
    result = ca1.project_semantic(input)
    triples = json.loads(result.kg_triples_json)
    assert ["person_dad", "had_meal_with", "person_mom"] in triples

def test_ca1_latency():
    """CA1 must complete in <20ms P95."""
    ca1 = CA1Bridge()
    input = CA1Input(text="Had dinner with mom" * 100)  # ~500 words
    latencies = [ca1.project_semantic(input).computation_ms for _ in range(100)]
    p95 = sorted(latencies)[95]
    assert p95 < 20  # ms
```

**Integration Tests**:

```python
async def test_p02_ca1_integration():
    """P02 pipeline must store CA1 outputs in st_hipp_events."""
    event_id = await p02_write_pipeline.execute({
        "text": "Had dinner with mom at Olive Garden",
        "participants": ["person_mom"]
    })
    row = await db.fetch_one(
        "SELECT embedding_id, entities_json, kg_triples_json FROM st_hipp_events WHERE event_id = ?",
        event_id
    )
    assert row.embedding_id is not None
    assert row.entities_json is not None
    assert row.kg_triples_json is not None

    # Verify embedding job queued
    job = await db.fetch_one(
        "SELECT * FROM st_embedding_queue WHERE embedding_id = ?",
        row.embedding_id
    )
    assert job.status == "PENDING"
```
