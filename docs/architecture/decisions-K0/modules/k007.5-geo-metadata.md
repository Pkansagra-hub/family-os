# k007.5 - Geo Metadata Lookup (Privacy-Preserving Location)

**Status**: ACCEPTED | **Parent**: [k007 - Context Enrichment Architecture](k007-context-enrichment.md)

---

## Executive Summary

**M12 (Geo Metadata Lookup)** stores privacy-masked geohash and location name from envelope. NO re-masking (reads pre-masked envelope), NO enrichment (defer to P09).

**Key Design Points**:
1. **Geohash Precision Tracking**: GREEN=full, AMBER=geohash-6 (~1.2km), RED=geohash-4 (~39km)
2. **NO Re-Masking**: Reads pre-masked envelope data (M05 already applied privacy band)
3. **NO Enrichment**: No reverse geocoding, no place lookup, no geofence (defer to P09)
4. **Passthrough Design**: Copy envelope fields → st_hipp_events
5. **Privacy Reason Tracking**: geo_masking_reason ("band_policy", "user_preference", "none")

**Performance Budget**: <2ms P95 (pure field copy, no external calls)

---

## Context

### Privacy-Aware Geolocation

Location data is highly sensitive (Gruteser & Grunwald, 2003):
- **Exact coordinates (lat/lon)**: Can identify home address (privacy violation)
- **Geohash-7 (~152m)**: Can identify building (still sensitive)
- **Geohash-6 (~1.2km)**: Neighborhood-level (acceptable for AMBER)
- **Geohash-4 (~39km)**: City-level (acceptable for RED)

**Privacy Band Mapping**:

| Band | Geohash Precision | Approximate Radius | Example |
|------|-------------------|--------------------|---------|
| GREEN | Full (geohash-9) | ~5m | Exact restaurant location |
| AMBER | geohash-6 | ~1.2km | "Near downtown" |
| RED | geohash-4 | ~39km | "San Francisco area" |

**Privacy-Preserving Design**:
- ✅ M05 (Geo Masker) already masked envelope.location.geohash based on band
- ✅ M12 reads pre-masked geohash (no re-masking)
- ✅ M12 stores geo_masking_reason (audit trail)

### NO Enrichment in P02

**P02 Scope**: Write path for episodic memory (fast, low-latency)

**Out of Scope** (defer to P09 - Geo Enrichment):
- ❌ Reverse geocoding (geohash → city name)
- ❌ Place lookup (geohash → "Starbucks")
- ❌ Geofence detection ("Home", "Work", "Gym")

**Why Defer to P09**:
1. **Latency**: Reverse geocoding adds 50-200ms (external API calls)
2. **Cost**: Place lookup requires paid APIs (Google Places, Mapbox)
3. **Batch Efficiency**: P09 enriches in batch (amortize API costs)

## Decision

### Algorithm

```python
async def lookup_geo_metadata(
    envelope: Envelope
) -> GeoMetadata:
    """
    Extract geo metadata from envelope (pre-masked).

    NO re-masking, NO enrichment.
    Performance: <2ms P95 (pure field copy)
    """
    location = envelope.location or {}

    # Step 1: Extract pre-masked geohash
    geohash_6 = location.get("geohash", "")[:6]  # Truncate to geohash-6 for storage

    # Step 2: Extract location name (user-provided or None)
    location_name = location.get("location_name")  # Optional
    location_type = location.get("location_type", "unknown")  # user_entered/api/import

    # Step 3: Extract geo precision metadata
    geo_precision_external = location.get("geo_precision", "unknown")  # gps/network/manual
    geo_masking_reason = location.get("geo_masking_reason", "none")  # band_policy/user_preference/none

    return GeoMetadata(
        geohash_6=geohash_6,
        location_name=location_name,
        location_type=location_type,
        geo_precision_external=geo_precision_external,
        geo_masking_reason=geo_masking_reason
    )
```

## Alternatives Considered

### Alternative 1: Re-Mask Geohash in M12 (Rejected)

**Approach**: M12 applies masking logic (band → precision), ignoring M05.

**Pros**: Single masking point (M12)

**Cons**:
- ❌ Duplicate logic: M05 already masks envelope.location.geohash
- ❌ Inconsistency risk: M05 and M12 masking diverge
- ❌ Extra work: Re-compute masking already done

**Rejected**: M05 (Geo Masker) is authoritative masking point. M12 reads pre-masked data.

### Alternative 2: Reverse Geocode in P02 (Rejected)

**Approach**: M12 calls external API to get city name from geohash.

**Pros**: Immediate city name for queries

**Cons**:
- ❌ Latency: 50-200ms per external API call
- ❌ Cost: $5-$10 per 1000 requests (expensive at scale)
- ❌ Privacy leak: Sends geohash to third party
- ❌ P02 scope: Write path must be fast (<20ms total)

**Rejected**: Defer reverse geocoding to P09 (batch enrichment).

### Alternative 3: No Geo Storage (Rejected)

**Approach**: Do not store geohash in st_hipp_events. Query envelope JSON when needed.

**Pros**: Simplest implementation

**Cons**:
- ❌ Query performance: Cannot index JSON fields efficiently
- ❌ Bounding box queries: "Show events near SF" requires full table scan

**Rejected**: Geohash index essential for geo queries.

### Alternative 4: Chosen - Passthrough Pre-Masked Geohash

**Pros**:
- ✅ <2ms P95 (pure field copy, no external calls)
- ✅ Privacy-preserving (reads pre-masked envelope)
- ✅ No duplicate logic (M05 is authoritative masking point)
- ✅ Geo queries ready (geohash_6 index)

**Cons**:
- ⚠️ No city name (defer to P09)
- ⚠️ No place enrichment (defer to P09)

**Why Chosen**: Fast, privacy-preserving, good enough for P02 write path.

---

## Consequences

### Positive

✅ **Fast Storage**: <2ms P95 (no external calls)
✅ **Privacy-Preserving**: Reads pre-masked envelope (M05 authority)
✅ **Geo Queries Ready**: geohash_6 index for bounding box
✅ **Audit Trail**: geo_masking_reason tracks why masked

### Negative (with Mitigations)

⚠️ **No City Name in P02**: st_hipp_events lacks human-readable location
- **Mitigation**: P09 (Geo Enrichment) adds city_name, place_name in batch
- **Benefit**: P02 write path stays fast (<20ms total)

⚠️ **Geohash-6 Storage**: May lose precision for GREEN band events
- **Mitigation**: Full geohash available in envelope JSON (can retrieve if needed)
- **Note**: Geohash-6 (~1.2km) sufficient for most queries

### Performance

| Operation | P50 | P95 | P99 |
|-----------|-----|-----|-----|
| Extract geohash | 0.1ms | 0.2ms | 0.3ms |
| Extract location_name | 0.1ms | 0.1ms | 0.2ms |
| **Total** | **0.2ms** | **0.3ms** | **0.5ms** |

## Testing Strategy

```python
def test_geohash_passthrough():
    envelope = Envelope(location={"geohash": "9q8yy", "location_name": "Downtown SF"})
    geo = await lookup_geo_metadata(envelope)
    assert geo.geohash_6 == "9q8yy"[:6]
    assert geo.location_name == "Downtown SF"

def test_geohash_truncation():
    assert "9q8yywkg62"[:6] == "9q8yyw"
```
