## Context

P03 requires extensive read/write access across the memory system (15+ tables). Access must be:
- Capability-gated (no implicit access)
- Phase-scoped (only grant what phase needs)
- Auditable (log all capability invocations)

---

## Decision

Implement capability-based security per [K004](../k004-capability-mesh-architecture.md) with P03-specific controls from Dossier Appendix D.2.2.

### Required Capabilities Matrix

| Capability | Mode | Phases | Purpose |
|------------|------|--------|---------|
| `st_hipp_events.read` | R | R0-R8 | Source events |
| `st_hipp_events.write` | W | R6 | Update status |
| `st_vec.read` | R | R1-R5 | Embedding queries |
| `st_vec.write` | W | R7 | New embeddings |
| `st_epi.read` | R | R2-R5 | Existing episodes |
| `st_epi.write` | W | R7 | New episodes |
| `st_sem.read` | R | R3-R5 | Semantic patterns |
| `st_sem.write` | W | R7 | New patterns |
| `st_kg_dom.read` | R | R4 | Entity lookup |
| `st_kg_dom.write` | W | R4 | New entities |
| `st_kg_edges.read` | R | R4-R5 | Relationship queries |
| `st_kg_edges.write` | W | R4 | New edges |
| `st_procedural.write` | W | R7 | Routines |
| `st_prospective.write` | W | R5 | Counterfactuals |
| `st_learning_queue.write` | W | R4, R7 | P06 gaps |
| `st_outbox.write` | W | R8 | Event emission |

### Fabric Invocation Policy

Per Dossier D.8.3: **INTERSECT_CALLER**
- Module capabilities = intersection of (pipeline grant ∩ caller's PolicyStamp)
- Prevents privilege escalation through pipeline chaining

### RLS Posture

Per Dossier Appendix I:
- Learning tables (st_learning_queue, st_anchors) enforce tenant_id RLS
- Gap records isolated per household

---

## Consequences

### Positive
- Fine-grained access control per phase
- Audit trail for compliance
- No implicit database access

### Negative
- Capability setup overhead per pipeline run
- Additional latency for policy checks
