## What Was Implemented

### 1. Stream-Based BusDispatcher (FEEDBACK-021, FEEDBACK-022)

**Added `stream` parameter to BusDispatcher**:
```python
BusDispatcher(scheduler, stream="wal")      # Default: WAL-backed, monotonic offsets
BusDispatcher(scheduler, stream="feedback") # Non-WAL, id-based idempotency
```

**Per-stream enforcement**:
- `stream="wal"`: Requires `message.offset`, enforces monotonic ordering, tracks last_offset
- `stream="feedback"`: Requires `metadata['message_id']`, ignores offset, no monotonic checks

**Changes**:
- Made `BusMessage.offset` optional (`int | None`)
- Added `_stream`, `_enforce_monotonic`, `_require_offset`, `_require_message_id` attributes
- Modified `dispatch()` to sort by offset only for WAL stream
- Added `_validate_message()` to enforce stream requirements

**Correctness**: WAL stream behavior unchanged (default), impossible to violate monotonicity

---

### 2. UniversalBus Facade (FEEDBACK-022)

**Topic-based routing** (Gold Standard):
```python
universal_bus = UniversalBus(wal_dispatcher, feedback_dispatcher)

# Automatically routes:
# - feedback.* → feedback stream
# - everything else → wal stream
```

**Prevents developer errors**: No need to remember `stream=` parameter, routing is automatic

**File**: [k0/bus/universal.py](../k0/bus/universal.py)

---

### 3. Per-Stream QoS Isolation (FEEDBACK-023)

**Separate scheduler ports**:
```python
SchedulerProfile(
    port_limits={
        "bus_wal": 32,      # WAL stream (high priority)
        "bus_feedback": 16,  # Feedback stream (lower priority)
    }
)
```

**Effect**: Feedback floods (10,000 signals) cannot starve WAL processing

**Tests**: Verified concurrent WAL + feedback dispatch under load (test_feedback_flood_does_not_block_wal)

---

### 4. Feedback Worker (FEEDBACK-024, FEEDBACK-025)

**Background worker** for dispatching feedback signals:
- Polls `st_feedback_signals` (status='pending')
- Claims batch using `FOR UPDATE SKIP LOCKED`
- Publishes to bus with `stream="feedback"`
- Marks as 'published' or 'error'

**Correct idempotency**:
```python
BusMessage(
    topic=row["topic"],
    offset=None,  # Ignored by feedback stream
    metadata={
        "message_id": row["feedback_id"],  # Required for stream="feedback"
    }
)
```

**No WAL involvement**: Feedback signals never touch `st_wal`

**File**: [k0/feedback/worker.py](../k0/feedback/worker.py)

### 5. Backpressure Monitoring (FEEDBACK-026, FEEDBACK-027)

**Metrics**:
- `feedback_queue_depth`: Count of pending feedback signals
- `feedback_signals_published`: Total published
- `feedback_signals_failed`: Total failures

**Optional 429 throttling**: Can add at `/k0/obs.emit` if queue depth exceeds threshold (future work)

## Architecture Decisions

**ADR-055**: [Stream-Based Bus Architecture](../docs/architecture/decisions-K0/ADR-055-stream-based-bus-architecture.md)

**Alternatives Rejected**:
- ❌ **Option A**: Feedback → WAL (WAL pollution, performance degradation)
- ❌ **Option B**: Separate feedback bus (code duplication, maintenance burden)
- ❌ **Option C**: Optional offset globally (too invasive, high blast radius)
- ✅ **Option D**: Streams inside bus (chosen for correctness, extensibility)

---

## Correctness Guarantees

| Guarantee | How It's Enforced |
|-----------|-------------------|
| **WAL monotonicity** | WAL stream unchanged (default), offset required, monotonic check on |
| **No offset confusion** | Feedback stream ignores offsets, uses message_id for idempotency |
| **No semantic collision** | `_validate_message()` prevents wrong stream usage |
| **Restart-safe** | Feedback uses feedback_id (not in-memory _last_offset) |
| **QoS isolation** | Separate scheduler ports (bus_wal, bus_feedback) |
| **No WAL pollution** | Feedback signals never write to st_wal |
