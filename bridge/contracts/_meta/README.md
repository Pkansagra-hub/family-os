# `bridge/contracts/_meta/` — registry meta-layer

Files in this directory are **not** contracts themselves. They define the
shape and trust roots that every contract under `bridge/contracts/manifests/`
and `bridge/contracts/schemas/` must satisfy.

| File | Purpose |
| --- | --- |
| `manifest.schema.json` | JSON Schema 2020-12 meta-schema. Every YAML in `manifests/` is validated against this in CI. |
| `ca_bundle.schema.json` | JSON Schema 2020-12 for the IFL signing trust root shape. |
| `ca_bundle.json` | The actual trust root. v1 ships one CA `familyos_root_v1`. Placeholder key until pre-MS-5 ceremony. |
| `feature_flags.yaml` | Reversibility flags for milestone gates (global rule #6). |

## Editing rules

- **No hand edits to `checksums:` blocks** in manifests — those are filled by
  `python -m tooling.contracts.checksums --update`.
- **No hand edits to `bridge/_generated/`** — it is regenerated by
  `python -m tooling.contracts.codegen` and CI fails on drift.
- The meta-schema is **extended additively** in MS-4/5/6 (codecs, mcp,
  l3_intra_person_devices). Never replaced.

See `docs/architecture/whiteboard_k1/bridge_system_design.md` (MS-2.5
substrate decisions) for the full rationale.
