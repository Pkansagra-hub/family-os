# Support

Welcome to FamilyOS! This document explains how to get help, share feedback, and stay informed as you work with the project.

## Self-Service Resources

- Review the root `README.md` for an overview of the system and quick links.
- Follow `docs/development/getting-started.md` to set up a development environment.
- Explore `docs/whiteboard.md` and `docs/architecture/` for deep technical context and ADR history.
- Check `docs/development/testing-guide.md` for Ward testing guidance.

## Getting Help

- **Questions & Discussions**: Open a GitHub Discussion or reach out via the issue tracker using the `question` label once the repository is public.
- **Bug Reports & Feature Requests**: Use GitHub Issues with the appropriate templates and labels described in `CONTRIBUTING.md`.
- **Security Reports**: Follow the process described in `SECURITY.md` and avoid filing public issues for sensitive findings.
- **Code of Conduct Concerns**: Contact the maintainer team as documented in `CODE_OF_CONDUCT.md`.

## Response Expectations

We aim to respond to new discussions or issues within **five business days**. Response times may vary depending on maintainer availability and the complexity of the request. Security disclosures receive priority handling per the security policy.

## Staying Informed

- Watch the repository for release notifications and important announcements.
- Review `docs/development/` and ADR updates after each release for architecture changes and migration notes.

Thank you for building FamilyOS with us! Together we can deliver a privacy-first family operating system that feels great to use and easy to contribute to.
